## 一、质量审计（证据链）

### 1.1 判决：现有前端"骨架优、肌理差"。分层结论如下

| 层面 | 判决 | 证据 |
|---|---|---|
| CSS 令牌体系 | **优** | 基调配置.css 单源；零色彩字面量纪律已实证执行 |
| 挂载契约（槽位制） | **优** | 乾坤界面.挂载 让组件与布局互不知晓，隔离思路正确 |
| 自包含组装（include_str!） | **良** | 零构建链、与 AI 工作流贴合；代价是 154KB 单页、无类型、无压缩 |
| 后端→前端字段契约 | **差** | 双名回退、双协议回放、哨兵字符串，详见 1.2 |
| 前端渲染链 | **差** | innerHTML 转义拼接 + 每 delta 全量重渲，详见 1.3 |
| 前端状态管理 | **差** | DOM 即状态 + 5 条独立传输通道各自为政，详见 1.4 |

### 1.2 契约层的三个铁证（"没有单一真相源"）

1. **双名字段回退**：前端不敢信任契约，处处 `a || b` 兜底——
   对话流.js L262 `d.会话 || d.sessions`、L266 `最新.会话id || 最新.id`、L286 `d.运行中 || d.running`、L709 `t.status || t.状态`。
   双名回退的存在本身就是契约失效的自白。
2. **同一语义三种形状**：道祖回复在三个通道里是三种协议——
   接待流（AG-UI 似方言：`TEXT_MESSAGE_CONTENT/delta`）、回放（`/api/dev/sessions/{id}` 返回 `事件[{类型:任务答复|思考|工具结果, 角色, 内容}]`）、过程流（AG-UI：`REASONING_*/TOOL_CALL_*/TEXT_MESSAGE_*`）。
   于是前端被迫维护两套渲染器（渲染过程行 + 建agui渲染器），逻辑双份漂移。
3. **哨兵字符串当错误通道**：受理处理.rs L242 `发帧(delta: "（道祖未能答复：{e}）")`、L345 `"（无回复）"`——错误语义被压扁成正文文本，前端无法程序化响应。

另有：AG-UI 方言不合规范（`TEXT_MESSAGE_CONTENT` 缺 `messageId`、`RUN_STARTED` 携带非标 `会话阶段`），协议测试把方言钉死成了"标准"；后端 84 条路由中"发生了什么"这一件事就有 6 个端点（/api/dev/stream、/stream/state、/stream/agui、/stream/agui/state、/pilot/events、/pilot/process）三种形状。

### 1.3 渲染层的两个铁证

1. **O(n²) 全量重渲**：对话流.js L338 `p.innerHTML = 净化(回复文本)`——每个 delta 到达都对**累积全文**跑 8 趟正则再整体重写 DOM。回复越长每帧越贵。
2. **转义拼接式 XSS 防线**：净化() 是"先转义再 innerHTML"的纪律型防线（引号不转义的坑靠"不拼属性"规避）。防线靠纪律不靠构造——记忆已实证**同一消息内并行编辑丢失 4 处净化导致 XSS 复现**。正确做法是内容路径根本不碰 innerHTML（见 §三 渲染原则）。

### 1.4 状态层的铁证

对话流组件内并存 **5 条传输通道**，各自持有游标、定时器、生命周期：

| 通道 | 机制 | 自持状态 |
|---|---|---|
| 接待流 | fetch 手泵 SSE | 缓冲、泡、回复文本、任务id、阶段 |
| 过程流 | EventSource | 事件游标、降级开关 |
| 过程轮询回退 | 2s setInterval | 事件游标（第二份） |
| 任务态 | 3s setInterval | 无（直接改 DOM） |
| 驱动状态 | 3s setInterval | 无 |

全停() 需同时掐 3 个句柄（L575-579），幽灵轮询靠 isConnected 逐处防御。**通道即状态、DOM 即数据库**——任何新功能（历史回看、多会话、断线续传）都要再复制这套组合。

### 1.5 审计总评

问题不在"写得不认真"——恰恰相反，纪律性很强。问题在于**没有一层东西是"唯一真相"**：字段没有唯一名、回放与实时没有唯一协议、状态没有唯一来源、错误没有唯一形状。质量是从"每个局部都努力"里漏掉的。

## 二、行业基准：AI 时代前端真正需要什么

### 2.1 五条行业共识（2025-2026 实证方向）

1. **一个类型化事件协议**：Agent↔UI 交互正在收敛到标准事件协议（AG-UI 16 事件成为事实标准；Google A2UI、Vercel generative UI 同向）。方言没有生态， conformant 才能白嫖生态工具。
2. **界面 = 事件日志的归约（Event-Sourced UI）**：UI 状态是对事件流 fold 的纯函数。回放 = 重放日志，续传 = 从游标归约，时间旅行调试 = 日志切片。你们后端的 会话回放/恢复/分叉 端点**已经存在**，前端却没用上同一套归约——这是最可惜的一点。
3. **传输单通道多路复用**：一条 SSE/WS 承载全部类型化事件（信封 = {类型, 载荷, 序号}），客户端归约。5 条通道是历史演化痕迹，不是设计。
4. **三层渲染**：稳定骨架（手写）/ 结构化组件（类型化 props 注册表）/ LLM 内容（流式 DSL/Markdown 渲染器，XSS 免疫由构造保证）。TokUI 的贡献正是第三层的介质形态——DSL 文本流 + 命名引用事件 + textContent 渲染。
5. **错误与进度是一等公民事件**：不是塞进正文的括号字符串。

### 2.2 与现有体系的关系：不是推翻，是"换真相源"

现有四件好东西**原样保留**：CSS 令牌单源、挂载契约槽位制、自包含组装、事件游标思维。水镜映真-域做的是把它们下面垫的那层"真相"换掉：**字段唯一、协议唯一、状态唯一、错误唯一**。

## 三、设计原则（五条）

1. **界面是河的镜面**：组件不许自行 fetch、不许持有业务状态；一切来自长河事件，一切显示是归约结果。（镜不藏水）
2. **契约单源**：长河事件词表只在 Rust 侧定义一次（词表.rs），wire 全中文单语言；旧接口方言由镜面**适配层**翻译（翻译表唯一，双名回退被隔离在适配层内，禁止渗入渲染与状态）。
3. **内容路径零 innerHTML**：LLM 内容流经 流光渲染器 以 createElement/textContent 构造 DOM——XSS 免疫由构造保证，不靠净化纪律。
4. **增量有界**：任何一次渲染的工作量与"本块增量"成正比，与全文长度无关（行固化 + 尾区重渲）。
5. **事件按名引用动作**：组件内不写业务 fetch，动作注册在 镜面.动作 表（沿用 TokUI 安全事件思路），DSL/组件只写动作名。

## 四、长河事件词表 v1（契约核心）

wire 格式：JSON，信封 `{"类型": "...", ...载荷}`，全中文字段。与旧接口的翻译表见 §4.2。

### 4.1 事件清单

| 类型 | 载荷 | 语义 |
|---|---|---|
| 回复开始 | 消息id, 角色 | 一条流式回复开始 |
| 回复增量 | 消息id, 文 | 正文增量（逐 token） |
| 回复结束 | 消息id | 回复收尾 |
| 思考开始/思考增量/思考结束 | 消息id, (文) | 思考流（折叠呈现） |
| 工具开始 | 调用id, 名称 | 工具调用开始 |
| 工具参数 | 调用id, 片段 | 参数增量 |
| 工具结束 | 调用id | 调用收尾 |
| 工具结果 | 调用id, 文 | 结果（终值） |
| 运行结束 | 阶段, 任务id? | 一轮运行收尾（阶段：接待中/待确认） |
| 任务状态 | 任务id, 状态 | 任务卡状态迁移（状态词=后端唯一词表，前端禁做字符串猜谜） |
| 过程事件 | 任务id, 序号, 类型, 角色, 工具名?, 内容 | 执行过程（序号单调，归约按游标去重） |
| 河错 | 来源, 文 | 类型化错误（替代哨兵字符串） |

### 4.2 旧接口方言 → 长河事件 翻译表（适配层唯一职责）

| 旧形状（证据） | → 长河事件 |
|---|---|
| `{type:RUN_STARTED, 会话阶段}` | （无显示语义，仅连接态） |
| `{type:TEXT_MESSAGE_CONTENT, delta}` | 回复增量{消息id:"接待", 文} |
| `{type:TEXT_MESSAGE_END}` | 回复结束{消息id:"接待"} |
| `{type:RUN_FINISHED, 阶段, 任务id}` | 运行结束{阶段, 任务id} |
| `{type:REASONING_MESSAGE_START/CONTENT/END}` | 思考开始/思考增量/思考结束 |
| `{type:TOOL_CALL_START/ARGS/END/RESULT}` | 工具开始/工具参数/工具结束/工具结果 |
| board `{status\|\|状态}` | 任务状态{任务id, 状态}（双名回退被隔离于此） |
| 过程 `{任务id,序号,类型,角色,工具名,内容}` | 过程事件（直通） |
| 回放 `事件[{类型:任务答复\|思考\|工具结果, 角色, 内容}]` | 回复增量/思考/工具结果 段序列（**回放与实时同管线**） |

### 4.3 会话视图（归约产物）

```
会话视图 { 阶段, 消息[消息视图], 任务{id→任务视图}, 过程游标 }
消息视图 { 方向: 己方|对方, 角色, 段[段视图] }
段视图   { 类: 正文|思考, 文 } | { 类: 工具, 名称, 参数, 结果 }
任务视图 { 状态, 过程[过程条] }
```

Rust 侧 归约.rs 为真理源（回放/快照/未来统一通道复用）；JS 侧 长河.js 为镜像同构实现（翻译规格 = 本节）。二者以同一批事件序列产出同一视图为验收。

### 5.4 实测证据（2026-09-10 真机闭环）

| 验证 | 结果 |
|---|---|
| cargo test（归约契约 4 测试） | 全绿：增量拼接 / 过程游标去重_乱序丢弃 / 河错不改结构_清河重置 / 工具段一一对应 |
| 编译 | 零警告（含命名规范） |
| **内联毒序列缺陷（实测抓到）** | 首轮落盘页四脚本全部未执行——流光样张里的字面量 `</script>` 提前闭合脚本标签，JS 源码泄漏成 DOM（`<b>非标签</b>` 成真实元素）。**修复在组装层**：内联前统一中和 `</script`→`<\/script`、`<!--`→`\!`（JS 字符串值不变，语义无损）——这是"安全由构造保证"的又一实证：同类缺陷在旧门面属潜伏态（资产恰好未含毒序列），水镜把它变成了构造级不可能 |
| 浏览器端到端（?v=2 注入完整长河事件序列） | 10 项断言通过：XSS 免疫（img/script/onerror/onmouseover 危元素数 = 0，毒串全部文本化）、标题/列表/行内码/思考折叠渲染、任务卡状态、过程行、河错条 |
| 真实后端联动 | 页面挂着不动，旧接口过程流（AG-UI 方言）经适配层实时翻译上屏——镜像里出现真实"道祖/圣人"消息 |

已知 v0 边界：工具参数实时路径只进视图不进屏（回放路径完整）；截图工具因光标闪烁动画超时，以 DOM 断言代替视觉证据。

## 八、已知取舍与风险

1. **v0 仍是 5 通道**：受"不动后端"约束，适配层只是把混乱关进笼子；v1 统一通道后才根治。这是有意的中间态。
2. **双实现（Rust/JS 归约）**：同一归约写两遍有漂移风险；以"同一事件序列 → 同一视图"为验收，v1 由后端统一出事件后 JS 归约可降级为纯显示缓存。
3. **DSL-lite 语法集 v0 极小**（card/btn/table/p/h/think/code/tag）：先证安全与流式，图表等 v2 再扩；语法与 TokUI 兼容保留迁移选项，但不绑定 TokUI。
4. **qk-mirror 依赖 qk-web 仅取令牌**：水镜未来若整体替换 门面，令牌背景样式随迁（基调配置.css 物理搬家一次），依赖即解除。
