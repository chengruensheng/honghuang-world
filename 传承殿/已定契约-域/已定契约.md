## 一、九根六层骨架（已定）

九根为顶层目录，不可增删；向内递进为 域→府→殿→阁→园。

| 层 | 职责 | 是否放代码 |
|----|------|-----------|
| 根 | 顶层分区（9根固定） | 否（纯目录） |
| 域 | 语义分组 | 否（纯目录） |
| 府 | 独立编译单元（crate） | 是（Cargo.toml + 府级模块.rs 为 crate 根） |
| 殿 | 模块分区（门面） | 汇总（殿级模块.rs 收阁） |
| 阁 | 功能分组（接口契约） | 汇总（阁级模块.rs 收园） |
| 园 | 实现落点 | 是（园级模块.rs 收实现文件 + 实现代码） |

九根：太初、混沌、乾坤、道韵、量劫（五行本体五根）+ 鸿蒙、证道、道果、传承殿（工程四根）。

**代码落园铁律**：实现代码只落在**园**层（园是文件夹，命名 `名字-类型-园`），crate 用 Cargo 的 `[lib] path` / `[[bin]] path` 指向**府级 `模块.rs`**（crate 根），府内经 `模块.rs` 层层汇总上报（园→阁→殿→府，见第六节），**整个项目不出现 `src` 目录**。府（crate）内代码经 殿→阁→园 中转，不直接放在府根下。

## 三、代码归属规则（已定）

- 五行本体五根承载**领域代码**（按本质语义归入）
- 鸿蒙只承载**跨域共享底层能力**（HTTP/日志/配置/模型连接等通用件）
- 证道承载验证类（测试与门禁）
- 道果承载统一构建物 + 临时物
- 传承殿承载所有非代码内容

## 四、府可插拔机制（已定）

- 府是唯一编译单元，通过 trait 定义跨府契约
- 府之间 `Arc<dyn Trait>` 解耦，生产路径注入真实实现，测试路径注入 mock
- 核心无特权：任何府都可被替换

## 五、治理细则（本轮敲定）

### 5.1 临时与非临时处置

凡可整体重建、无独立演化价值的产物，集中到道果；承载语义、需独立演化的内容，分布到 8 根 + 传承殿。

| 类别 | 归属 |
|------|------|
| debug 构建物 | 道果 |
| 会话临时状态 | 道果 |
| 编译缓存 | 道果 |
| 领域代码 | 8 根（本体五根 + 鸿蒙） |
| 非代码内容 | 传承殿 |

道果 clean = 整体重建，不损失语义。

### 5.2 层命名规则

沿用 E 盘格式，命名纯表意、不承载五行语义（五行语义只由根承担）。

| 层 | 格式 | 示例 |
|----|------|------|
| 域 | 4字-域 | 基础设施-域 |
| 府 | 4字-府 | 事件总线-府 |
| 殿 | 2字-2字-殿 | 事件分发-殿 |
| 阁 | 2字-2字-阁 | 分发实现-阁 |
| 园 | 名字-类型-园 | 日志-模块-园 |

> 园为文件夹，命名三段式：`名字-类型-园`，类型词表示内容类别（数据/配置/模块/接口等）；代码文件放在园内（中文名 + `.rs`）。

**命名唯一性（严禁同名）**：
- 同级节点语义词不重复（如同一域下两府不得同名）
- 下级节点语义词不得与其直接上级相同，即 域≠府、府≠殿、殿≠阁、阁≠园（例：禁止 `启动装配-域` 与 `启动装配-殿` 并存）
- 判定以"去掉后缀的语义词"为准（园以"名字-类型"整体判定）

### 5.3 数量上限

- **域 ≤ 3**（硬约束，根下域超限必须合并而非新增；域是语义大类，宜少）
- 域内府数不限（府是独立编译单元，可多）
- 殿 ≤ 6阁（硬约束，超限必须切割）
- 阁 ≤ 4园（硬约束，超限必须切割）

## 六、代码组织与规模约束（本轮敲定）

### 6.1 模块汇总上报（模块.rs）

1. 每层目录（含代码者）有一个 `模块.rs` 作为汇总文件，收集本层子项并对外上报。
2. 园级 `模块.rs`：`mod` 引入园内实现文件 + `pub use` 上报。
3. 阁级/殿级/府级 `模块.rs`：`#[path]` 引入下一层 `模块.rs` + `pub use` 上报。
4. 府级 `模块.rs` 是 crate 根（`[lib] path` / `[[bin]] path` 指向），对外暴露公共 API。
5. 目录名含连字符不是合法 Rust 标识符，`#[path]` 引入时**标识符 = 目录名去连字符转下划线**。
6. 纯配置/数据园（如 default.toml 所在园）不建模块.rs（模块.rs 只服务含代码目录）。

### 6.2 代码规模约束

1. 单文件 ≤ 350 行（建议），≤ 500 行（硬上限），超则拆分。
2. 单函数 ≤ 50 行，超则拆分。

### 6.3 证道测试权限

1. 证道只能测试府级（crate 的公共 API）。
2. 内部（殿/阁/园）无测试权限，不得在内部写 `#[cfg(test)]`。
3. 府是插件、单独可编译单位，测试针对府级公共接口。

## 七、跨引擎信号总线与联动装配（本轮敲定）

### 7.1 中立信号总线

- 新增 `hm-signal`（信号契约-府）：`信号` 数据（类型 + `信号载荷` 强类型载荷）+ `信号总线` trait（继承 `Component`，`发布(&self)`/`订阅(&self, 类型, Arc<dyn Fn>)`）。
- 信号类型与载荷键收敛为 `信号类型`/`载荷键` 常量模块（统一于 hm-signal，全项目引用，杜绝魔法字符串）。
- 新增 `hm-signal-bus`（信号总线-府）：`内存信号总线` 内存实现，发布时锁内克隆匹配处理器、释放锁后执行（**重入安全**，支撑信号级联）。
- 信号为跨引擎中立消息，引擎间不直接调用，只经总线发布/订阅。

### 7.2 引擎接入

- 五引擎各加 `信号总线: Option<Arc<dyn 信号总线>>` 字段、`设置信号总线` 方法、私有 `发布信号`（无总线时静默忽略）。
- **引擎间仍无直接依赖**，只新增 `hm-signal` 依赖；落盘不受运行时态影响（总线字段 `#[serde(skip)]` 或本就不整体序列化）。

### 7.3 联动装配 Composition Root

- 新增 `hm-linkage`（联动装配-府）：`五行装配` 创建五引擎 + 信号总线，向每引擎注入总线并订阅五段相生桥接。
- `hm-linkage` 依赖全部五引擎 + 信号总线，是唯一反向串联点，不构成依赖环。
- `hm-bootstrap` 启动入口已并入 `hm-linkage`：启动即装配五行，并触发一次完整相生闭环自检（`演示闭环`）。

## 八、领域契约抽象与运行时容器（本轮敲定）

### 8.1 领域契约（府可插拔的领域层落地）

- 新增 `hm-domain-contract`（领域契约-府，落「基础契约-域」）：五个领域契约 trait，均继承 `Component`——
  - `任务仓库契约<任务, 状态>`、`迭代日志契约<迭代, 版本>`、`记忆库契约<记忆>`、`规则库契约<规则>`、`事件总线契约<事件>`。
- **泛型参数解耦领域模型**：契约 trait 以类型参数承载领域模型（如 `任务仓库契约<Task, TaskStatus>`），使契约府不依赖任何引擎，避免「契约府 ↔ 引擎府」依赖环。
- 契约只含**运行时读写接口**；持久化（保存/加载）与信号总线注入（设置信号总线）留在具体实现，不进契约。
- 五引擎实现各自契约（如 `impl 任务仓库契约<Task, TaskStatus> for TaskStore`），方法委托既有实现，**不改引擎既有行为**。

### 8.2 装配层 trait 对象解耦

- `hm-linkage` 的 `五行装配` 字段类型由具体引擎改为 `Arc<Mutex<dyn 领域契约>>`：
  - 生产路径装配真实引擎（先注入信号总线，再 coerce 为 trait 对象）；
  - 测试路径可注入 mock，替换任一引擎（核心无特权）。
- 五段相生桥接函数与 `演示闭环` 只经领域契约 trait 对象调用，不感知具体实现。

### 8.3 运行时组件容器

- 新增 `hm-container`（组件容器-府，落「系统装配-域」）：`组件容器` 统一管理可插拔组件的注册、初始化、关闭生命周期。
  - 三能力桶独立存储：基础组件（`Component`）、可初始化（`Initializable`）、可关闭（`Shutdown`）。
  - `初始化()` 遍历可初始化组件并 `init`，任一失败即报错；`关闭()` 遍历可关闭组件并 `shutdown`。
- `hm-bootstrap` 启动走容器：生产装配五行 → 注册日志器（可初始化）+ 信号总线（基础组件）→ `容器.初始化()`。

### 8.4 证道验证

- 证道联动测试新增 `运行期注入_mock替换真实任务仓库`：mock 实现 `任务仓库契约<Task, TaskStatus>`，替换生产装配体的任务仓库字段，验证 trait 对象可插拔、mock 被调用。

## 九、五行相克（负反馈约束增长，本轮敲定）

### 9.1 定位：相生为生、相克为制

- 相生（相邻环）= **流水线**，正向数据流：任务→迭代→记忆→规则→事件→任务，让系统「活」。
- 相克（隔一克制）= **横切治理**，负反馈收敛，让系统「稳」。
- **相克 = 约束增长，不删已有**：克制是负反馈——被克方积累过盛时限制新增/降级处理，而非删除已沉淀数据；土克水的「去重」是唯一保留的删除语义（本质是合并重复、不丢失信息）。

### 9.2 克制语义（过盛才克，约束增长）

| 相克 | 过盛条件 | 克制动作（约束增长） |
|------|---------|---------------------|
| 金克木 | 待受理任务 ≥ 容量上限 | 拒绝创建新任务（不取消已有） |
| 木克土 | 记忆数 ≥ 容量上限 | 新记忆标注 `归档 = true`（不淘汰旧记忆） |
| 土克水 | 记忆写入 | 事件去重（按类型与载荷合并重复，唯一删除语义） |
| 水克火 | 进行中迭代 ≥ 容量上限 | 拒绝开启新迭代（不回滚已有） |
| 火克金 | 规则数 ≥ 容量上限 | 拒绝新增（严格数量上限，不废止旧规则） |

### 9.3 实现方式（容量注入 + 去重桥接）

- 四引擎各新增 `设置容量上限(上限)` 方法与私有 `容量上限` 字段（默认 `i64::MAX` 近似不限，且 TOML 可序列化；`usize::MAX` 会致持久化溢出）。
- 引擎内置约束：任务 `创建` 超限返回 `容量超限`；迭代 `开启` 超限返回 `容量超限`；记忆 `写入` 超限标注归档；规则 `添加规则` 超限拒绝新增（严格数量上限）。
- 相克模块（克制-模块-园）提供 `克制金克木/木克土/水克火/火克金`（容量注入）与 `克制土克水`（信号驱动去重）；装配层 `装配带上限(n)` 注入约束，`装配()` 用默认上限。
- 土克水仍经信号驱动（记忆写入 → 事件去重）。

### 9.4 契约变更

- `任务仓库契约.创建` 与 `迭代日志契约.开启` 返回 `Result<u64>`（超限即 Err，不吞错）。
- 删除型 API 已移除：`取消最旧`/`回滚最旧`/`淘汰最旧`/`废止最旧` 从契约与实现删除（相克已改为约束增长，无删除语义调用点）。
- 错误类型新增 `任务不存在`/`迭代不存在`/`规则已存在`/`规则不存在`/`记忆不存在`/`事件不存在`/`信号类型未知`/`状态流转非法`/`容量超限` 领域变体，以及 `序列化`/`反序列化` 持久化错误变体（保存/加载不再用 `Other` 包装）。

### 9.5 证道验证

- 证道联动测试相克 5 例：`金克木_任务过盛拒绝创建`、`木克土_记忆过盛标注归档`、`土克水_记忆写入去重事件`、`水克火_迭代过盛拒绝开启`、`火克金_规则达上限拒绝新增`。
- `演示相克` 启动自检触发事件去重，返回克制状态快照（`去重事件` 布尔）。

## 十一、信号总线持久化（同步落盘，本轮敲定）

### 11.1 定位：可靠事件流第一步

- 内存信号总线只做同步分发、不落盘；为后续演化提供「可靠事件流」，第一步先补**同步落盘持久化**（零风险，不改分发语义），异步队列留待第二步。

### 11.2 落盘信号总线（hm-signal-bus 新增「落盘总线-阁」）

- `信号` 补 `Serialize/Deserialize`（hm-signal 加 serde 依赖），使信号可持久化。
- 新增 `落盘信号总线`（与 `内存信号总线` 同府、不同阁，真实实现变体）：
  - `发布`：同步分发（语义同内存总线）+ 发布即追加一行 JSON 到日志文件（append-only 可靠事件流）+ 记录历史。
  - `设置落盘路径(path) -> Result<()>`：打开/创建追加日志；`加载(path) -> Result<Self>`：从 JSONL 日志重放历史（订阅关系需重新注册）。
  - `全部() -> Vec<信号>`：内存镜像。
- **落盘失败仅告警不 panic**：`信号总线::发布` 契约为 `()`，落盘为副作用，失败用 `tracing::warn!` 记录，不影响内存分发。

### 11.3 证道验证
