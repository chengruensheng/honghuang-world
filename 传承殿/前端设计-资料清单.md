# 前端界面设计 · 给外部设计师/设计型 AI 的资料清单

> **用途**：本清单是项目「洪荒·世界」对外部前端设计者（网页上的 AI / 设计师）的**委托资料包**。请完整阅读本文档后，产出一份可落地的前端界面设计方案。
>
> **约定**：本清单只提供设计所依据的**项目定位、能力边界与约束**，不含任何既有 UI 成品与视觉形态，请完全从零设计一套与项目气质匹配的界面。
>
> **版本**：v1.1 · 2026-09-08

---

## 〇、委托方期望的交付物

请基于本资料包，交付一份**前端界面设计方案**，至少包含：

1. **信息架构**：整体页面结构、导航、每个页面的功能分区。
2. **界面设计**：关键页面的视觉稿 / 高保真描述（布局、色彩、组件、交互）。
3. **设计规范**：色彩体系、字体、间距、明暗模式、组件规范（按钮/卡片/弹层/时间线等）。
4. **交互范式**：任务「发布→执行→验收→回放」全流程的界面交互设计。
5. **设计原则呼应**：如何在视觉上体现本项目的哲学（见第一节）而不落俗套。

> 本项目已有**后端全量 API**（见第五节），你**不需要**设计后端，只需围绕这些 API 的能力设计前端如何承载。

## 一、项目定位（灵魂，请务必先读懂）

### 1.1 一句话定位

> **面向架构、AI 主刀 —— AI 原生的面向架构开发平台与智能体工作台。**

配套一句话文案（可选，用于引导页角标等）：
> "面向架构，AI 主刀。人写律与骨架，AI 填实现；架构即契约，契约即约束。"

### 1.2 三层解读（给设计者的完整理解）

| 层 | 内容 | 设计含义 |
|----|------|---------|
| **本质** | AI 原生开发平台：不是普通 IDE，而是能**自主开发自身**的智能体系统。人负责架构与规则，AI 负责大规模编写与运行时决策。 | 界面应呈现「人机协作」感：人设目标/把关，AI 执行/展示过程。 |
| **底座** | Rust 后端 + 五行引擎（任务/迭代/记忆/规则/事件闭环）+ 三态认知底座（图谱/格位/临时上下文）+ 自主开发智能体（LLM 决策 + 工具调用 + 本地执行）。 | 界面需承载**过程可观性**：AI 每一步在想什么、调了什么工具、产出了什么都应可视、可回放。 |
| **差异化** | 全中文六层架构、律可机器校验、自举闭环、五行/三态世界观作增强层。 | 世界观不是噱头，而是**降低认知负担、核验 AI 正确性**的辅助层。设计上宜「克制的东方气韵」而非堆砌玄学符号。 |

### 1.3 设计基调建议（供参考，可超越）

- 建议以**深色专业基调**为主（开发者工具常规选择），浅色模式可作为可选扩展。
- 气质关键词：**克制、纵深、秩序中带灵性**。避免「赛博霓虹堆砌」，更接近「现代专业 IDE + 东方留白气韵」的融合。
- 五行色建议做**语义色**而非装饰：金/白、木/青、水/墨蓝、火/赤、土/橙赭，用于状态与分类，不用作满屏背景。

## 二、目标用户与核心场景

- **主用户**：开发者个人，把复杂编码任务"交给 AI 自主完成"，同时要**看得懂、把控得了、复盘得了**整个过程。
- **核心诉求**：① 下需求（对话收敛）② 看 AI 执行（过程可视化）③ 验收产物（diff / 表格 / 代码块）④ 回放与纠偏（历史会话 / resume / fork）。⑤ 管全局（任务/迭代/看板/记忆/规则/事件）。
- **反面设计**：不要把它设计成「黑盒发个指令看结果」，本项目强项正是**过程全透明、可回放**，这是灵魂中的灵魂。

## 三、九根与五行（领域地图，视觉信息架构的依据）

「洪荒·世界」分**九根六层**，前端是「乾坤根」的对外门面。五行承载五类领域能力：

| 五行 | 维度（根目录） | 工程能力（引擎） | 语义色建议 |
|------|--------------|-----------------|-----------|
| 木 | 太初 | 任务引擎（需求生长） | 青色 |
| 火 | 量劫 | 迭代引擎（转化/焚炼重生） | 赤红 |
| 土 | 乾坤 | 记忆引擎（承载/稳定） | 橙赭 |
| 金 | 道韵 | 规则引擎（收敛/规范） | 金色 |
| 水 | 混沌 | 事件引擎（流动/连接） | 墨蓝 |

- **相生环**：木→火→土→金→水→木（任务完成开启迭代→迭代完成写记忆→记忆写入加规则→规则命中发事件→事件发布建任务）。
- **相克环**：隔一克制，防止任一系统过盛（如任务堆积拒创建、迭代过盛拒开启等）。

> 设计提示：五行可作为**分类标签色 / 图标语义 / 概览分区**（如看板按行分组），但不要强迫用户先学五行才能用界面。

## 四、三态认知底座（一个前端可展示的新概念模块）

前端除了常规任务/看板，还承载一套「认知底座」可视化：

| 态 | 别名 | 本质 | 前端可如何呈现 |
|----|------|------|---------------|
| **图谱** | 世界态 | 代码真源，客观实在（模块/符号/依赖边） | 依赖关系图（力导向 / 树状），点节点看符号与引用 |
| **格位** | 心智态 | AI 对项目关键面的提炼摘要（36 格：6 维度×6 格位） | 仪表盘格网，每格显示最新摘要卡片、更新状态 |
| **临时** | 过程态 | 执行记录、运行轨迹（有界、可压缩） | 过程时间线 / 日志流，按轮次分组、可压缩折叠 |

> 这是「智能体读懂项目」的底座，是区别于普通 IDE 的差异化亮点。设计者可考虑为其设计专门的「认知」视图（依赖图 + 格位盘 + 过程流），但优先级可放任务驱动主线之后。

## 五、后端全量 API（前端能力边界＝这些 API）★最硬约束

前端只通过 HTTP 调后端。**你设计的所有交互最终都要落到这些接口上**。以下按功能域分组：

### 5.1 任务与迭代（木·火）
- `GET /api/tasks`、`POST /api/tasks`、`GET /api/tasks/{id}` — 任务列表 / 创建 / 查询
- `GET /api/iterations`、`GET /api/iterations/version` — 迭代列表 / 当前版本

### 5.2 看板（状态流转主线）★核心
- `GET /api/board`、`POST /api/board`、`GET /api/board/{id}` — 看板列表 / 发布 / 查询
- `POST /api/board/{id}/accept` — 承接任务
- `POST /api/board/{id}/submit` — 提交
- `POST /api/board/{id}/clean` — 清理
- `POST /api/board/{id}/rollback` — 定向回退
- `POST /api/board/{id}/sweep` — 扫尾检查
- `POST /api/board/{id}/clarify` — 澄清对齐

> 状态阶段（v1.62 已按此统计）：**设计 → 实现 → 验收 → 终审 → 清理**。看板应能按这些阶段分列展示与移动。

### 5.3 智能体对话与驱动（对话收敛 → 发布 → 过程）★灵魂
- `POST /api/dev/chat` — 道祖对话（闲聊 / 澄清 / 收敛），返回 `{阶段, 回复, 需求?}`
- `POST /api/dev/chat/confirm` — 确认发布对齐需求（落看板 + 写记忆 + 自动驱动），返回 `{任务id}`
- `POST /api/dev/agent`、`GET /api/dev/events?since=N`、`POST /api/dev/agent/stop` — 受理开发任务 / 增量事件 / 停止
- `POST /api/dev/workspace` — 切换工作区
- `GET /api/dev/pilot/status` — 驱动台状态（就绪 / 运行中 / 最近阶段 / 最近结果）
- `GET /api/dev/pilot/events?since=N` — 驱动阶段事件增量（阶段流转）
- `GET /api/dev/pilot/process?since=N` — 驱动过程事件增量（智能体每步：思考 / 工具调用 / 工具结果 / 答复）
- `POST /api/dev/pilot`、`POST /api/dev/pilot/drain` — 驱动看板一轮 / 到空闲

### 5.4 历史会话与回放 ★差异化亮点（Resume / Fork / Replay）
- `GET /api/dev/sessions` — 历史会话清单（按创建倒序）
- `GET /api/dev/sessions/{id}` — 会话回放（元数据 + 全程过程事件）
- `POST /api/dev/sessions/{id}/resume` — 定向恢复驱动（断点续跑）
- `POST /api/dev/sessions/{id}/fork` — 分叉新驱动线（可继承源断点消息）

### 5.5 模型（LLM）接入
- `GET /api/llm/status` — 当前选择 + 供应商清单
- `GET /api/llm/models` — 各供应商可用模型（失败供应商标注错误）
- `POST /api/llm/select` — 切换供应商 + 模型
- `GET /api/llm/templates`、`POST /api/llm/discover`、`POST /api/llm/connect` — 内置模板 / 零网络探测 / 接入供应商

### 5.6 记忆 / 规则 / 事件（土·金·水）
- `GET /api/memories` — 记忆列表
- `GET /api/rules` — 规则列表（律）
- `GET /api/events` — 事件列表

### 5.7 认知三态 ★差异化
- `GET /api/cognition/graph` — 图谱查询（依赖 / 符号 / 引用）
- `GET /api/cognition/cells` — 格位查询（36 格摘要）
- `GET /api/cognition/context` — 语境查询（临时上下文）
- `GET /api/cognition/search` — 认知检索

### 5.8 日志
- `GET /api/logs`、`POST /api/logs` — 日志列表 / 记日志

## 六、核心交互范式（一定要在界面设计中体现）

### 6.1 主链路：对话式收敛 → 确认发布 → 过程可视化 → 验收 → 复盘

```
用户描述需求 → [多轮对话持续收敛，界面就地更新对齐后的需求摘要，不打断输入]
→ 用户说「开始」/ 点「开始执行」→ POST /dev/chat/confirm 发布
→ 前端轮询（process 过程事件 + events 阶段事件 + status 状态）→ 过程实时流式呈现
→ 每一次智能体行为都在界面呈现：推理过程 / 工具调用（含入参与结果）/ 工具结果 / 阶段流转 / 错误
→ 任务完成 → 呈现结论 / 产物（代码、diff、表格）
→ 用户可到「历史会话」回放全程，或对某会话 Resume（续跑） / Fork（开新线）
```

### 6.2 前端轮询模型（重要技术事实）
- 事件是**按序号的增量拉取**：`GET /pilot/process?since=N`、`GET /pilot/events?since=N`，前端维护游标 `N`。
- 驱动状态三接口并行拉：`process` + `events` + `status`。
- 说明前端需设计**流式滚动的时间线/过程列表**，且能**断点续显、增量追加**；历史回放则是从头顺序播放同一种事件结构。

### 6.3 过程事件类型（前端渲染的"原材料"）
思考 / 工具调用 / 工具结果 / 阶段完成 / 错误（以及阶段事件的 空闲 / 状态流转）。
每个过程事件带：**类型、角色、轮次 R、工具名、内容、时间**。

### 6.4 需求对齐视图（对话收敛的界面语义）
多轮对话中，后端持续返回对齐后的需求 `{标题, 描述, 场景, 优先级}`，前端需**就地持续更新**这份已对齐需求（提示"已按最新对话更新"），并随时可「开始执行」。

> 这是本产品「收敛不打断」的独特交互——对话与需求确认并行不阻塞。具体的视觉形态（卡片/面板/侧栏等）交由你设计，重点是"就地更新"与"随时可发布"这两个语义。

## 七、技术硬约束（前端必须遵守）

1. **后端通信**：只用 **HTTP + axum API**（上文全部接口）。无 Tauri invoke、无 Node 依赖需求。
2. **一套前端 Web/桌面通用**：前端打包为桌面应用（Tauri 壳）时**代码零改动**。因此不写死桌面专属 API；一律走 `http://localhost:8321` 或相对同源。用浏览器直接开即可跑。
3. **可落地性**：设计应基于普通 HTML/CSS/JS（或可编译为静态资源的框架，如 Vue3+Vite），构建产物为静态资源即可被 axum 托管。避免需要复杂服务端渲染或专有运行时的方案。
4. **当前入口 URL**：浏览器访问 `http://localhost:8321`。
5. **中文本地化**：界面全中文；命名与文案贴合「世界」语境（任务/看板/对话/图谱/格位等），但避免晦涩文言影响易用性。
