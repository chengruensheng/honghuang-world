## 缺陷 1 · 命令-沙箱-园 模块桥接缺失（已修）

- **现象**：接手时 `cargo check --workspace --lib` 在 `daoshu_fu` 报两条 `unresolved import`：
  ```
  派发落单.rs:17:32: unresolved import `crate::沙箱视图`
  工具执行.rs:5:38: unresolved imports `crate::校验命令护栏`, `crate::沙箱视图`
  ```
- **根因**：`鸿蒙/基础设施 - 域/道术施展-府/手脚-施展-殿/命令-执行-阁/命令-沙箱-园/模块.rs` 当前只 `pub mod 工具执行`，漏掉了同园另两个文件 `命令沙箱.rs`（含 `pub struct 沙箱视图`）和 `沙箱护栏.rs`（含 `pub fn 校验命令护栏`）的桥接。
- **背景**：第三个文件 `越界判定.rs` 也是孤立未桥接（含 `pub fn 判定路径越界` 等），但 `工具执行.rs` 内未引用且无外部 `use`，暂未桥接——启用需单独评审。
- **修复**：补齐两条 `#[path]` 声明与两条 `pub use` 透出，模块.rs 同时更新顶部注释说明三文件分工与 `越界判定.rs` 暂未桥接的原因。
- **验证**：`cargo check --workspace --lib` 通过。

## 缺陷 2 · 工具执行涉及路径校验 函数 trim 掉点破坏匹配（已修）

- **现象**：`daoshu_fu` 测试 `涉及路径_拒绝列表命中` 期望拒绝 `.上下文` 能命中 `.上下文/格位/xxx.json`，但函数返回「涉及路径外拒写」。
- **根因**：`命令-沙箱-园/工具执行.rs::校验涉及路径预归一` 第 37 行 `let 目标去点 = 目标.trim_start_matches('.').to_string();` 把 `.上下文` 去点变成 `上下文`，与拒绝列表 `.上下文` 不再匹配。
- **错误注释**：作者写「含 `trim_start_matches('.')`，对齐原 校验涉及路径 第 1 行语义」——但原版 `任务-派遣-阁/工具-循环-园/工具执行.rs::校验涉及路径` 实际并无此操作，属注释与实现不一致的引入 bug。
- **修复**：去掉 `trim_start_matches('.')` 调用，保留 `trim()` + `replace('\\', "/")`；同步更新注释说明「`.上下文` 与 `上下文` 是不同语义，去点会破坏匹配」。
- **验证**：`cargo test -p daoshu_fu --lib` 通过（99 passed / 0 failed / 1 ignored）。

## 缺陷 3 · 并发幂等测试 跟上 存会话 API 演进（已修）

- **现象**：`zhengdao_fu` 测试 `分级-缓存-园/并发幂等测试.rs` 编译失败 9 个错误——API 调用形态错。
- **根因**：上游 `shihai_fu::分级缓存.rs::存会话` 已从 `pub fn 存会话(&mut self, k: String, v: String)` 演化为 `pub fn 存会话(&mut self, 会话: 会话记录)`，但 `并发幂等测试.rs` 仍按旧 API 调用。
- **修复**（5 处）：
  - `use shihai_fu::{三级缓存, 模型存储, 记录, 缓存错误};` 增加 `会话记录`
  - 新增 `fn 会话(k, v) -> 会话记录` 快捷构造
  - 5 处 `g.存会话(key, val)` → `g.存会话(会话(key, val))`
  - 2 处断言 `opt.unwrap() == val` → `opt.unwrap().内容 == val`（新 API 返回 `&会话记录`，`.内容` 字段比对）
  - 1 处 `let 存储 = 模型存储::打开(...)` → `Arc<模型存储>`，闭包内 `Arc::clone` 共享
  - 1 处 `let g = 缓存.lock().unwrap()` → `let mut g = ...`（`取永久` 是 `&mut self`）
- **验证**：`cargo test -p zhengdao_fu --lib` 通过（162 passed / 0 failed / 5 ignored）。

## 经验沉淀

- **API 演进时下游测试没同步**：上游改函数签名，下游测试必报错（编译期保护），但本次存在是「函数签名变了 + 测试代码用了旧形态」的漂移。教训：API 改动的提交应同时改测试，否则 cargo test 会暴露不一致——本次正是这样发现的。
- **「对齐原版」的注释需落实**：作者留的注释「对齐原版」与实际原版不符，是引入 bug 的常见源头。修法：保留注释但写明「与原版 xxx.rs::校验涉及路径 行为一致」，方便未来读者核对。
- **孤立 .rs 文件的风险**：`越界判定.rs` 是孤立文件（未桥接、未引用），未来启用时需先确认与现有 `工具执行.rs::校验涉及路径预归一` 的分工，避免双实现并存。
