# 事故复盘 0001：工作区定位缓存导致测试竞态

## 日期
2026-08-25

## 状态
已修复

## 摘要
`工作区::定位()` 用 OnceLock 缓存首次计算结果，后续调用直接返回缓存。
测试通过 `WORLD_WORKSPACE_ROOT` 环境变量切换临时工作区，但 OnceLock 固化后不再读环境变量，
导致第二个测试起沙箱根指向第一个测试的临时目录，路径越界被拒。

## 影响
- zhengdao_fu 4 个测试失败：写文件后可读回 / 写文件自动建父目录 / 沙箱接受工作区根内路径 / 沙箱拒绝跳出工作区根
- 严重程度：阻塞（cargo test --workspace 不全绿）

## 根因
`工作区::定位()`（模型落盘.rs:51）用 `OnceLock<工作区>` 缓存 →
`临时工作区()`（隔离设施.rs:48）设 `WORLD_WORKSPACE_ROOT` 环境变量 →
`写文件()`（写入文件.rs:43）调 `工作区::定位()` 返回旧缓存 →
沙箱根 = 旧临时目录 → 新测试路径不在旧目录内 → 沙箱拒绝。

## 修复
把 `OnceLock<工作区>` 改成 `Mutex<Option<(工作区, Option<String>)>>`：
缓存时记下当时的 `WORLD_WORKSPACE_ROOT` 值，下次调用若环境变量变化则自动重算。
- 文件：`识海承载-府/识海-纳藏-殿/模型-存储-阁/模型-落盘-园/模型落盘.rs`
- 热路径开销：Mutex lock ~20ns + env::var ~100ns，文件 I/O 毫秒级，占比 0.01%。

## 教训
- OnceLock 不可重置，不适合需要测试切换状态的场景
- 缓存环境变量依赖项时，应同时缓存环境变量快照用于失效检测
- 测试共享设施（隔离设施.rs）的设环境变量操作，必须与被测代码的缓存机制协调
