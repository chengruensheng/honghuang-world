# 事故复盘 0003：mingling_fu 并行测试环境变量竞态

## 日期
2026-08-25

## 状态
已修复

## 摘要
mingling_fu 内三个测试模块各自定义独立的 Mutex 锁保护 `WORLD_WORKSPACE_ROOT` 环境变量。
锁不互斥（不同 static），并行测试时一个模块改环境变量，另一个模块的 `裁决验收` 写入错误路径，
导致 jsonl 追加冲突或断言失败。

## 影响
- mingling_fu `特殊字符意见_仍入队` 间歇性失败（并行跑时失败，单线程跑时通过）
- 严重程度：降级（cargo test --workspace 间歇性不过）

## 根因
三把独立锁不互斥：
- `批量审验.rs:49` → `串行锁`（只保护 测试_裁决验收 模块）
- `缓存读取.rs:186` → `测试环境锁`（只保护缓存读取测试）
- `流式回放测试.rs:11` → `串行`（只保护流式回放测试）
- `规模统计.rs` → 无锁

`裁决验收`（批量审验.rs:22）写 `状态目录()/验收.jsonl` →
`状态目录()`（入口执行.rs:60）读 `工作区根()` →
`工作区根()`（入口执行.rs:42）读 `WORLD_WORKSPACE_ROOT` →
其他模块的测试改了环境变量 → `裁决验收` 写入错误路径 →
断言 `结果.contains("已入验收历史")` 失败。

## 修复
在 crate 根（入口.rs）定义共享锁 `工作区测试锁`，4 个测试模块共用：
- `入口.rs` 加 `#[cfg(test)] pub mod 测试设施 { pub static 工作区测试锁: Mutex<()> = Mutex::new(()); }`
- `批量审验.rs`：`串行锁` → `crate::测试设施::工作区测试锁`
- `缓存读取.rs`：`测试环境锁` → `crate::测试设施::工作区测试锁`
- `流式回放测试.rs`：`串行` → `crate::测试设施::工作区测试锁`
- `规模统计.rs`：加 `crate::测试设施::工作区测试锁`

## 教训
- crate 内多个测试模块共享进程级状态（环境变量）时，必须用 crate 级共享锁
- 各模块独立锁不互斥，等于没锁
- 间歇性测试失败（单线程通过、并行失败）是竞态的典型信号

## 验证
```
cargo test -p mingling_fu --lib  # 93 passed / 0 failed / 0 ignored，并行跑
cargo test --workspace --lib     # 650 passed / 0 failed / 22 ignored
```
