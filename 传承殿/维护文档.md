## 六、命名与组织规则速查

- **层命名**：域=`4字-域`、府=`4字-府`（含 Cargo.toml）、殿=`2字-2字-殿`、阁=`2字-2字-阁`、园=`名字-类型-园`（园是文件夹）。
- **代码落园**：实现代码只落园层，crate 根是府级 `模块.rs`（`[lib] path` 指向），`#[path]` 层层汇总（连字符转下划线），**全项目无 `src` 目录**。
- **命名唯一性**：同级不重复，下级≠直接上级（域≠府≠殿≠阁≠园）。
- **数量上限**：域 ≤ 3；殿 ≤ 6 阁；阁 ≤ 4 园。
- **规模**：单文件 ≤ 500 行（建议 ≤ 350）；单函数 ≤ 50 行。

**③ 智能体自主开发（配置化收尾）**：工作区指向项目根，任务为「执行器超时/输出上限进 default.toml + Ctrl+C 接中断句柄」。智能体独立完成配置化三处（AppConfig 加字段、default.toml 加配置、执行器加 `new_with_limits`），但在接线/依赖上卡住（ctrlc 加错 crate、调用点未改、工具参数键误用英文 `path`、改完不验证），最终由验收补完（补 `executor_ctrlc` 字段、ctrlc 依赖入 hm-bootstrap、启动入口传参、修正 Ctrl+C 注释、补配置默认值测试）。

**能力结论**：智能体擅长局部单点改动，弱于跨 crate 全局接线与依赖管理，且缺"改完必验证"自律；危险命令拦截与 git 基线在本次实测中有效拦截了 `del`/`ren` 误发、支撑了审查回滚。

**测试数**：75 → 78（危险命令拦截 2 例 + 配置默认值 1 例）。

### 七·十、三态认知底座骨架（2026-09-05）

将「洪荒·世界」从"能理解项目的智能体"推进为"能可靠开发本项目"的底座型系统，落地「三态认知」的 MVP 数据骨架。三态对应三种互补的项目认知形态：

| 态 | 本体定位 | 注入策略 | 本次落地 |
|----|----------|----------|----------|
| 世界态（图谱） | 客观实在，代码即真源，毫秒级实时更新 | 拉（需细节时少量多次） | `图谱`：模块/符号/依赖边 + `查依赖`/`被谁依赖`/`查符号` |
| 心智态（36 格位） | 主观认知，命名与定性，可错可纠 | 推（每格最新一段全量常驻） | `维度`（6 主轴+正交）+ `格位`（维度/格位名/摘要/可信度/证据引用/目标内容）+ `心智地图`（维度+格位名唯一） |
| 过程态（上下文） | 执行过程，落盘可恢复 | 流（有就加，超阈值压缩） | `语境消息`+`过程上下文`：消息角色/追加/消息数 |

**错误变体新增**（hm-error）：`格位已存在`、`格位不存在` 共 2 个。

**构建主线**（后续迭代遵循）：先构造项目整体模型（图谱）→ 通过模型构建心智（36 格位）→ 根据执行过程获取运行时上下文。语言无关底座：核心图模型只用通用概念（模块/符号/依赖边/导出/引用），语言差异收敛到适配器。

**本次范围界定**：本骨架为 MVP 数据层，仅含数据容器与增删查改，serde 可序列化。以下留待后续迭代（本次不碰）：三态持久化（写穿落盘）、过程上下文阈值压缩、图谱 crate 扫描器（从 Cargo.toml 自动构建）、语言适配器、注入装配逻辑（推/流/拉接入 hm-agent）、36 格位本质清单。

**测试数**：81 → 95（认知 14 例：图谱查依赖/被谁依赖/查符号/序列化往返、心智地图添加查询/同维度同名拒绝/单点修正/更新不存在报错/序列化往返、维度内外判定/正交对、目标内容归属/非目标维度无目标内容、过程上下文追加内容/序列化往返）。

### 七·十一、世界入口前端府（2026-09-05）

将「洪荒·世界」的展示层从单文件 demo 推进为符合项目命名规范的组件化前端。定位：前端是「对外门面」，把五行引擎、三态认知底座、自主开发智能体的运行状态可视化呈现、供人交互，只做呈现、不承载业务逻辑。

**技术选型**（详见 `传承殿/设计原则-域/前端门面技术选型.md`）：先做 Web 前端、后续打包桌面（Tauri 2.0 壳，前端零改动）；通信用 axum HTTP API（Web/桌面统一）。组件化落地时，用户否决 Vue/Vite 框架——引入 Node 生态会带来 `node_modules`/`package.json` 等英文工具货，与项目「全中文、零构建、纯净」哲学相悖。最终确定：**不用框架，纯手写原生 ES Modules，参考框架理念以中文复写**。

**落地结构**（乾坤根下，严格套用域/府/殿/阁/园五层命名）：
- 域：`界面呈现-域`（乾坤土·展示）；府：`世界入口-府`（非 Rust crate，无 Cargo.toml）
- 殿（3）：`框架布局-殿`（三栏骨架）、`视图呈现-殿`（五视图）、`运行支撑-殿`（状态/路由/数据，最底层）
- 阁（各殿下 2/4/3 阁）、园（三段式，代码落园）

**理念对齐后端**（技术不同、理念一致）：分层后缀统一、依赖单向无环（视图层→布局层→运行支撑层）、府根 `入口.js` 层层装配（对应 crate 根 `模块.rs` 层层上报）。

**手写框架核心理念复刻**：`响应式核心.js` 实现发布订阅存储（参考 Pinia）、`导航核心.js` 实现视图注册 + hash 路由 + 订阅切换（参考 Vue Router）、每个视图一个组件文件含 `挂载/属性/卸载` 生命周期（参考 SFC）。

**五视图 + 数据流转**：对话（模拟执行流，完成联动五行引擎任务数 +1）、五行引擎（相生环 + 卡片点击详情）、项目图谱（节点点击结构化解释）、格位地图（6×6 点击字段）、运行日志（跨视图响应式实时刷新）。数据 mock 层（引擎/图谱/格位/日志）与未来 axum API 返回结构对齐。

**验证**：前端无 cargo 测试；经本地 HTTP 服务器运行，node 级联 import 验证全部模块语法与路径无误，浏览器渲染验证通过。
