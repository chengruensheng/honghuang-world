# 五行相生联动 落地设计

> **定位**：第七个落地模块。兑现已定契约「相生闭合循环」——用中立信号总线串联五个已验收的引擎，让
> 太初(木)→量劫(火)→乾坤(土)→道韵(金)→混沌(水)→太初(木) 形成真实跨引擎闭环，而非纸面承诺。
>
> **状态**：v1.1 · 2026-09-04
>
> **上游契约**：`传承殿/已定契约-域/已定契约.md`（实现必须遵守）
>
> **组织规则**：`rules/代码组织规则.md`（规模上限、模块.rs 汇总、证道只测府级）
>
> **前置**：鸿蒙、太初、量劫、乾坤、道韵、混沌均已实现并验收通过。

## 0. 设计目标

在九根之**鸿蒙**落地信号契约与信号总线，在**鸿蒙/系统装配-域**落地联动装配府（Composition Root），
在**证道**落地联动测试府，跑通五行相生的跨引擎信号闭环。

验证点：
1. 鸿蒙根下域 ≤ 3，代码只落园（无 `src`），crate 根为府级 `模块.rs`
2. 五个引擎保持互相独立（不新增引擎间直接依赖），依赖方向仍单向无环
3. 信号总线以「发布/订阅」中立解耦，引擎注入总线后由装配层统一串联
4. 五行相生五段桥接各自成立，且可整体闭环
5. 测试全在证道，只测 hm-linkage 府级公共 API

## 4. 信号契约（hm-signal）

### 4.1 信号（信号定义-殿/信号模型-阁/信号-数据-园/信号数据.rs）

```rust
use serde::{Deserialize, Serialize};

/// 信号：跨引擎的中立消息，类型 + 键值对载荷
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct 信号 {
    pub 类型: String,
    pub 载荷: Vec<(String, String)>,
}

impl 信号 {
    pub fn 新建(类型: String, 载荷: Vec<(String, String)>) -> Self {
        信号 { 类型, 载荷 }
    }
}
```

### 4.2 信号总线 trait（总线契约-殿/总线接口-阁/信号-接口-园/信号接口.rs）

```rust
use std::sync::Arc;
use hm_contract::Component;
use crate::信号定义_殿::信号;

/// 信号总线：府间解耦的发布/订阅通道（继承 Component 契约）
pub trait 信号总线: Component {
    fn 发布(&self, 信号: &信号);
    fn 订阅(&self, 类型: &str, 处理器: Arc<dyn Fn(&信号) + Send + Sync>);
}
```

> 说明：`发布`/`订阅` 均取 `&self`，要求实现用内部可变性（如 `Mutex`），以保证引擎在 `&self` 方法中也能发信号。

## 5. 内存信号总线（hm-signal-bus）

总线实现-殿/内存总线-阁/总线-模块-园/总线模块.rs：

```rust
use std::sync::{Arc, Mutex};
use hm_contract::Component;
use hm_signal::{信号, 信号总线};

/// 内存信号总线：订阅表 + 发布时克隆处理器、释放锁后执行（重入安全）
pub struct 内存信号总线 {
    订阅表: Mutex<Vec<(String, Arc<dyn Fn(&信号) + Send + Sync>)>>,
}

impl 内存信号总线 {
    pub fn new() -> Self {
        内存信号总线 { 订阅表: Mutex::new(Vec::new()) }
    }
}

impl 信号总线 for 内存信号总线 {
    fn 发布(&self, 信号: &信号) {
        let 处理器列表: Vec<_> = self.订阅表.lock().unwrap().iter()
            .filter(|(类型, _)| 类型 == &信号.类型)
            .map(|(_, 处理器)| 处理器.clone())
            .collect();
        for 处理器 in 处理器列表 {
            处理器(信号);
        }
    }

    fn 订阅(&self, 类型: &str, 处理器: Arc<dyn Fn(&信号) + Send + Sync>) {
        self.订阅表.lock().unwrap().push((类型.to_string(), 处理器));
    }
}

impl Component for 内存信号总线 {
    fn name(&self) -> &'static str { "内存信号总线" }
}
```

> 关键：`发布` 先锁内克隆匹配处理器、立即释放锁，再逐个执行处理器。这样处理器内若再发信号（信号级联），不会死锁——重入安全。

## 6. 引擎接入（五个引擎各加总线注入 + 触发点）

五个引擎**不改动互相依赖**，只新增：
1. 字段 `信号总线: Option<Arc<dyn 信号总线>>`（`hm-signal` 依赖）
2. 方法 `设置信号总线(&mut self, 总线: Arc<dyn 信号总线>)`
3. 私有 `发布信号(&self, 类型, 载荷)`（无总线时静默忽略）
4. 关键动作后发信号

| 引擎 | 触发点 | 信号类型 | 载荷 |
|------|--------|---------|------|
| tc-task 任务 | `推进` 到 `已完成` | 任务完成 | id、title |
| lj-iteration 迭代 | `完成` 成功 | 迭代完成 | version、变更说明 |
| qk-memory 记忆 | `写入` 成功 | 记忆写入 | 内容、标签 |
| dy-rule 规则 | `评估` 命中最高优先级 | 规则命中 | 规则名、结论 |
| hd-event 事件 | `发布` 成功 | 事件发布 | 类型、id |

> 注意：`MemoryStore`、`RuleSet` 因含 `Option<Arc<dyn 信号总线>>` 无法 `derive(Debug)`（`dyn 信号总线` 不实现 Debug），
> 故仅保留 `#[derive(Clone, Serialize, Deserialize)]`，总线字段加 `#[serde(skip)]`（不参与落盘，加载后需重新注入）。
> `EventBus` 因含闭包字段本就不整体派生序列化，总线字段运行时态，不落盘。

## 7. 联动装配（hm-linkage）

桥接模块.rs 中 `五行装配`（Composition Root）：

```rust
pub struct 五行装配 {
    pub 任务仓库: Arc<Mutex<TaskStore>>,

    pub 记忆库: Arc<Mutex<MemoryStore>>,
    pub 规则库: Arc<Mutex<RuleSet>>,
    pub 事件总线: Arc<Mutex<EventBus>>,
    pub 信号总线: Arc<内存信号总线>,
}

pub fn 装配() -> 五行装配 {
    let 信号总线 = Arc::new(内存信号总线::new());
    // 创建五个引擎（Arc<Mutex<引擎>>）
    // 向每个引擎 设置信号总线(信号总线.clone())
    // 桥接木生火(信号总线, 迭代日志);
    // 桥接火生土(信号总线, 记忆库);
    // 桥接土生金(信号总线, 规则库);
    // 桥接金生水(信号总线, 事件总线);
    // 桥接水生木(信号总线, 任务仓库);
}
```

五段桥接逻辑（相生链）：

| 桥接 | 相生 | 订阅信号 | 动作 |
|------|------|---------|------|
| 桥接木生火 | 木生火 | 任务完成 | 当前版本递增次 → 开启新迭代 |
| 桥接火生土 | 火生土 | 迭代完成 | 写入记忆（内容=迭代标题，标签="迭代"） |
| 桥接土生金 | 土生金 | 记忆写入 | 添加规则（空条件，结论=记忆内容） |
| 桥接金生水 | 金生水 | 规则命中 | 发布事件（类型=规则名，载荷=结论） |
| 桥接水生木 | 水生木 | 事件发布 | 创建任务（标题=事件类型驱动） |

### 启动接入（hm-bootstrap）

`hm-bootstrap` 启动入口依赖 `hm-linkage`，启动流程：
1. 初始化配置 + 日志（原有）
2. `五行装配::装配()` 完成五引擎 + 信号总线串联
3. `演示闭环()` 触发一次完整相生闭环，返回 `闭环状态` 快照，验证相生链真实可运行

```rust
pub struct 闭环状态 {
    pub 任务数: usize,
    pub 迭代数: usize,
    pub 记忆数: usize,
    pub 规则数: usize,
    pub 事件数: usize,
}
```
