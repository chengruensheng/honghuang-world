## 二、五层职责定义（对齐的是后端的「组织思想」）

后端五层角色（道祖→圣人→大罗金仙→准圣→太乙金仙）是一条**串行接力流程**，前端没有这条流程。前端对齐的是后端的**组织思想**：单一职责、层层汇总上报、插件化、依赖单向、同级不重复。

| 层 | 后端语义 | 前端职责 | 韧性语义 |
|----|---------|---------|---------|
| 域 | 唯一对外边界 | 呈现边界：统一装配各府、隔离故障 | 静态骨架先行 |
| 府 | 独立编译单元（插件） | **可插拔能力单元**：独立装载/卸载 | **故障隔离边界** |
| 殿 | 府内分区 | 能力内的职责分区 | 分区互不依赖 |
| 阁 | 具体功能 | 具体功能单元 | — |
| 园 | 落地实现文件 | 落地实现文件（代码落园） | — |

## 三、韧性设计（崩溃隔离）

### 3.1 三道防线

1. **静态骨架**——背景、顶栏、两栏栅格、看板容器写在 `index.html`，样式用 `<link>` 静态引入，不经过任何 JS。JS 全崩，骨架仍在，空的只是内容区。
2. **动态装载**——域装配各府时用 `await import()` 逐个加载，每次包 `try/catch`。某府加载失败或抛错，只在该区域显示降级提示，不拖垮其它府。
   （若用静态 `import`，一处语法错会让整条依赖链全挂，达不到隔离；故必须动态装载。）
3. **单向依赖**——府与府之间不互相 `import` 业务代码，只经「总线」（浏览器 CustomEvent）通信。依赖方向唯一：域装配 → 府 → 殿 → 阁 → 园。

### 3.2 崩溃影响面

| 崩掉的单元 | 用户看到什么 |
|---|---|
| 底座骨架（样式部分） | 样式丢失——几乎不可能（纯 CSS 静态引入，无 JS 依赖） |
| 底座骨架（运行时中枢部分） | 全局不可用——但它无网络、无异步、无渲染，风险最低 |
| 契约词表 | 各视图提示「契约未就绪」，骨架完好 |
| 观测台面 | 左右两栏空白，顶栏、看板照常可用 |
| 看板流转 | 看板页空白，观星台照常用 |
| 流式驱动 | 无实时数据，可切回演示模式，骨架完好 |

## 七、模块契约与依赖方向

- 各模块用 ES module `export` 显式暴露；运行时可变状态统一收敛在 `运行时中枢.js` 导出的**状态对象**上（`export let` 在跨模块赋值时不会同步，必须用对象承载）。
- 依赖方向（单向无环）：
  `装配入口 → 各府对外模块 → 运行时中枢 / 契约词表 / 演示语料`
- 被多处调用的公共函数一律下沉到 `运行时中枢.js`（`$`/`转义`/`连接语`/空态），杜绝各府各算一套。
- `帧编排.js` 单向依赖 `棒条渲染.js`/`变更渲染.js`/`摘要逻辑.js`；反向不成立。

### 10.3 落地期修复

- `对话渲染.js` 摘要卡字段恢复 `转义()` 包裹时漏改 import，致演示重放抛 `ReferenceError`。已补 `转义` 导入，复测通过。
- **降级提示被空态覆盖**（韧性复验抓到）：某府装载失败后，顶层已在该区写下故障说明，随后「流式驱动-府」的 `刷连接语()` 又调 `刷天机空态()` 把该区改写为「实时已连接，等待任务事件…」——界面在替一个没就绪的区域自述正常。修复：`降级()` 给该区打 `data-降级` 留痕，`渲染天机空态()` / `渲染对话()` 见到留痕即不改写。故障说明与空态语同属「界面陈述」，前者优先级更高。

### 10.4 府间总线化（原「已知偏差」已解决）

第七节约定「府与府之间不互相 import 业务代码，只经总线通信」。首次落地有 8 处跨府直连，**已全部拆除**，改由顶层装配入口做唯一接线台：

| 调用方（府） | 原被调方 | 原调用 | 现经总线事件 |
|---|---|---|---|
| 观测台面 · 帧编排 | 看板流转 | `拉看板` | `请求拉看板` |
| 观测台面 · 发布逻辑 | 看板流转 | `拉看板` | `请求拉看板` |
| 观测台面 · 发布逻辑 | 流式驱动 | `重放事件` | `请求重放` |
| 流式驱动 · 订阅逻辑 | 观测台面 | `收帧` / `复位呈现` / `播放脚本` | `收到帧` / `复位呈现` / `播放脚本` |
| 流式驱动 · 接待逻辑 | 观测台面 | `起消息` / `落确认钮` / `发布` | `接待开启` / `接待增量` / `接待收尾` |
| 流式驱动 · 接待逻辑 | 看板流转 | `拉看板` | `请求拉看板` |

- **总线词表**（8 项）与 `广播()` / `监听()` 同归 `运行时中枢.js`（公共底座），各府只 import 它，不 import 同侪。
- **唯一接线台**：`装配入口.js` 的 `承总线()` 把一府的发令转给另一府的接口。接线表必须在 `连实时()` **之前**接好——订阅府一被调用即广播「复位呈现」。
- **配套拆解**：`复位呈现` / `播放脚本` 由 `帧编排.js` 导出（原先散在订阅逻辑内）；`刷天机空态` 下沉为公共底座函数；`装配入口.js` 模块清单新增「帧流」条目（订阅府已不再 import 帧编排，须由顶层显式装载）。
- **复查结论**：全库 import 逐条核对，跨府 import **仅剩两个允许方向**——公共底座（底座骨架-府）与数据常量（契约词表-府）。任一业务府缺件，不再沿 import 链连坐。

### 10.5 思考与正文分离下发（2026-09-11 续）

**背景**：接待流式原先把答复里的 `<think>…</think>` 草稿**剥掉丢弃**——正文干净了，过程证据也没了；而推理模型（MiniMax-M3）另把思考放在 `reasoning_content` 独立字段，链路末端未透传，思考再次被静默丢弃。界面上既看不到草稿，也看不到思考。

**升级**（对齐 AG-UI `REASONING_MESSAGE_*` 词表，与业界「分离到独立通道」的主流做法一致）：

| 层 | 改动 |
|---|---|
| 协议适配（`协议适配.rs`） | `思考链过滤器` 由「剥除」改为**分离双输出**（`分流结果{思考, 正文}`）；「任务答复」夹带的思考转入推理通道，正文仍走文本三段式 |
| 请求处理（`受理处理.rs`） | 接待流式按分离下发：思考走 `REASONING_MESSAGE_START/CONTENT/END`（游标管理，一条消息不跨段），正文走 `TEXT_MESSAGE_CONTENT`；上游 `思考` 字段补进同一推理通道 |
| 接待驱动（`接待模块.rs`） | `接待响应` 补 `思考` 字段并透传（此前上游 reasoning 在链路末端被丢弃） |
| 前端（总线 / 接待 / 渲染 / 样式） | 新增 `接待思考` 总线与接线；`接待逻辑.js` 识别 `REASONING_MESSAGE_CONTENT` 独立累积；`对话渲染.js` 新增折叠推理条 `.推理条`（挂气泡之前、默认折叠），重绘按记录还原；色位与右栏「条.推理」同源（水色） |

**修复的三个真缺陷**：

1. **工具调用路径答复丢失**（浏览器实测抓到）：道祖走「对齐总结」工具时，答复由**工具参数合成**（「我理解为「…」，现在开始安排…」），不在 `content` 流式增量里——模型在 `content` 里只回了 `"\n\n"`。正文气泡因此空着，答复实际没给来访者看。修复：收尾时若正文通道**没吐出任何可见内容**且最终答复非空，则补发该答复。
2. **空白答复冒充内容**：前端兜底判空用 `!记录.文`，`"\n\n"` 被判「非空」→ 不兜底 → 气泡显示为一片空白。修复：改按可见内容判（`!记录.文.trim()`），只有空白等同没有答复。
3. **右栏棒头摘要被思考霸占**（硬约束复查抓到）：`帧编排.js` 曾把 `REASONING_MESSAGE_CONTENT` 的 delta 写入 `棒.数据.首句`，而 `首句` 正是**无工具动作时的棒头摘要**来源（`棒条渲染.js` 的 `摘文`）。推理帧在协议上先于正文到达，`if(!首句)` 先到先得 → 摘要必然是思考草稿，真正的答复永远进不去。修复：推理只进「推 理」条，`首句` 仅由 `TEXT_MESSAGE_CONTENT`（正文）写入——摘要只回答「这一棒给了什么答复」。

**兜底措辞**（按用户指令）：原「（未收到答复：道祖可能未上线）」在替道祖猜原因，属界面自述。改为中性陈述：「（道祖未返回可显示的答复）」。

| `cargo build --workspace` / `cargo test --workspace` | 通过（仅 MSVC 链接器噪音）/ 全绿（`CARGO_EXIT=0`，无 FAILED） |
| 分离下发（工具调用路径） | 道祖气泡 = 权威答复 32 字；推理条 1038 字；思考与正文互不混入；确认发布钮正常 |
