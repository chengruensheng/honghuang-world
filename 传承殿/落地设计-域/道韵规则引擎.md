# 道韵·规则引擎 落地设计

> **定位**：第五个落地模块。兑现五行之**金**（收敛、规范）——规则是"经验中的收敛"。核心职责：规则入库、收敛唯一、规则评估（匹配 + 优先级消解）、落盘持久化。
>
> **状态**：v1.0 · 2026-09-04
>
> **上游契约**：`传承殿/已定契约-域/已定契约.md`（实现必须遵守）
>
> **组织规则**：`.codeartsdoer/rule/代码组织规则.mdc`（规模上限、模块.rs 汇总、证道只测府级）
>
> **前置**：鸿蒙、太初、量劫、乾坤均已实现并验收通过，复用其 hm-error、hm-contract、「模块汇总 + 证道测府级」范式，以及乾坤已验证的 TOML 持久化范式。

---

## 0. 设计目标

在九根之**道韵**下落地规则引擎，跑通"规则入库 → 收敛唯一 → 事实评估匹配 → 落盘 → 加载还原"的最小闭环。

验证点：
1. 道韵根下域 ≤ 3，代码只落园（无 `src`），crate 根为府级 `模块.rs`
2. 规则能添加（收敛入库）、能按名称查询、能列出全部
3. 同名规则被拒绝（金之收敛/唯一约束），集合保持不变
4. 规则评估：给定事实，匹配所有条件都满足的规则，并按优先级降序返回
5. 规则库能落盘（保存）并从文件还原（加载），往返内容一致，加载后 id 延续不冲突
6. 府可插拔：`RuleSet` 实现 `Component` 契约
7. 测试全在证道，只测 dy-rule 府级公共 API

## 6. crate 设计（dy-rule）

### 6.1 Rule 规则条目（规则定义-殿/规则模型-阁/规则-数据-园）

园内 `规则数据.rs`：

```rust
use serde::{Deserialize, Serialize};

/// 规则：金之规范，零散经验收敛而成的判定单元
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Rule {
    pub id: u64,
    pub 名称: String,
    /// 条件：前提键值对列表，规则命中的事实要求
    pub 条件: Vec<(String, String)>,
    pub 结论: String,
    /// 优先级：数值越大越优先（金之收敛，用于冲突消解）
    pub 优先级: u32,
}

impl Rule {
    pub fn 新建(id: u64, 名称: String, 条件: Vec<(String, String)>, 结论: String, 优先级: u32) -> Self {
        Rule { id, 名称, 条件, 结论, 优先级 }
    }
}
```

### 6.2 RuleSet 规则库（规则收敛-殿/规则库-阁/库-模块-园）

园内 `库模块.rs`：

```rust
use hm_contract::Component;
use hm_error::{Error, Result};
use serde::{Deserialize, Serialize};
use crate::规则定义_殿::Rule;

/// 规则库：收敛规则，支持事实评估与落盘持久化
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RuleSet {
    rules: Vec<Rule>,
    next_id: u64,
}

impl RuleSet {
    pub fn new() -> Self {
        RuleSet {
            rules: Vec::new(),
            next_id: 1,
        }
    }

    /// 添加规则（金之收敛：同名拒绝），返回规则 id
    pub fn 添加规则(&mut self, 名称: &str, 条件: Vec<(String, String)>, 结论: &str, 优先级: u32) -> Result<u64> {
        if self.rules.iter().any(|r| r.名称 == 名称) {
            return Err(Error::Other(format!("规则名已存在: {名称}")));
        }
        let id = self.next_id;
        self.next_id += 1;
        self.rules.push(Rule::新建(id, 名称.to_string(), 条件, 结论.to_string(), 优先级));
        Ok(id)
    }

    /// 按名称查询
    pub fn 按名称(&self, 名称: &str) -> Option<&Rule> {
        self.rules.iter().find(|r| r.名称 == 名称)
    }

    /// 全部规则
    pub fn 全部(&self) -> Vec<&Rule> {
        self.rules.iter().collect()
    }

    /// 评估：匹配所有条件都满足的规则，按优先级降序返回
    pub fn 评估(&self, 事实: &[(String, String)]) -> Vec<&Rule> {
        let mut matched: Vec<&Rule> = self
            .rules
            .iter()
            .filter(|r| r.条件.iter().all(|(k, v)| 事实.iter().any(|(fk, fv)| fk == k && fv == v)))
            .collect();
        matched.sort_by(|a, b| b.优先级.cmp(&a.优先级));
        matched
    }

    /// 保存到文件（落盘）
    pub fn 保存(&self, path: &str) -> Result<()> {
        let content = toml::to_string(self)
            .map_err(|e| Error::Other(format!("序列化规则失败: {e}")))?;
        std::fs::write(path, content)
            .map_err(|e| Error::Other(format!("写入规则文件 {path} 失败: {e}")))?;
        Ok(())
    }

    /// 从文件加载（还原）
    pub fn 加载(path: &str) -> Result<Self> {
        let content = std::fs::read_to_string(path)
            .map_err(|e| Error::Other(format!("读取规则文件 {path} 失败: {e}")))?;
        toml::from_str(&content)
            .map_err(|e| Error::Other(format!("解析规则文件失败: {e}")))
    }
}

impl Component for RuleSet {
    fn name(&self) -> &'static str { "规则库" }
}
```

依赖：`hm-error`、`hm-contract`、`serde`、`toml`。

### 6.3 zd-rule-test（证道/基础验证-域/规则测试-府）

只测 dy-rule 府级公共 API。

园内 `规则测试.rs`：

```rust
#[cfg(test)]
mod tests {
    use dy_rule::RuleSet;

    fn 临时路径(名: &str) -> String {
        std::env::temp_dir()
            .join(format!("dy_rule_test_{名}.toml"))
            .to_string_lossy()
            .into_owned()
    }

    #[test]
    fn 添加规则后可按名称查询() {
        let mut set = RuleSet::new();
        let id = set.添加规则("金规", vec![("层".into(), "园".into())], "代码落园", 1).unwrap();
        let r = set.按名称("金规").unwrap();
        assert_eq!(r.id, id);
        assert_eq!(r.结论, "代码落园");
    }

    #[test]
    fn 同名规则被拒绝() {
        let mut set = RuleSet::new();
        set.添加规则("金规", vec![], "一", 1).unwrap();
        assert!(set.添加规则("金规", vec![], "二", 2).is_err());
        assert_eq!(set.全部().len(), 1);
    }

    #[test]
    fn 规则评估匹配满足条件的规则() {
        let mut set = RuleSet::new();
        set.添加规则("落园规", vec![("对象".into(), "代码".into())], "代码落园", 1).unwrap();
        set.添加规则("无痕规", vec![("对象".into(), "秘密".into())], "不落盘", 2).unwrap();
        let 事实 = vec![("对象".into(), "代码".into())];
        let 命中 = set.评估(&事实);
        assert_eq!(命中.len(), 1);
        assert_eq!(命中[0].名称, "落园规");
    }

    #[test]
    fn 评估按优先级降序() {
        let mut set = RuleSet::new();
        set.添加规则("低", vec![("天".into(), "雨".into())], "低", 1).unwrap();
        set.添加规则("高", vec![("天".into(), "雨".into())], "高", 9).unwrap();
        let 事实 = vec![("天".into(), "雨".into())];
        let 命中 = set.评估(&事实);
        assert_eq!(命中.len(), 2);
        assert_eq!(命中[0].名称, "高");
        assert_eq!(命中[1].名称, "低");
    }

    #[test]
    fn 持久化往返() {
        let path = 临时路径("往返");
        let mut set = RuleSet::new();
        set.添加规则("金规", vec![("层".into(), "园".into())], "代码落园", 1).unwrap();
        set.保存(&path).unwrap();
        let loaded = RuleSet::加载(&path).unwrap();
        assert_eq!(loaded.全部().len(), 1);
        assert_eq!(loaded.按名称("金规").unwrap().结论, "代码落园");
        std::fs::remove_file(&path).ok();
    }

    #[test]
    fn 加载后id延续不冲突() {
        let path = 临时路径("延续");
        let mut set = RuleSet::new();
        set.添加规则("一", vec![], "一", 1).unwrap();
        set.保存(&path).unwrap();
        let mut loaded = RuleSet::加载(&path).unwrap();
        let new_id = loaded.添加规则("二", vec![], "二", 1).unwrap();
        assert_eq!(new_id, 2);
        std::fs::remove_file(&path).ok();
    }
}
```

> 注意：持久化相关测试用 `临时路径(名)` 生成独立文件名（`往返`/`延续`），避免并发测试互相覆盖（乾坤记忆引擎的教训）。

依赖：`dy-rule`。
