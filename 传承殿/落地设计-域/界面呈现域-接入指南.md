# 界面呈现域 · 接入指南

> 定位：记录「门面.html」如何从纯静态骨架，逐步接入真实能力（对话 / 看板 / 记忆 / 图谱 / 文件 / LLM），
> 让**界面真实显示、LLM 真实使用、AI 真实产出**。

- 文档型：落地设计（实施契约）
- 版本：1.0
- 域：乾坤/界面呈现-域
- 更新：2026-09-08

---

## 一、现状与目标

### 现状
`门面.html` 已通过 **四层隔离** 落地：

| 层 | 落点 | 职责 |
|---|---|---|
| 背景层 | 视觉背景-殿/色彩基调-阁 | 设计令牌（五行基色/面材/线/字），页面底色 |
| 布局层 | 区域布局-殿/骨架分区-阁 | 五槽位网格（顶/左/主/右/底）+ `乾坤界面.挂载` 契约 |
| 组件层 | 功能组件-殿/*-阁/组件-园 | 各组件=「样式 + 脚本 + 模块.rs」，经契约入园 |
| 组装层 | 页面承载-殿/入口组装-阁 | 内联背景+布局+组件，`落盘页面(目录)` 写出门面.html |

**关键缺口**：组件目前是**静态 mock 数据**，未调用任何后端接口。

### 目标
让门面页成为数据服务（`hm-http`）的同源前端页面，组件通过 `fetch` 调用真实 API，
对话流接入 `/api/dev/chat`（道祖对话），LLM 真实产出。

## 二、接入三件事

### 1. 让数据服务托管门面页
数据服务用 `ServeDir` 托管 `static_dir`（默认 `artifacts/agent-workspace`）。
要让门面页生效，任选其一：

- **A（推荐）**：把 `落盘页面()` 产物复制到 `artifacts/agent-workspace/` 下（文件名 `门面.html`），
  并把 `[http].static_dir` 指向该目录 → 启动后 `http://127.0.0.1:8321/门面.html` 即真实页面。
- **B**：改 `[http].static_dir` 为 `target/界面-预览`，直接托管 `门面.html`。

> 同源关键：门面页与 `/api/*` 同端口，`fetch "/api/..."` 的相对路径才成立。
>
> **环境注入（已落地）**：`门面.html` 模板内联 `window.乾坤配置 = { 道祖: … }`——
> 同源（8321）时为空串走相对路径；预览端口（8899）或 file 打开时显式指向 `http://127.0.0.1:8321`
> （后端 `CorsLayer::permissive()` 允许跨源）。组件统一经 `乾坤配置.道祖` 取后端地址，不写死端口。

### 2. 对话接真实 LLM（已完成 ✅）
- 接口：`POST /api/dev/chat`，body `{ "消息": "..." }`，返回 `{ 阶段, 回复, 需求? }`。
- 前置：后端 `[app].run_dev_agent = true` 且 LLM 池装配成功（`[llm.providers]` 配置 + api_key 有效），
  否则返回 503「道祖未上线」。
- 密钥：`api_key = "env:变量名"` → `dotenvy` 从项目根 `.env` 加载；密钥不进仓库。
- 前端：对话流「发送」时先 `fetch` 调 `/api/dev/chat`，成功渲染 `回复`；
  失败（503/未上线）降级提示，不阻塞界面。
- 回复净化：HTML 转义 + `<think>` 思考段折叠为 `<details>`（对话流.js `净化`）。

### 2b. LLM 设置面板接真实接口（已完成 ✅）
- 打开设置面板时拉取 `GET /api/llm/status`（当前选择/配置态）与 `GET /api/llm/models`（供应商模型清单）。
- 点击模型 chip → `POST /api/llm/select` `{供应商, 模型}` → 成功后重拉状态，当前行与 chip 高亮同步。
- 降级：后端未在线 → 红点「数据服务未在线」；供应商拉模型失败 → 组内黄字显示接口原始错误。
- 已实测闭环：UI 切 M2.5 → 后端 `当前选择` 变更 → UI 切回 M3。

### 2c. 左栏视图接真实数据（已完成 ✅）
- 新增「左栏视图-阁」组件：`乾坤视图` 监听 `乾坤图标` 事件，键=记忆/图谱 展开左抽屉，其余收起。
- 记忆：`GET /api/memories` → 逐条渲染（内容 · 标签 · 待归档徽标 · 时间）；空库显示空态。
- 图谱：`GET /api/cognition/graph` → 按**真实字段**渲染：`符号集` 按 `所属模块` 聚合为可折叠分组、
  计数（`符号集`/`模块集`/`依赖集`）、`技术栈` chips。
- 关键修正：图谱顶层字段是 `符号集/模块集/依赖集`（非 `节点`），见 `hm-cognition` 图谱数据定义。
- 抽屉收起时 `pointer-events:none` + `visibility:hidden`，避免移出屏幕的边缘压住图标轨拦截点击。
- 已实测：记忆 0 条空态、图谱 698 符号 · 39 模块 · 145 依赖，均真实拉取渲染。

### 2d. 三殿文件面板接真实文件（已完成 ✅）
- 后端新增文件接口（`hm-http` 观测读取-殿/文件查询-阁）：
  - `GET /api/files` → 扫描 `扫描根` 递归收集，按互斥优先级分类返回 `{传承殿, 门禁, 架构}`。
  - `GET /api/files/content?路径=xxx` → 读单文件内容（限可读扩展名 + 128 KiB 上限 + 防目录穿越）。
- 分类规则（互斥，按优先级）：**架构**（文件名含「架构/蓝图」）> **门禁**（含「门禁」）>
  **传承殿**（扩展名 md/html/txt 纯文档，代码文件不归传承殿）。
- 前端左栏视图扩展：键=传承殿/门禁/架构 → 左抽屉按顶层目录分组（默认展开）列文件；
  点击文件 → 阅读覆盖层拉 `/api/files/content` 全屏预览。
- 数据服务状态新增 `扫描根` 字段（默认 `./`），启动模块注入 `config.app.scan_root`。
- 已实测：传承殿 126 文档 / 门禁 6 / 架构 5；内容读取返回正常；后端 3 项分类测试 + 前端断言通过。

### 2e. 底栏接真实状态（已完成 ✅）
- 底栏由静态 mock（1.2M/340 节点/DeepSeek-V3/v1.55）改为真实 fetch：
  记忆/规则/事件计数、图谱符号数、当前模型（`/api/llm/status`）、版本（`/api/iterations/version`），失败降级为「—」。

### 2f. 主区任务看板接入（已完成 ✅）
- 看板复用现有 `GET /api/board`（返回 `Vec<Task>`，字段含 `status`/`title`/`优先级`/`当前承接人`）。

### 2g. 顶栏项目工作区选择器（已完成 ✅）
- 后端新增工作区接口：`GET /api/workspace`（返回当前项目根）+ `POST /api/workspace`（设置项目根，
  校验目录存在并规范化为绝对路径，去掉 Windows `\\?\` 前缀）。
- 「项目工作区根」= 项目根目录：文件面板（传承殿/门禁/架构）扫描它，后续智能体产出也落在此根下。
- 数据服务状态 `扫描根` 由 `String` 改为 `Arc<Mutex<String>>`，支持运行时切换（文件清单/内容读取实时跟随）。
- 顶栏新增工作区选择器：显示当前项目根，点击展开内联输入面板，输入路径 → POST 切换；模型标识顺带接真实 `/api/llm/status`。
- **工作区三处统一**（关键）：`POST /api/workspace` 同时同步 ①扫描根 ②开发受理台（`重装配工作区`）
  ③看板驱动台（`重装配看板驱动`），确保五层协作驱动器的执行器工作区与扫描根一致，
  智能体产出直接落项目根而非独立沙箱子目录。

### 3. 其余组件逐个接对应接口
每个组件园遵循统一约定：**样式只引令牌、脚本只经契约入园、数据一律来自 fetch**。

| 组件 | 接口 | 用途 |
|---|---|---|
| 对话流 | `POST /api/dev/chat` / confirm | 道祖澄清会话、确认对齐 |
| 看板 | `GET /api/board` · `POST /api/board/{id}/accept|submit|clean|rollback|sweep` | 任务看板分列 |
| 记忆 | `GET /api/memories` | 记忆库列表 |
| 图谱 | `GET /api/cognition/graph` | 世界态图谱 |
| 规则 | `GET /api/rules` | 道韵规则清单 |
| 事件 | `GET /api/events` /* `POST /api/logs` | 事件增查 |
| 文件/终端 | 走 `hm-execute` 本地执行器（受限于桌面壳工作区） | 工作区读写 |
| LLM 设置 | `GET /api/llm/status` · `/models` `POST /select` `/discover` `/connect` | 供应商/模型管理 |

## 三、前端接入模式（组件园统一范式）

每个组件园三件套 + 一份聚合，就能接上真实数据：

```
功能组件-殿/<名称>-阁/组件-园/
├── <名称>.css    # 外观 · 只引令牌（var(--契) 等）
├── <名称>.js     # 实现 · 经乾坤界面.挂载入园 + fetch 调接口
└── 模块.rs       # 导出 pub const <名称>样式 / <名称>脚本
功能组件-殿/模块.rs   # 聚合导出 组件样式() / 组件脚本()
```

### 组件脚本骨架
```js
window.乾坤<名称> = (function(){
  function 建(){ /* 构建 + 经挂载契约入园 */ }
  function 取数据(){ // 真实调用
    fetch("/api/{接口}").then(r=>r.json()).then(d=>渲染(d)).catch(降级);
  }
  return { 建, 渲染, 取数据 };
})();
乾坤界面.挂载("<槽位>", 乾坤<名称>.建);
```

## 四、验证与门禁

- **构建验证**：`cargo run -p qk-web --bin 界面-预览` 生成并落盘门面.html，产物含目标槽位与契约。
- **静态断言**（界面测试-府/界面校验-殿/页面测试-阁）：`页面源码` 含令牌、`data-槽位名="主区"`、`乾坤界面` 与 `挂载:`。
- **真实联调**：启动 `hm-bootstrap`（`run_dev_agent=true` + 配置供应商密钥），
  `POST /api/dev/chat` 应返回 `{阶段, 回复}`；门面页发送同内容应渲染该 `回复`。
- **门禁**：对话流接入后，若有接口返回非 2xx，前端需有可见降级提示，不得静默空白。
