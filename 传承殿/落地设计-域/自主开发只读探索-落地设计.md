# 自主开发只读探索 · 落地设计

> 定位：把智能体从「全锁工作区」升级为「**读项目根、写工作区**」——让它能理解本体代码，但产出仍落沙箱，由外部（评测方/人工）独立测试后搬移。这是「自己开发自己」信任阶梯的第 1 步（读写分离），不放开任何写权限。

- 文档型：落地设计（实施契约）
- 版本：1.0
- 域：鸿蒙/基础能力-域（执行工具）+ 鸿蒙/系统装配-域（自主开发）
- 更新：2026-09-13

---

## 一、背景与目标

### 背景
用户要把项目推向「系统自己开发自己」。当前智能体（循环驱动 + 五层驱动）的执行器把**读与写都锁死在工作区沙箱内**，智能体**读不到本体代码**（鸿蒙/太初/证道等 40 个 crate 全在工作区之外），自然无法「理解现状再开发」。

用户给出的信任边界（已确认）：

1. **读**放开到「项目根 + 白名单子目录」。
2. **写**仍锁工作区沙箱。
3. **命令**放开到「只读」。
4. 测试由**外部**（评测方/人工）连接执行；通过后由外部**搬移**进本体；失败则沙箱内删除。

### 目标
- 智能体可**只读**探索完整项目（读文件/列目录/按名找文件/搜索内容/只读命令）。
- 智能体**写**能力不变：仍只能写工作区，越界一律拒绝。
- 外部「测试 → 搬移 / 删除」的闭环由评测方执行，本设计不改变系统的验收/合入逻辑（那是后续阶段）。

### 关键事实：读越界已有「半开口子」
命令白名单含 `cd`/`dir`/`type`/`findstr`，而命令经 `cmd /C` 每轮独立子进程执行（`cd` 只作用于该子进程）。因此智能体**已可用 `cd .. && dir` 偷看工作区外**。本设计不是「新开一个洞」，而是把这个**不受控的半开口子规范化、显式化、可控制化**——这是安全性提升，不是下降。

## 三、核心设计：读写分离 + 只读根

### 3.1 执行器新增「只读根集合」

`本地执行器` 新增字段：

```
只读根: Vec<PathBuf>   // 默认空 = 只有工作区可读（保持现状，测试 mock 零改动）
```

构造与链式注入：

```
pub fn 设置只读根(mut self, 根们: Vec<PathBuf>) -> Self
```

启动装配时（[开发入口.rs](../../鸿蒙/系统装配-域/启动入口-府/装配流程-殿/流程入口-阁/开发-入口-园/开发入口.rs) 三处 + [启动模块.rs](../../鸿蒙/系统装配-域/启动入口-府/装配流程-殿/流程入口-阁/启动-模块-园/启动模块.rs) 扫尾），把以下合并为「只读根集合」注入：

1. **项目根**（进程 cwd，即 `f:\洪荒 - 世界`，自动探测）；
2. **配置白名单**（新配置项，见 3.4）。

### 3.2 路径语义：`~/` 前缀 = 项目根

对**读操作**（`读文件`/`列目录`/`按名找文件`/`搜索内容`）引入路径约定：

| 路径形态 | 含义 |
|---|---|
| 普通相对路径（如 `src/lib.rs`） | 相对**工作区**（与现状完全一致，零破坏） |
| `~/` 开头（如 `~/鸿蒙/…`） | 相对**项目根**（新能力） |
| 绝对路径 | 仅当落在「只读根集合」内才允许读，否则拒绝 |

`..` 规则：相对工作区时仍拒绝（不变）；相对项目根时，允许 `..` 但**最终规范化路径必须仍落在「只读根集合」内**，否则拒绝（防止经 `~/../..` 逃逸到盘上任意位置）。

**写操作**（`写文件`/`精确编辑`/`删除文件`）：**不识别 `~/`，不接受绝对路径，不接受 `..`**——行为与现状**完全一致**。`~/` 开头直接返回「越界」错误。

### 3.3 命令：cwd 分级 + 只读白名单

命令仍走单一 `运行命令` 工具，但按**前缀**切换 cwd 与白名单：

| 命令前缀 | cwd | 允许的命令白名单 |
|---|---|---|
| 无前缀 | 工作区 | 现有白名单（cargo/rustc/rustup/dir/type/echo/cd/where/findstr/set/cls/chcp/ping） |
| `~ ` 开头（`~` 后跟空格再跟命令） | 项目根 | **只读白名单**（见下表） |

**只读白名单**（项目根 cwd 下仅允许这些，杜绝经命令写本体）：

| 命令 | 允许的子命令/形态 | 说明 |
|---|---|---|
| `dir` / `type` / `findstr` / `where` / `echo` / `cls` / `chcp` / `ping` | 全部 | 纯只读或进程内 |
| `cd` | 仅限在项目根与只读根之间切换，**禁止绝对路径写出只读根** | 防 `cd /d C:\` 逃逸 |
| `cargo` | **仅** `metadata` / `--version` / `--list` / `tree` | 禁止 `build/test/run/add/install/…`（会写 target 或改项目） |
| `rustc` / `rustup` / `set` | **项目根 cwd 下禁止** | rustc 写产物、rustup 可能下载、set 改环境，均非只读 |

> 设计要点：**「测试由外部做」** 是本设计的前提。智能体在项目根**不**被允许 `cargo build/test`——它只负责「读 + 理解 + 在工作区产出」，验证与搬移在外部。这从机制上杜绝了「自己改本体 + 自己跑测试宣布通过」的自证闭环。

### 3.4 配置新增项

[default.toml](../../鸿蒙/基础能力-域/配置管理-府/配置加载-殿/默认配置-阁/默认-配置-园/default.toml) 新增：

```toml
# 智能体只读探索根：项目根自动加入，此列表为额外的可读子目录白名单（绝对路径）
only_read_roots = []
```

默认空 → 只有项目根可读（工作区之外的读仅限项目根，最保守）。

## 四、安全不变式（必须逐条守住）

1. **写永不出工作区**：无论读怎么放开，`写文件`/`精确编辑`/`删除文件` 的路径解析逻辑**一行不改**。
2. **读不出只读根集合**：任何读路径（含 `~/`、绝对路径、`..`）规范化后必须落在「工作区 ∪ 只读根集合」内。
3. **项目根命令不可写**：`~ ` 前缀命令仅命中只读白名单；任何写倾向命令（cargo build/test、rustc、rustup、set）在项目根 cwd 下被拒。
4. **越界即报错留痕**：所有被拒路径/命令返回明确错误文案（含被拒原因），供会话事件留痕，不静默吞掉。

|---|---|---|
| 1 | 执行器读写分离 + `只读根` + `~/` 路径 + 单元测试 | 低（写逻辑不动，读增量） |

| 4 | 真机验证：发布一个「读本体 → 工作区产出」任务，外部测试后搬移/删除 | 需后端重启 |

## 八、风险与回滚

- **读越界**：不产生写入，风险低；唯一风险是「读了不该读的」（如 `.env` 密钥）——但 `.env` 在项目根内，放开读后智能体可读到。**需评估是否把 `.env`、密钥文件列入读黑名单**（本条待用户定，见下）。
- **命令只读白名单误拦**：可能拦掉合法探索命令，通过单元测试回归收敛。
- **回滚**：`只读根` 默认空 → 空配置即回到「全锁工作区」现状，一键回退。

### 待决（需用户拍板）
1. **`.env` 与密钥文件**是否对智能体隐藏（读黑名单）？建议：是——`只读根` 之外，额外维护「读黑名单」：`.env`、含密钥的配置、`.git` 内部对象。放行读会泄密钥。
2. **白名单子目录**具体是哪些（`only_read_roots` 的值）？当前可先留空，仅项目根。
