# 项目骨架与鸿蒙基础设施 落地设计

> **定位**：第一个落地模块的实现设计。目标是跑通一个"能编译、能运行、能验证"的最小闭环，证明九根六层容灾结构与府可插拔机制能真实落地。
>
> **状态**：v1.5 · 2026-09-04（已实现并验收通过 8/8；serde 默认值改手写 impl Default、中文路径验证无风险）
>
> **上游契约**：`传承殿/已定契约-域/已定契约.md`（实现必须遵守）
>
> **组织规则**：`rules/代码组织规则.md`（单文件/单函数规模上限、模块.rs 汇总、证道只测府级）

---

## 0. 设计目标

创建九根目录骨架 + Cargo workspace + 鸿蒙三域（基础契约/基础能力/系统装配）下的 5 个府 + 证道 1 个测试府，跑通最小闭环。

验证点：
1. 九根物理目录存在，代码只落在园（无 `src`），鸿蒙下域 ≤ 3
2. 府是独立 crate，通过 trait 契约解耦
3. 依赖单向、无环
4. 每个 crate 以府级 `模块.rs` 为根，`#[path]` 层层汇总上报（园→阁→殿→府）
5. 测试全部落在证道测试府，只测府级公共 API
6. 一个 `cargo run` 能启动并输出日志

## 4. 模块汇总上报机制（本轮核心）

每个 crate 的**根是府级 `模块.rs`**（`[lib] path` / `[[bin]] path` 指向它），不再指向园内代码文件。代码仍落在园，但经 `模块.rs` 层层汇总对外暴露：

```
府/模块.rs        → #[path] 引入殿/模块.rs，pub use 上报
殿/模块.rs        → #[path] 引入阁/模块.rs，pub use 上报
阁/模块.rs        → #[path] 引入园/模块.rs，pub use 上报
园/模块.rs        → mod 引入园内实现文件，pub use 上报
园/实现文件.rs     → 真正实现
```

**关键规则**：
1. 每层目录（含代码者）有一个 `模块.rs`，收集本层子项并 `pub use` 上报。
2. **目录名含连字符**（如 `错误类型-殿`）不是合法 Rust 标识符，无法直接 `mod`，因此用 `#[path = "殿名/模块.rs"] mod 标识符;`，**标识符 = 目录名去连字符转下划线**（`错误类型-殿` → `错误类型_殿`）。
3. **园内实现文件**用中文名（如 `错误数据.rs`，无连字符），`mod 错误数据;` 直接声明（Rust 支持 Unicode 标识符）。
4. 纯配置/数据园（如 `默认-配置-园`，只有 `default.toml`）**不建模块.rs**——模块.rs 只服务含代码的目录。
5. 府级 `模块.rs` 是对外公共 API 的唯一出口；证道只测这里导出的公共 API，不触碰内部殿/阁/园。

### 4.1 范式示例（hm-error 全 5 层）

府级 `模块.rs`（crate 根）：
```rust
#[path = "错误类型-殿/模块.rs"]
mod 错误类型_殿;

pub use 错误类型_殿::*;
```

殿级 `错误类型-殿/模块.rs`：
```rust
#[path = "错误枚举-阁/模块.rs"]
mod 错误枚举_阁;

pub use 错误枚举_阁::*;
```

阁级 `错误枚举-阁/模块.rs`：
```rust
#[path = "错误-数据-园/模块.rs"]
mod 错误_数据_园;

pub use 错误_数据_园::*;
```

园级 `错误-数据-园/模块.rs`：
```rust
mod 错误数据;

pub use 错误数据::*;
```

园内 `错误数据.rs`：
```rust
use thiserror::Error;

#[derive(Debug, Error)]
pub enum Error {
    #[error("配置错误: {0}")]
    Config(String),
    #[error("日志错误: {0}")]
    Log(String),
    #[error("IO 错误: {0}")]
    Io(#[from] std::io::Error),
    #[error("未知错误: {0}")]
    Other(String),
}

pub type Result<T> = std::result::Result<T, Error>;
```

> 其余 crate 的 `模块.rs` 照此范式，仅替换 `#[path]` 与标识符（见第 6 节）。

## 6. crate 设计

### 6.1 hm-error（基础契约-域/错误定义-府）

统一错误类型，全项目错误根基。用 thiserror。模块.rs 结构见 4.1 范式，园内 `错误数据.rs` 见 4.1。

依赖：`thiserror`。

### 6.2 hm-contract（基础契约-域/核心契约-府）

府间解耦的根基 trait。本轮只定义契约，不做运行期注入。

模块.rs 链（路径替换）：府 `模块.rs` → `契约定义-殿/模块.rs`（`契约定义_殿`）→ `组件接口-阁/模块.rs`（`组件接口_阁`）→ `契约-接口-园/模块.rs`（`契约_接口_园`）→ `mod 契约接口;`

园内 `契约接口.rs`：
```rust
use hm_error::Result;

/// 所有可插拔组件的基础标识
pub trait Component: Send + Sync {
    fn name(&self) -> &'static str;
}

/// 可初始化的组件：生产/测试路径都通过它接入
pub trait Initializable: Component {
    fn init(&self) -> Result<()>;
}

/// 可关闭的组件：保证资源释放
pub trait Shutdown: Component {
    fn shutdown(&self);
}
```

依赖：`hm-error`。

### 6.3 hm-config（基础能力-域/配置管理-府）

用 serde + toml 加载配置，字段提供默认值（缺配置也能启动）。

模块.rs 链：府 `模块.rs` → `配置加载-殿/模块.rs`（`配置加载_殿`）→ `加载解析-阁/模块.rs`（`加载解析_阁`）→ `配置-模块-园/模块.rs`（`配置_模块_园`）→ `mod 配置模块;`

> `默认配置-阁/默认-配置-园/default.toml` 是纯配置，**不进模块树**，由 `include_str!` 直接嵌入。

园内 `配置模块.rs`：
```rust
use serde::Deserialize;
use hm_error::{Error, Result};

#[derive(Debug, Clone, Deserialize, Default)]
pub struct Config {
    #[serde(default)]
    pub app: AppConfig,
    #[serde(default)]
    pub log: LogConfig,
}

#[derive(Debug, Clone, Deserialize)]
pub struct AppConfig {
    #[serde(default = "default_name")]
    pub name: String,
    #[serde(default = "default_version")]
    pub version: String,
}

#[derive(Debug, Clone, Deserialize)]
pub struct LogConfig {
    #[serde(default = "default_level")]
    pub level: String,
}

fn default_name() -> String { "洪荒·世界".into() }
fn default_version() -> String { "0.1.0".into() }
fn default_level() -> String { "info".into() }

// 字段用 #[serde(default = "函数")] 时不可再 #[derive(Default)]，
// derive 默认值为空串会与 serde 默认函数冲突，故手写 impl Default 复用同一函数。
impl Default for AppConfig {
    fn default() -> Self {
        AppConfig { name: default_name(), version: default_version() }
    }
}

impl Default for LogConfig {
    fn default() -> Self {
        LogConfig { level: default_level() }
    }
}

// 编译时嵌入默认配置，不依赖运行时工作目录（cwd）
const DEFAULT_TOML: &str = include_str!("../../默认配置-阁/默认-配置-园/default.toml");

/// 默认配置（编译时嵌入，任何 cwd 下均可用）
pub fn default_config() -> Config {
    toml::from_str(DEFAULT_TOML).unwrap_or_default()
}

/// 运行时加载外部配置文件（path 为绝对路径或相对调用方 cwd 的路径）
pub fn load(path: &str) -> Result<Config> {
    let content = std::fs::read_to_string(path)
        .map_err(|e| Error::Config(format!("读取配置 {path} 失败: {e}")))?;
    toml::from_str(&content)
        .map_err(|e| Error::Config(format!("解析配置失败: {e}")))
}
```

> 注意：`include_str!` 路径是相对 `配置模块.rs` 所在目录（`配置-模块-园/`），`../../` 回到 `配置加载-殿/`，再进 `默认配置-阁/默认-配置-园/default.toml`。

依赖：`hm-error`、`serde`、`toml`。

### 6.4 hm-log（基础能力-域/日志管理-府）

用 tracing + tracing-subscriber 初始化结构化日志。**实现 `Component`/`Initializable` 契约，验证府可插拔**。

模块.rs 链：府 `模块.rs` → `日志记录-殿/模块.rs`（`日志记录_殿`）→ `记录输出-阁/模块.rs`（`记录输出_阁`）→ `日志-模块-园/模块.rs`（`日志_模块_园`）→ `mod 日志模块;`

园内 `日志模块.rs`：
```rust
use hm_contract::{Component, Initializable};
use hm_config::LogConfig;
use hm_error::{Error, Result};

/// 日志组件：持有日志等级，实现府间契约
pub struct Logger {
    level: String,
}

impl Logger {
    pub fn new(config: &LogConfig) -> Self {
        Logger { level: config.level.clone() }
    }
}

impl Component for Logger {
    fn name(&self) -> &'static str { "日志系统" }
}

impl Initializable for Logger {
    fn init(&self) -> Result<()> {
        use tracing_subscriber::{fmt, EnvFilter};
        let filter = EnvFilter::try_new(&self.level)
            .map_err(|e| Error::Log(e.to_string()))?;
        fmt().with_env_filter(filter)
            .try_init()
            .map_err(|e| Error::Log(e.to_string()))?;
        Ok(())
    }
}
```

依赖：`hm-config`、`hm-contract`、`hm-error`、`tracing`、`tracing-subscriber`。

### 6.5 hm-bootstrap（系统装配-域/启动入口-府）

bin crate，装配所有府，跑通闭环。**main 是薄入口，装配逻辑落园**（遵守代码落园铁律）。

模块.rs 链：府 `模块.rs` → `装配流程-殿/模块.rs`（`装配流程_殿`）→ `流程入口-阁/模块.rs`（`流程入口_阁`）→ `启动-模块-园/模块.rs`（`启动_模块_园`）→ `mod 启动模块;`

府级 `模块.rs`（bin 入口，含 `fn main`）：
```rust
#[path = "装配流程-殿/模块.rs"]
mod 装配流程_殿;

use 装配流程_殿::*;

fn main() -> hm_error::Result<()> {
    启动()
}
```

园内 `启动模块.rs`：
```rust
use hm_contract::Initializable;

pub fn 启动() -> hm_error::Result<()> {
    let config = hm_config::default_config();
    let logger = hm_log::Logger::new(&config.log);
    // 通过契约 trait 对象调用，验证府可插拔
    let init: &dyn Initializable = &logger;
    init.init()?;
    tracing::info!("{} v{} 启动成功", config.app.name, config.app.version);
    Ok(())
}
```

依赖：`hm-config`、`hm-log`、`hm-contract`、`hm-error`、`tracing`。

### 6.7 zd-config-test（证道/基础验证-域/配置测试-府）

证道测试府，**只测 hm-config 的府级公共 API**（`Config`、`default_config`、`toml::from_str` 反序列化），不触碰 hm-config 内部殿/阁/园。

模块.rs 链：府 `模块.rs` → `配置校验-殿/模块.rs`（`配置校验_殿`）→ `配置测试-阁/模块.rs`（`配置测试_阁`）→ `配置-测试-园/模块.rs`（`配置_测试_园`）→ `mod 配置测试;`

园内 `配置测试.rs`：
```rust
use hm_config::Config;

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn 解析合法配置() {
        let s = "[app]\nname = \"测试\"\nversion = \"0.0.1\"\n[log]\nlevel = \"debug\"\n";
        let cfg: Config = toml::from_str(s).unwrap();
        assert_eq!(cfg.app.name, "测试");
        assert_eq!(cfg.log.level, "debug");
    }

    #[test]
    fn 缺字段用默认值() {
        let cfg: Config = toml::from_str("").unwrap();
        assert_eq!(cfg.app.name, "洪荒·世界");
        assert_eq!(cfg.log.level, "info");
    }

    #[test]
    fn 默认配置可解析() {
        let cfg = hm_config::default_config();
        assert_eq!(cfg.app.name, "洪荒·世界");
        assert_eq!(cfg.log.level, "info");
    }
}
```

依赖：`hm-config`、`toml`。

## 7. 依赖关系（单向、无环）

```
hm-bootstrap ──> hm-log ──> hm-config ──> hm-error
      │            │           │
      │            └──> hm-contract ──> hm-error
      └──> hm-contract

zd-config-test ──> hm-config ──> hm-error
```

方向：错误最底层，契约次之，配置在上，日志（依赖配置+契约）居中，启动装配最上，证道测试在最外沿。依赖仍为单向 DAG、无环。

## 8. 各 crate 的 Cargo.toml 要点

成员 crate 用 `workspace = true` 继承版本，path 依赖用相对路径（相对各 crate 的 Cargo.toml 位置）。**`[lib] path` / `[[bin]] path` 均指向府级 `模块.rs`**（与 Cargo.toml 同级），不再指向园内文件。

| crate | path 依赖 | 入口 |
|-------|----------|------|
| hm-error | — | `[lib] path = "模块.rs"` |
| hm-contract | `hm-error = { path = "../错误定义-府" }` | `[lib] path = "模块.rs"` |
| hm-config | `hm-error = { path = "../../基础契约-域/错误定义-府" }` | `[lib] path = "模块.rs"` |
| hm-log | `hm-config = { path = "../配置管理-府" }`、`hm-contract = { path = "../../基础契约-域/核心契约-府" }`、`hm-error = { path = "../../基础契约-域/错误定义-府" }` | `[lib] path = "模块.rs"` |
| hm-bootstrap | `hm-config = { path = "../../基础能力-域/配置管理-府" }`、`hm-log = { path = "../../基础能力-域/日志管理-府" }`、`hm-contract = { path = "../../基础契约-域/核心契约-府" }`、`hm-error = { path = "../../基础契约-域/错误定义-府" }` | `[[bin]] name = "hm-bootstrap"`、`[[bin]] path = "模块.rs"` |
| zd-config-test | `hm-config = { path = "../../../鸿蒙/基础能力-域/配置管理-府" }` | `[lib] path = "模块.rs"` |

> 实现时以各 crate 实际相对路径为准，本表 path 为从各 crate 的 Cargo.toml 所在目录出发的示意。
>
> 注意：指定 `[lib] path` 后 Cargo 不再自动探测 `src/`，整个项目不出现 `src` 目录。
