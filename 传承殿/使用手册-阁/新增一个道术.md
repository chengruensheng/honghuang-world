# 新增一个道术（工具）

在「道术施展-府」的工具流水线中注册一个新工具，供模型调用。

## 落点

| 层 | 路径 |
|----|------|
| 府 | `鸿蒙/基础设施 - 域/道术施展-府` |
| 殿 | `任务-调度-殿` |
| 阁 | `任务-派遣-阁` |
| 园 | `工具-循环-园` |

关键文件：
- `工具定义.rs` — 工具声明（名字、描述、参数 schema）
- `工具执行.rs` — 四段流水线（护栏 → 守卫 → 执行 → 后执行）
- `手脚-施展-殿/` — 实际执行函数所在

## 步骤

### 1. 声明工具定义

在 `工具定义.rs` 的 `全部工具定义()` 返回向量中追加：

```rust
工具定义 {
    名字: "查格位".to_string(),
    描述: "查询某个格位的历史记录。路径相对工作区根。".to_string(),
    参数: serde_json::json!({
        "type": "object",
        "properties": {
            "格位": {"type": "string", "description": "格位名称"},
            "深度": {"type": "integer", "description": "回溯层数"}
        },
        "required": ["格位"]
    }),
}
```

### 2. 实现执行函数

在 `手脚-施展-殿/` 对应阁/园下编写实际逻辑：

```rust
pub fn 查格位(格位: &str, 深度: Option<i64>) -> Result<String, String> {
    // 业务逻辑
    Ok(format!("格位 {格位} 最近 {深度:?} 层记录…"))
}
```

### 3. 接入执行器

在 `工具执行.rs` 的 `执行器()` 函数 match 中追加分支：

```rust
"查格位" => {
    let 格位 = 参数["格位"].as_str().ok_or("缺格位")?;
    let 深度 = 参数.get("深度").and_then(|v| v.as_i64());
    查格位(格位, 深度)
}
```

### 4. 如需护栏，在 `工具护栏()` 中追加规则

```rust
"查格位" => {
    // 例：格位名不得含路径分隔符
    if 格位.contains('/') || 格位.contains('\\') {
        return Err("格位名不得含路径分隔符".into());
    }
}
```

## 约束

- 工具名用中文，与 `工具定义.名字` 一致
- 参数 schema 用 OpenAI 兼容格式（`type`/`properties`/`required`）
- 执行函数返回 `Result<String, String>`（当前统一；未来迁 `世界结果`）
- 落盘类工具须经 `校验落盘` + `校验路径范围` 两道护栏
- 新工具须在 `证道/鸿蒙 - 域/单元测试-府/道术施展-验证-殿/` 下补测试
