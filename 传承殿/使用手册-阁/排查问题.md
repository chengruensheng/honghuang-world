# 排查问题

排查问题的流程与原则。

## 原则

**先看实际产出内容，再看代码定义。**（AGENTS 第 7 条）

排查时先看完整字段、完整提示词、落盘记录原文、中间产物，而非代码定义、文件位置或摘要概括。看到真实内容再下结论。

## 流程

### 1. 复现并看实际产出

```bash
# 跑相关测试，看失败信息
cargo test -p <府名> --lib -- --nocapture

# 看落盘记录（非摘要）
Get-Content .上下文/某记录.jsonl -Tail 20
```

### 2. 定位根因

从实际产出中定位：
- 完整错误信息（不是摘要）
- 完整提示词（看模型实际收到什么）
- 落盘记录原文（看中间产物真实内容）

### 3. 修复并验证

```bash
cargo test --workspace --lib           # 全测试
cargo clippy --workspace -- -D warnings  # 零警告
cargo fmt --all -- --check             # 格式
```

## 常见问题

### 测试超时

根因可能是测试在沙箱里运行 `cargo test`，cargo 向上找 workspace 根 → 递归触发自身。改为 `cargo --version` 等轻量命令。

### 沙箱拒绝

工作区根设为当前 crate 而非临时目录。检查 `WORLD_WORKSPACE_ROOT` 环境变量是否被正确设置。

### 并行竞态

多个测试改同一环境变量。须经 `隔离-互斥-园` 的 `临时工作区` 取共享锁串行化。

### 格式字符串变量名

Rust 2021 格式字符串捕获变量用变量名。`{result:?}` 要求变量名是 `result`，若变量名是中文 `结果` 则须写 `{结果:?}`。

## 事故复盘

重大问题须在 `传承殿/落稿留痕-阁/事故复盘-府/` 下写 postmortem，格式见 `模板.md`。
