# 新增一个验证园（测试）

在六层结构中新增测试，遵循「证道/鸿蒙 - 域/单元测试-府」的镜像组织。

## 落点

测试镜像被测府的殿/阁/园结构：

```
证道/鸿蒙 - 域/单元测试-府/
  └─ <被测府>-验证-殿/
       └─ <子领域>-验证-阁/
            └─ <场景>-验证-园/
                 └─ <场景>测试.rs
```

例：`道术施展-验证-殿/手脚-验证-阁/原子-写入-园/写入文件测试.rs` 对应被测 `道术施展-府/手脚-施展-殿/文件-读写-阁/原子-写入-园/写入文件.rs`。

## 步骤

### 1. 建测试文件

在对应验证园下建 `<场景>测试.rs`：

```rust
//! 原子写入验证：覆盖沙箱拒绝/接受/可读回三类 invariant。

#[cfg(test)]
mod 测试 {
    use crate::道术施展_验证_殿::手脚_验证_阁::隔离_互斥_园::隔离设施::设施::临时工作区;
    use daoshu_fu::写文件;

    #[test]
    fn 写文件后可读回() {
        let (根, _锁) = 临时工作区("写文件", "可读回");
        let 路径 = 根.join("可读回.txt");
        写文件(路径.to_str().unwrap(), "内容").unwrap();
        assert_eq!(std::fs::read_to_string(&路径).unwrap(), "内容");
    }
}
```

### 2. 注册模块

在对应层级的 `模块.rs` 中声明子模块：

```rust
// 阁级模块.rs
#[path = "原子-写入-园/写入文件测试.rs"] pub mod 写入文件测试;
```

### 3. 需要隔离时用共享锁

涉及进程级环境变量（如 `WORLD_WORKSPACE_ROOT`）的测试，须经 `隔离-互斥-园` 取锁：

```rust
let (根, _锁) = 临时工作区("标记", "场景名");
// _锁 生命周期内独占环境变量，其他测试等待
```

`临时工作区` 自动在 `.上下文/.test-tmp/` 下建临时目录并设环境变量。

## 验证

```bash
cargo test -p zhengdao_fu --lib                    # 全验证府测试
cargo test -p zhengdao_fu --lib 写文件后可读回      # 单测
cargo test --workspace --lib                       # 全 workspace
```

## 约束

- 测试只用被测府 lib 根 pub 符号，不深链私有实现
- 测试函数名用中文，描述 invariant（如 `写文件后可读回`）
- 临时目录放 `.上下文/.test-tmp/`（已 gitignore）
- 并行测试改环境变量须经 `隔离-互斥-园` 共享锁
- 严禁 `tests/` 平铺目录（AGENTS 第 10 条）；测试内联在 `#[cfg(test)] mod 测试`
- 已知 broken 测试标 `#[ignore = "原因"]`，不得删除
