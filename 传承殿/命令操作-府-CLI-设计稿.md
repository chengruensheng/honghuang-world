# 命令操作-府 CLI 设计稿

> 定位：**世界的操作台**。CLI 是命令操作-府的第一个产物，AI 用它驱动世界（写命令），人类用它观览世界（只读）。
> 落位：`乾坤 / 呈现-域 / 命令操作-府`（lib = `mingling_fu`，bin = `号令`）。
> 状态：设计稿 v3 · 命名已按审判规范合规（阁园异名 + 园含实现手段词）· 待界主审阅。
> 交付：本设计稿 + 可运行骨架（`临时文件夹/命令操作-府-骨架/`）。三府未落地，骨架以内存模拟数据验证命令流与权限。

## 一、定位

| 项 | 内容 |
|:--|:--|
| 一句话 | CLI = 世界操作台：AI 下令，人类观览 |
| 使用者 | AI（写命令 + `--json` 机器输出）为主；人类（只读命令 + 文本输出） |
| 数据流 | 直连型：CLI 以 lib 依赖调用三府（识海承载-府 / 天庭治理-府 / 道术施展-府），止步各府 lib 根 |

## 二、命令集（域 × 动作）

命令结构：`号令 <域> <动作> [参数] [旗标]`

> 打开即见全流程：`号令`（无参数）→ 全流程总览（人类主视图）；`号令 帮助` → 命令清单。

| 域 | 动作 | 权限 | 对应三府接口 |
|:--|:--|:--|:--|
| 想法 | `投递 <内容>` | AI | 想法池_投递 |
| 想法 | `列表` / `详情 <id>` | 读 | 想法池 |
| 要求 | `化为 <想法id>` | AI | 解析想法→化为要求→入队 |
| 要求 | `列表` / `详情 <id>` | 读 | 要求队列 |
| 设计 | `上呈 <要求id> [-f 文件]` | AI | 设计方案上呈 |
| 设计 | `确认 <要求id> <通过\|打回> [-意见]` | AI | 确认设计 |
| 设计 | `列表` / `详情 <id>` | 读 | 设计方案 |
| 验收 | `裁决 <要求id> <通过\|打回> [-意见]` | AI | 验收裁决 |
| 验收 | `历史` / `详情 <id>` | 读 | 验收历史 |
| 版本 | `存档` | AI | 版本存档 |
| 版本 | `列表` / `详情 <版本号>` / `回退 <版本号>` | 读 / 读 / AI | 版本历史 / 回退 |
| 记忆 | `投影 <角色>` | 读 | 回想-殿检索投影 |
| 记忆 | `回填 <格位> [-f 内容]` | AI | 铭记-殿编码 |
| 世界 | `状态` | 读 | 读世界状态 |
| 队列 | `水位` | 读 | 要求/设计队列水位 |
| 流水 | `列表` | 读 | 会话索引 |
| 流水 | `跟踪 <会话id> [--全文]` | 读 | 会话完整过程 |
| 流水 | `跟随 <会话id>` | 读 | 实时跟随（骨架回显快照） |
| 巡世 | `扫描` / `报告` | AI / 读 | 巡世发现（乙阶段占位） |
| 帮助 | `帮助` | 读 | 命令清单 |

旗标：`--json`（JSON 输出）· `-t/--令牌 <值>` · `-f/--文件 <值>` · `-意见 <文本>` · `--全文`

## 三、权限分级（人类只读）

- **读命令**（列表/详情/历史/状态/水位/投影/跟踪/跟随/报告/帮助）：无门槛，人机皆可。
- **写命令**（投递/化为/上呈/确认/裁决/存档/回退/回填/扫描）：**AI 专用**。
- 令牌校验：写命令须携带 AI 令牌（环境变量 `WORLD_AI_TOKEN` 或 `-t <令牌>`），缺失即拒绝并提示「写命令仅 AI 可执行」。
- 人类只读落地 = 人类不持有 AI 令牌，天然只能执行读命令。

## 四、流水视图（人类核心视图）

人类用它看**全过程**，不是看当前阶段数字。入口：`号令` 默认显示**全流程总览**（管道各段在途数 + 在途要求 + 最近事件流），再下钻单会话：

```
全流程总览
管道：想法池[2] → 要求队列[1] → 设计中[1] → 待确认[0] → 已确认[1] → … → 已验收[1] → 版本[1]
在途要求：
  要求-1747...02 朝堂六层流水视图 · 设计中
最近事件：
  [10:00:16] 鸿钧 进度：状态推进 → 已验收
  [10:00:15] 红云 验收：通过（六维无缺陷）
```

单会话跟踪：

```
会话 会话-要求-1747...  ·  要求-1747...（功能：配置管理-府骨架）
├─ 10:00:01 [鸿钧] 想法接收 → 化为要求书
│   模型回复：已将想法化为要求，验收标准=可读写密钥……
├─ 10:00:05 [女娲] 设计落笔 → 设计方案上呈
│   工具调用：搜索代码库「配置管理」→ 返回 3 个文件
│   模型回复：拆解为 2 项：①密钥-加载-园 ②配置-读写-殿……
├─ 10:00:08 [鸿钧] 设计确认 → 通过
├─ 10:00:12 [多宝] 实现 → 产物：密钥加载.rs（2.4KB）+ 自证通过
│   工具调用：写入 密钥加载.rs → 返回 ok
│   工具调用：运行 cargo test → 返回 12 passed
└─ 10:00:15 [红云] 验收审验 → 通过
    状态推进：待领→设计中→待确认→已确认→待实现→实现中→已验收
```

- `流水 跟踪 <会话id>` 输出上述时间轴；`--全文` 展开原始全文。
- `流水 跟随`（不带id）实时跟随全流程新事件；`流水 跟随 <会话id>` 实时追加单会话事件（骨架回显快照，生产实现持续监听）。

## 五、返回摘要（模型回复 / 工具链返回）

- 过程事件的「模型回复」「工具调用」「工具返回」默认只记**一行简短摘要**，原始全文另存、默认不展示。
- `--全文` 才展开原始输出，避免流水被噪音淹没。
- 摘要生成：v1 甲阶段**机械摘要**（截前 N 字 + 关键行）；乙阶段**LLM 语义摘要**（走鸿蒙模型连接园，符合「代码记事实、LLM 补语义」）。
- 防幻觉：摘要与原文同存一条记录，摘要必带证据指向（哪次调用、哪个文件），来源可信度 代码 > 人类 > LLM。

## 七、命令操作-府工程结构（六层）

```
乾坤/呈现-域/命令操作-府/
├── Cargo.toml                    # lib=mingling_fu + bin=号令
├── 入口.rs                       # lib 根：pub mod 各殿 + pub use 透出
├── 命令-解析-殿/
│   ├── 命令-入口-阁/兜底-入口-园/   # bin 入口（号令.rs 极薄转发）+ 入口执行（解析→校验→分发→输出）
│   ├── 命令-分发-阁/兜底-分发-园/   # 命令清单 + 分发调用（兜底提示未知命令）
│   └── 参数-解析-阁/流式-解析-园/   # argv → 调用（域/动作/参数/旗标）
├── 权限-校验-殿/
│   └── 令牌-校验-阁/原子-校验-园/   # 写命令须 AI 令牌
├── 观览-查询-殿/                  # 读命令（人类只读）
│   ├── 世界-观览-阁/缓存-读取-园/   # 世界状态/队列水位/版本历史
│   ├── 事项-查询-阁/并行-检索-园/   # 想法/要求/设计/验收 列表与详情
│   ├── 记忆-回想-阁/增量-投影-园/   # 记忆投影
│   └── 流水-观览-阁/流式-回放-园/   # 全程跟踪/跟随/列表
├── 号令-下达-殿/                  # 写命令（AI 专用）
│   ├── 想法-投递-阁/原子-入池-园/   # 想法入池
│   ├── 要求-提审-阁/并行-提审-园/   # 想法化为要求
│   ├── 设计-审定-阁/分块-审定-园/   # 上呈/确认设计
│   ├── 验收-裁决-阁/批量-审验-园/   # 六准圣审验
│   ├── 版本-定档-阁/增量-快照-园/   # 存档/回退
│   ├── 记忆-回填-阁/增量-写入-园/   # 编码回填
│   └── 巡世-执行-阁/批量-扫描-园/   # 巡世（乙阶段占位）
└── 输出-呈现-殿/
    ├── 文本-输出-阁/分块-呈现-园/   # 人类可读
    └── 序列-输出-阁/原子-序列化-园/ # --json（原名 JSON-输出-阁，按禁中英混用规范改名）
```

每层只放 `模块.rs` 桥接（`pub mod` + `pub use`），实现只在园；目录名连字符、模块名下划线，`#[path]` 桥接。跨殿经共同上级 `模块.rs` 透出，不深链。

## 八、数据源（流水视图依赖识海承载-府）

- 识海承载-府「铭记-殿」编码时**新增过程事件记录**：模型回复 / 工具调用与返回 / 进度推进 / 产物生成，逐条落盘、不截断，对应心智模型「调用」「事件」格位 + 会话记录。
- 流水视图经「回想-殿」按会话查询；`--全文` 取原始全文。
- 骨架阶段无三府，以内存模拟数据代替，验证命令流与展示形态。

## 九、日志框架结论（两层拆分）

| 层 | 是什么 | 承载 | 框架 |
|:--|:--|:--|:--|
| 业务流水 | 模型回复/工具返回/进度——语义事件流 | 识海承载-府（结构化 JSON，可查询可回放） | **不需要日志框架**，是领域数据 |
| 技术日志 | 三府代码运行时诊断（进出/错误/耗时/线程） | 控制台/文件 | **需要**：推荐 `tracing`（结构化 + 异步友好）；v1 可先用 `log`+`env_logger` |

- 业务流水 = 领域能力，留识海承载-府；技术日志 = 通用能力（层级结构 §五 明确「日志」归鸿蒙），封装为鸿蒙的园（如 `日志-写入-园`），三府经 lib 根调用。
- 两者互不替代：技术日志帮排障，业务流水帮观览。
