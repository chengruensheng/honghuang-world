# 前端门面技术选型调研文档

> **定位**：为「洪荒·世界」未来对外「门面」（展示层前端）做技术选型。本文档是调研结论，供确认后落地。
>
> **状态**：v0.1 · 2026-09-05（调研草案，待确认）

---

## 一、目标与定位

### 1.1 前端是什么

前端是项目的**对外门面**——把五行引擎（任务/迭代/记忆/规则/事件）、三态认知底座（图谱/格位/临时）、自主开发智能体的运行状态，用可视化界面呈现给人看、供人交互。

### 1.2 关键需求（用户已拍板）

1. **先做 Web 前端**，后续**打包成桌面应用**。
2. **前端代码在打包桌面时不能改**（一套前端代码，Web/桌面通用）。

### 1.3 落点

按既有架构蓝图，前端落**乾坤根（土·空间层）**——「空间、承载、稳定、展示」的展示代码归乾坤。前端不承载业务逻辑，只是「呈现」。

## 二、桌面壳框架选型

核心结论：**选 Tauri 2.0**。对比：

| 维度 | Tauri 2.0 | Electron |
|------|-----------|----------|
| 后端语言 | Rust | Node.js |
| 与本项目契合 | ✅ 项目全 Rust workspace，天然一体 | ❌ 引入 Node 技术栈 |
| 前端 | 任意 Web 框架（编译为 HTML/JS/CSS） | 任意 Web 框架 |
| 包体积 | 最小 600KB（用系统 WebView） | ~100MB+（捆绑 Chromium） |
| 内存占用 | 低 | 高 |
| 安全 | Rust 内存/线程/类型安全 + 安全审计 | 需自行加固 |
| 前端改代码 | 打包桌面时前端零改动 | 打包桌面时前端零改动 |

**结论**：Tauri 2.0 是唯一既贴合本项目 Rust 生态、又满足「前端不改代码打包桌面」的方案。Electron 因引入 Node 栈、体积大、内存高，与本项目理念相悖。

---

## 三、前端框架选型

Tauri 前端无关，支持任意框架。对比：

| 维度 | Vue 3 + Vite | React | Svelte | 原生 HTML+JS |
|------|-------------|-------|--------|-------------|
| 学习成本 | 低（模板直观） | 中（JSX/Hooks） | 低 | 无 |
| 中文生态 | ✅ 完善 | 一般 | 较少 | 无 |
| 组件化 | ✅ 单文件组件 | ✅ | ✅ | ❌ 手动 |
| 生态/组件库 | 适中 | 最大 | 较小 | 无 |
| 构建 | Vite（快） | Vite | Vite | 无需 |
| 可视化仪表盘 | 好 | 好 | 中 | 难 |
| Tauri 官方模板 | ✅ 支持 | ✅ | ✅ | ✅ |

**推荐：Vue 3 + Vite**。理由：
1. 中文文档与生态完善（贴合本项目中文语境）。
2. 单文件组件 + 模板语法，适合快速搭「门面」仪表盘。
3. Tauri 官方 `create-tauri-app` 直接提供 Vue 模板。

**图表库**：ECharts（中文生态好，适合图谱依赖关系图、格位仪表盘、日志流可视化）。

## 四、前端与 Rust 后端通信

核心问题：前端如何拿到五行引擎/三态认知的数据？

| 方案 | 机制 | Web 阶段 | 桌面阶段 | 前端是否改代码 |
|------|------|---------|---------|--------------|
| **A. HTTP API（axum）** | Rust 起 HTTP 服务，前端 fetch | 浏览器访问端口 | Tauri 壳内嵌 axum（localhost） | ✅ 完全不改 |
| B. Tauri invoke | 前端 `invoke` 直接调 Rust 函数 | 无 Tauri，需 fallback | 原生 | ❌ 需抽象/分支 |

**推荐：方案 A（HTTP API + axum）**。

理由：前端始终通过 HTTP 拿数据，Web 阶段和桌面阶段共用**同一套前端 + 同一套 API**，前端代码彻底零改动。桌面阶段 Tauri 壳启动时顺带起 axum 服务（localhost），前端 WebView 访问同一地址即可。`invoke` 方案在纯 Web 阶段没有 Tauri 运行时，需要额外抽象层，反而复杂。

---

## 五、推荐方案总览

```
前端门面 = Tauri 2.0（壳，仅桌面阶段） + Vue 3 + Vite + ECharts（界面）
后端数据 = axum HTTP API（Web/桌面通用，暴露五行引擎 + 三态认知数据）

Web 阶段：  浏览器 ──HTTP──▶ axum ──▶ 五行引擎/三态认知
桌面阶段：  Tauri 壳(内嵌 WebView) ──HTTP──▶ axum ──▶ 五行引擎/三态认知
```

前端代码（Vue 组件 + ECharts 图表）在两种形态下**完全一致**，仅在桌面阶段多一个 Rust 壳 + 打包配置。
