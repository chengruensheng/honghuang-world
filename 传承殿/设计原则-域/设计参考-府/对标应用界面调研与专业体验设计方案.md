> **定位**：对标 DSH / Cursor / Claude Code / Windsurf / Devin / Lovable·v0·Bolt 的界面与使用体验调研，提炼「专业 AI 开发工具」的设计共识，并结合洪荒项目特色给出「该展示什么、不该展示什么」的体验设计方案（蓝图，未实现）。

## 一、调研结论：专业 AI 开发工具「展示什么」

### 1.1 六类对标工具的界面形态速览

| 工具 | 界面形态 | 核心展示内容 | 关键交互 | 一句点评 |
|------|----------|--------------|----------|----------|
| **Devin** | 网页工作台，每任务一个「会话卡片」 | 任务分解步骤清单（Playbook）、每步的终端输出、浏览器截图、编辑器 diff、进度状态 | 会话内「计划→执行→验证」全流程回放，可插话引导 | 把「AI 工程师」的工作**全程录屏式**呈现 |
| **Cursor** | IDE 内嵌面板 + 编辑器内联 | Composer 多文件 diff（红绿逐行）、Plan 模式先出计划不动手、Agent 自主跑、checkpoint 可回退 | diff 逐条「接受/拒绝」、Tab 补全、⌘K 行内改 | diff 审阅是「信任」的基石 |
| **Claude Code** | 终端流式文本 | thinking → tool call → tool result → reply 四类事件**逐条流式吐出** | 终端内回车确认、权限询问、/命令 | 极简但「过程全透明」，无黑盒感 |
| **Windsurf Cascade** | IDE 侧边面板 | Code/Chat 双模式、检查点、实时感知 linter | 检查点回退、自动感知上下文 | 检查点是「敢放手」的前提 |
| **DeepSeek Harness** | 本地 Web UI（一键起） | 插件执行过程、模型思考 + Harness 执行分离 | 模型可换、插件可插拔 | 开箱即用 + 一切皆插件 |
| **Lovable / v0 / Bolt** | 左对话右预览 | 生成过程 + **实时可视化预览** + 代码 + 一键部署 | 描述需求 → 看它一步步搭出来 | 「所见即所得」降低非开发者门槛 |

### 1.2 设计共识（四条铁律）

调研后的共同结论——**专业 AI 开发工具的核心不是「聊天」，而是「让用户看见 AI 在干活，并信任它的产出」**：

1. **过程可见是第一价值**。Claude Code 的四类事件流、Devin 的录屏式回放、Cursor 的 diff、Lovable 的实时预览，本质都是同一件事：把「黑盒 LLM」变成「可观察、可审计、可打断」的过程。**没有过程可见，就没有专业感，只有玩具感。**

2. **diff 逐行审阅是「信任」的基石**。Cursor 的核心交互是「AI 提出 diff → 人逐条接受/拒绝」。人必须能**精确看到改了哪一行、删了什么、加了什么**，才敢让 AI 动真实代码。

3. **计划先行 / 检查点可回退**。Cursor Plan 模式「只动脑不动手」，Devin 的 Playbook 步骤清单、Windsurf 检查点——都在传达：AI 先给计划，人确认后再动手；动手后可回退。**「敢放手」的前提是「能反悔」。**

4. **一个主工作流，而非一堆平铺视图**。成熟工具都把「对话 → 过程 → 产物」串成**一条沉浸式时间线**（Devin 会话卡、Cursor Composer 面板、Lovable 左右分屏），而不是让用户在多个视图间切换找东西。

## 二、洪荒项目特色盘点（差异化资产）

在照搬对方设计前，先明确我们**独有的、对方没有的**东西——这些才是「专业」与「山寨」的分水岭：

| 特色 | 说明 | 对标的差异化价值 |
|------|------|------------------|
| **律可机器校验** | 「律」是护栏，可被督察/门禁机器校验（13 条检测门禁） | **DSH/Cursor/Claude Code 全都没有**。这是「专业」的最高形态：不靠自觉，靠机器兜底 |
| **全中文六层架构** | 域→府→殿→阁→园，命名即架构 | 降低单人项目认知负担，中文语义自解释 |
| **五行相生闭环** | 木火土金水五引擎信号闭环（任务→迭代→记忆→规则→事件） | 让「架构即内容」，观测视图有真实数据可看 |
| **五层协作看板** | 圣人设计→大罗金仙实现→准圣验收→道祖终审→太乙金仙清理 | 把「AI 自主流转」角色化、戏剧化，天然适合可视化 |
| **道祖接待** | 主控澄清：闲聊→识别任务→对齐→确认发布 | 一条「意图澄清」闭环，非裸聊天 |
| **认知三态** | 世界态图谱 / 心智态格位 / 过程态上下文 | 有真实的「认知可观测」数据，非空壳 |

**关键判断**：我们的工程底子（过程事件流、diff、会话回放、验收证据、扫尾门禁）**已经接近 DSH**；真正的短板在**体验层——这些能力被「平铺的六视图 + 折叠面板」藏起来了，没有形成一条「专业工具」应有的沉浸式主工作流**。

## 三、设计方案：什么该展示、什么不用

### 3.1 信息架构：从「六视图平铺」到「主工作流 + 观测」两层

**现状问题**：对话、看板、五行、图谱、格位、日志六视图平铺在侧栏，用户「看 AI 干活」要在对话（看过程）和看板（看结果）间来回切换，割裂。

**方案**：把视图分成两层——

- **主工作流（唯一主角）**：一个「对话 + 过程 + 产物」**同屏沉浸式时间线**。左边/上边对话与指令，中间一条**过程时间线**（思考/工具调用/结果/diff/答复，按时间流式滚动），产物（生成的代码 diff、写文件内容、测试结果）**内联**在时间线里，而不是藏在折叠面板。
- **观测视图（按需进入）**：看板、五行、图谱、格位、日志——它们是「架构/认知的剖面」，属于「想看全局/追责时再切」的二层，不该和主工作流抢首屏。

**一句话**：首屏只给「我下达需求 → 看它怎么干 → 看它产出了什么」这一条线；架构剖面降为次要入口。

### 3.2 过程可视化升级（对标 Claude Code / Devin）

**该展示**（核心，缺一不可）：

1. **四类事件**：💭思考 / 🔧工具调用 / ✅工具结果 / 📝任务答复——已具备，但要从「折叠面板里的文字流」升级为「时间线卡片流」。
2. **diff 卡片**：精确编辑（红删绿增）+ 写文件（内容块）——已具备，需强化为「文件路径 + 行号 + 红绿高亮」的完整 diff 卡片，对标 Cursor。
3. **步骤清单（Playbook）**：把五层流转（圣人→大罗金仙→准圣→道祖→太乙金仙）渲染成一条**可勾选的进度清单**，当前阶段高亮、已完成打勾，对标 Devin 的 Playbook。这是「任务推进到哪了」最直观的表达。
4. **状态徽标**：每阶段完成/失败/空闲的彩色徽标，实时轮询刷新。

**不用展示**（克制，避免噪音）：

- 原始 LLM 请求体 / serde 反序列化错误堆栈 / token 消耗明细 / 锁竞争日志——这些是「开发者调试」用的，不是「使用体验」。
- 无意义的「智能体运行中」这类永远在动却无信息的占位动效。

### 3.3 律的可视化（本项目独有的「专业」制高点）

这是 DSH/Cursor 都没有的东西，**必须显性化，否则自废武功**：

- 在产物/交付界面，把「律的校验结果」作为一个**醒目的质量徽标**：`律·门禁 13/13 PASS`，绿/黄/红三态。
- 看板任务卡片、验收弹层里，把「自检 / 验收轮次 / 扫尾证据 / 终审评语」用**状态色块**呈现（已具备雏形，需强化视觉层级）。
- 让用户**一眼看到「这条产出是被机器校验过的」**，而不是「AI 说它做完了」。

### 3.4 视觉语言与交互（对标专业工具质感）

- **密度与层次**：首屏克制，深度信息「按需展开」（点击展开 diff、展开事件详情），而非一次性铺满。
- **等宽字体区隔**：代码/路径/工具名一律 `Consolas/monospace`，与自然语言气泡明确区隔（已部分具备）。
- **红绿语义统一**：绿=新增/通过，红=删除/失败，黄=待处理/警告，水青=清理/就绪——全局统一，不混用。
- **过程时间线**：连续竖线 + 节点圆点（已具备），颜色按事件类型（思考灰/工具紫/结果绿/答复紫），强化「流水感」。

### 3.5 明确「不展示」清单（克制红线）

| 类别 | 不展示 | 原因 |
|------|--------|------|
| 内部细节 | token 数、LLM 原始 JSON、serde 堆栈、锁竞争 | 非用户价值，制造噪音 |
| 刷屏日志 | 每秒「心跳/轮询中」类无信息动效 | 消耗注意力 |
| 过载首屏 | 六视图全铺、面板全展开 | 主次不分 |
| 未完成的空壳 | 无数据的视图给「正在建设中」占位 | 要么有真实数据，要么不出现 |

## 四、分阶段落地建议（蓝图 → 实现）

> 以下为设计蓝图，**未经确认不直接改代码**。按优先级排序：

1. **P0 主工作流合一**：把「对话 + 过程时间线 + 产物内联」合并为一个沉浸式首屏视图（对话视图升级为主工作流），看板/五行等降为次要入口。这是「专业感」的质变点。
2. **P1 步骤清单（Playbook）**：五层流转渲染为可勾选进度条 + 当前阶段高亮，对标 Devin。
3. **P2 律的可视化**：门禁 PASS 徽标 + 验收证据色块层级强化。
4. **P3 视觉精致化**：diff 卡片、红绿语义统一、monospace 区隔、微动效收敛。
