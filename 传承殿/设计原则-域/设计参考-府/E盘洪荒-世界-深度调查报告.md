## 三、哲学基石

### 3.1 四大概念体系

| 概念 | 本义 | 工程解读 | 设计原则 |
|:--|:--|:--|:--|
| **五行** | 金木水火土动态平衡 | 双向反馈循环系统 | 生克并存、动态平衡、五行归位 |
| **九五至尊** | 至高且居中的权威 | 决策中枢定位 | 唯一决策中心、居正不偏、高而不悬 |
| **六道轮回** | 业力驱动的状态循环 | 质量状态流转 | 业力驱动、六道皆可转、人道最宜修行 |
| **四角色** | 决策/设计/执行/验收 | 职责分离与制衡 | 角色不可兼任、单向授权链、反馈闭环 |

**关联框架**：九五至尊定决策之位 → 四角色分行事之责 → 六道轮回判质量之阶 → 五行生克调系统之衡。

### 3.2 5 工程基线（治理哲学核心）

1. **确定性程序是治理操作唯一执行者**——LLM 只生成符号材料，不拥有写入权限
2. **信息洪流是旧仓库失败根因**——人类注意力稀缺，介入点限制在异常
3. **人类只看异常**——所有 LLM 输出需有摘要 + 异常自动上报
4. **可验证性约束**——操作来源可追溯、结果可机械校验、历史不可篡改
5. **治理延伸是减少 LLM 参与**——关键决策确定化

### 3.3 4 禁止条款

1. LLM 不可直改知识包（decided_by 字段强制校验）
2. 不可复现的多 Agent 交互不可作治理决策依据（多 LLM 投票 + 阈值）
3. 治理操作必入事件流（frozen outcome + 哈希链）
4. 人类仅通过异常摘要介入（不看原始日志）

### 3.4 元三治（治理的治理）

- **治病**：核心规则修改需人类确认
- **治益**：4 分类不增不减
- **治强**：核心逻辑不绕过检验

## 五、4 分类角色体系

### 5.1 角色定义

| 分类 | 原语 | 职责 | LLM 池 | 写权限 | 工具偏好 |
|:--|:--|:--|:--|:--|:--|
| 决策者 | 道祖级 | 化要求/派遣/终裁/定档 | 2-3 模型（多 LLM 投票） | 只读 | 读记忆+提问+规划 |
| 设计者 | 圣人级 | 设计/评审 | 3 模型 | 只读 | 读+检索 |
| 验收者 | 准圣级 | 六维验收（4 机械+2 LLM） | 1-2 模型 | 只读 | 读+测试运行 |
| 实现者 | 大罗金仙级 | 实现（按领域分工） | 1 模型 | 可写代码 | 写+编辑+执行 |

### 5.2 流水线

```
决策者 → 设计者 → 实现者 → 验收者 → 决策者（终裁）
            ↑         │          │
            │  重做   │          │
            └─────────┘          │
              验收驳回 ──────────┘
```

- **不可跳层**：决策者不能直接验收
- **不可反序**：实现者不能先于设计者
- **可循环**：验收驳回→实现者重做→复验（≤3 轮，超出升级终裁）
- **13 过程态**：每职责拆"待 X"+"X 中"+3 中间态（已定档/已打回待重做/循环超限升级）

### 5.3 机械判定

4 分类权限通过代码枚举机械判定，**LLM 不能决定自己能不能写**：
- `分类_机械判定()` 校验：任务标识非空、decided_by 非空、分类匹配
- 写权限分层：决策者/设计者/验收者只读，实现者可写代码
- 路径前缀校验：实现者不越领域

### 6.2 模块桥接模式

中文目录通过 `#[path]` 桥接到 Rust 模块：

```rust
#[path = "角色-卡册-殿/模块.rs"]
pub mod 角色_卡册_殿;
pub use 角色_卡册_殿::*;
```

- 目录名：连字符中文（`角色-卡册-殿`）

### 7.3 接力引擎关键铁律

1. **默认真实**：无 key 直接失败并指路 .env，绝不静默降级 mock
2. **上游产出全文透传下游**：不允许中间环节截断/转述
3. **沉默 = 打回**：终裁判定机械判定，含"打回/不通过/❌"或沉默→打回，"通过"必须同时含"通过"与"终裁/✅/放行"

### 7.4 落盘回执五重证据

- 路径（声明原样保留）
- 成功/失败（真实执行回执）
- 字节数（规范化后真实字节）
- 首行预览（最多 40 字符）
- SHA256 哈希（从磁盘读回算得）

安全围栏：只允许工作区根内相对路径；绝对路径/盘符/`..` 一律拒绝。

## 十、核心设计模式与创新

### 10.1 五条世界级工程纪律

1. **无 key 严禁降级 mock**——fail-loud 铁律（退出码 4），mock 仅允许显式 `LLM_BACKEND=mock` 且走临时隔离库
2. **决策带 falsifiable + 时间窗口**——8 必填字段 + 17 项门禁脚本
3. **上游产出全文透传下游**——不截断不转述，避免层层语义漂移
4. **沉默 = 打回**——终裁机械判定，防止 LLM 自我放行
5. **哲学先于代码**——6 层结构 + 命名哲学判据 + 先入稿再落码

### 10.2 命名哲学

- **祖孙三层不同名**：阁名去后缀不能包含园名去后缀
- **同层全局唯一**：全项目 -殿/-阁/-园 各自不重复
- **目录名无英文**：白名单仅 SQLite/P0-P3/LLM
- **不沿用借来的词**：拒绝"乐高"等未推导命名
- **中文标识符**：目录连字符，Rust 模块下划线，`#[path]` 桥接

### 10.3 DSH 对齐

| DSH 概念 | 本项目落地 |
|:--|:--|
| 核心无特权 | 4 分类每分类可替换为新 LLM 池 |
| 插件可组合 | 工具通过 manifest 拼装 |
| 事件可拦截 | Waterfall 事件链（next() 模式） |
| Session 事件 | 事件流 + frozen outcome + 哈希链 |
| Agent 事件 | 4 分类角色卡 + LLM 池 |
| Capability 事件 | 工具 manifest + 权限枚举 |

### 10.4 事件流唯一事件源

引擎不再拥有独立事件类型，所有治理动作统一通过事件流留痕。引擎构造通用 `事件` struct，领域数据填入 `事件.内容`，然后写入事件流。SSE 从 `事件流.读取自(起始ID)` 读取增量事件。
