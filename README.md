# 洪荒 · 世界

> 用洪荒神话世界观建模的、会自己进化的多智能体软件开发系统。
> 界主发布想法，天道与鸿钧主政，圣人设计，大罗金仙与准圣实现、审验——世界自己写代码、自己验收、自己存档、自己进化。

---

## 一、这是什么

洪荒世界不是玩具，也不是普通的代码生成器。它被当作一个「世界」培养：

| 层级 | 角色 | 职责 |
|:--|:--|:--|
| 顶层 | 界主（人·天意） | 发布想法，不干预实现 |
| 天层 | 天道 / 鸿钧 | 巡世发现 / 化要求·派遣·验收·定档 |
| 中层 | 女娲 + 四圣 | 设计 + 评审 |
| 底层 | 大罗金仙 + 准圣 | 实现 + 六维审验 |

一次完整迭代：**想法 → 要求书 → 设计 → 实现 → 验收 → 版本存档**。

世界分两阶段生长：

- **甲阶段（v1 实现期）**：功能优先，关闭自动优化，一切力量集中把第一版做出来。
- **乙阶段（自动优化期）**：v1 存档后永久进入，天道巡世 + 进化环全开，自主进化。

## 二、六层结构

所有代码按「维度 → 域 → 府 → 殿 → 阁 → 园」六层切分，层层递进，**能力只在园落地**：

| 层 | 回答 | 承载 |
|:--|:--|:--|
| 维度 | 世界由什么构成 | 本体范畴 + 工程需求 |
| 域 | 靠什么活着 | 纯目录，无文件 |
| 府 | 什么能力 | 唯一编译单位（lib crate），引用止步点 |
| 殿 | 哪些模块 | `模块.rs` 桥接 |
| 阁 | 什么功能 | `模块.rs` 桥接 |
| 园 | 怎么实现 | 实现代码 + `模块.rs` 桥接 |

三条铁律：

1. **跨府止步 lib 根**：`use {府lib}::符号`，禁深链到殿/阁/园。
2. **跨维经鸿蒙**：维度之间不直调，经鸿蒙事件总线 / 状态共享中转。
3. **单向向下**：维度 → 域 → 府 → 殿 → 阁 → 园，下层永不反向引用上层。

## 四、世界之身与脑（三府）

心智模型（脑）与多智能体架构（身）融合为三个府：

```
                天庭治理-府 (tianting_fu)  组织编排 · 管组织
                      │ 调度执行          │ 读投影/回填
                      ▼                  ▼
                道术施展-府 (daoshu_fu)   识海承载-府 (shihai_fu)
                任务执行 · 管角色执行      脑 · 记忆
                      └───── 读投影 ──────┘
```

| 府 | lib | 定位 | 一句话 |
|:--|:--|:--|:--|
| 识海承载-府 | `shihai_fu` | 世界之脑 | 代码记事实，LLM 补语义，人兜底填根 |
| 天庭治理-府 | `tianting_fu` | 世界之身 | 想法 → 要求 → 设计 → 验收 → 版本 → 进化 |
| 道术施展-府 | `daoshu_fu` | 世界之身 | 每个角色按自己的道术跑 L1-L4 工作流 |

## 七、快速开始

### 构建

```powershell
cargo build
```

构建产物统一落入 `道果树/构建物-域`（由 `.cargo/config.toml` 配置，不污染源码树）。

### 运行操作台

```powershell
cargo run -p mingling_fu --bin 号令
```

### 测试

```powershell
cargo test
```
