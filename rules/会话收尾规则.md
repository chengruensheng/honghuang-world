# 会话收尾规则

## 一、结束前必给推荐
1. 每次任务 / 会话结束，向用户给出五个「最高优先级接下来做什么」的推荐，并明确指出建议的下一步。

## 二、推荐必须全局
1. 每条推荐必须基于当前项目整体全局，回答「整个项目下一步往哪走」，不得是局部 / 琐碎的修补（如清理缓存、微调命名、单文件重构、跑一次自检等收尾性动作）。
2. 避免项目漂移：推荐应服务于项目主线目标（世界观与工程一体两面、五行相生驱动演化），而非零散细节。
3. 优先级排序依据：对项目主线价值的贡献度，而非实现难易或工作量。
4. 推荐前必须先盘点项目当前真实状态（已实现能力 / 未接入生产的差距 / 主线待办），据此给出方向，禁止凭空罗列。
