# 代码质量规则

## 一、错误处理
1. 生产路径业务错误走 `Result`，用 `?` 传播，不吞错。
2. `unwrap()`/`expect()` 仅限锁中毒等不可恢复且已证不 panic 的场景（如 `Mutex::lock().unwrap()`）；其余一律返回错误。

## 二、面向契约编程（可扩展）
1. 装配层只依赖 `Arc<dyn Trait>`（契约），不依赖具体引擎；替换/新增实现不动装配代码。
2. 领域契约用泛型参数承载领域模型，契约府不依赖引擎。
3. 契约最小化：只暴露运行时必需接口；持久化、注入等具体能力留实现。
4. 开闭原则：新增能力走新增 trait/实现，不修改既有契约。

## 三、配置化与不硬编码
1. 魔法值（信号类型、载荷键、事件类型等跨府字符串）收敛为常量模块，杜绝散落字符串字面量。
2. 可配置项走配置（默认值 + 覆盖），不写死；默认配置有兜底。
3. 源码禁绝对路径；相对路径仅限语言/工具机制必需（Cargo path、#[path]、include_str!）。

## 四、可维护与文档
1. 单一职责：一个园一个实现，一个引擎一种能力。
2. 公共 API 用中文语义名，自解释；关键模块有 `///` 文档注释。
3. 变更同步更新文档版本与修订记录。
