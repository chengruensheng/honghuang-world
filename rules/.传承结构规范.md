# .传承结构规范

> **定位**：约定 IDE 接入任一项目时，该项目根下应建立的元数据目录 `.传承/` 的结构与契约——使 IDE 在不同时刻接入不同项目时，认知层接口稳定。
>
> **不解决什么**：本规范只约定 `.传承/` 这一层；项目内部的业务目录（`鸿蒙/`、`乾坤/`、`太初/`、`道果/`）由各项目命名规则与设计文档自行定义。

## 一、设计原则

| 原则 | 含义 |
|------|------|
| **类 `.trae` 模式** | 项目根平级，每个项目独立一份 |
| **介质分流** | 文档型目录用 `.md`/`.html`；代码型目录用 `.ps1`/`.sh`/`.rs` 等 |
| **源态二分** | 源=契约/定义，进 git；状态=运行产物，`.gitignore` |
| **AI 自生长** | 子目录与文件名不固定，由 AI 按项目需要创建（仅门禁动词集强约束） |
| **生命周期入口** | 门禁 = OS 级可调、幂等、退出码明确 |

## 二、`.传承/` 顶层目录树

```
.传承/                                          # 项目级元数据根（类 .trae）
│
├── README.md                                    # 索引：项目身份 + 各子目录契约
│
├── 规则/                                        # 【源】.md，进 git
│   ├── 大道规则/                                #     不可改（项目宪法）
│   ├── 天道规则/                                #     可议（项目法律）
│   └── 临时规则/                                #     任务级，终态清除（不入 git）
│
├── 门禁/                                        # 【源】脚本，进 git
│   ├── 总入口.{ps1,sh}                          #     聚合所有门禁的入口
│   ├── 启动.{ps1,sh}                            #     进程编排
│   ├── 停止.{ps1,sh}
│   ├── 升级.{ps1,sh}                            #     数据迁移
│   ├── 备份.{ps1,sh}
│   ├── 安装.{ps1,sh}                            #     项目安装
│   ├── 初始化.{ps1,sh}
│   └── 校验/                                    #     契约校验（聚合 + 专项）
│       ├── 总校验.{ps1,sh}
│       └── 校验<名>.{ps1,sh}                    #     单一职责
│
├── 图谱/                                        # 【源】.md/.html/.json，进 git
│   ├── 架构图/
│   ├── 数据流/
│   ├── 调用链/
│   └── 知识图谱/
│
├── 设计/                                        # 【源】.md/.html，进 git
│   ├── 落地设计/                                #     *-落地设计.md
│   ├── 设计原则/                                #     设计原则/方法论
│   ├── 已定契约/                                #     已定契约/接口
│   └── 原型/                                    #     *.html（可点击原型）
│
├── 治理/                                        # 【源】.md，进 git
│   ├── 缺陷清单.md
│   ├── 修订记录.md
│   ├── 验收报告/                                #     *-验收报告.md
│   └── 决策记录/                                #     NNNN-标题.md（ADR）
│
├── 格位/                                        # 【源】.json/.md，进 git
│   ├── 36格位.json                              #     格位定义
│   └── 演变/                                    #     格位变化历史
│
└── 记忆/                                        # 【状态】.gitignore
    ├── 棒级/<run-id>/
    ├── 任务级/<task-id>/
    ├── 用户偏好/
    └── 缓存/
```

## 三、子目录契约

| 子目录 | 介质 | git | 命名 | 例 |
|--------|------|-----|------|----|
| `规则/` | `.md` | 进 | frontmatter「层级: 大道/天道」 | `命名-大道.md` |
| `门禁/` | `.ps1`/`.sh`/`.rs`/... | 进 | `<动词>.<ext>`（见第五节） | `启动.ps1` |
| `图谱/` | `.md`/`.html`/`.json` | 进 | 图类 `<主题>-架构图.md/html`；索引类 `<名>.json` + `<名>.md` 摘要 | `完整-架构图.html`；`坐标索引.json` |
| `设计/` | `.md`/`.html` | 进 | `<名>-落地设计.md` | `棒级目标与交接-落地设计.md` |
| `治理/` | `.md` | 进 | `<类型>.md` 或 `NNNN-标题.md` | `缺陷清单.md` |
| `格位/` | `.json`/`.md` | 进 | `36格位.json` | — |
| `记忆/` | 任意 | ignore | `<粒度>/<id>/<文件>` | `棒级/r-20260911-001/黑板.md` |

## 四、`门禁/` 脚本动词清单（强约束）

| 动词 | 语义 | 本项目实证 |
|------|------|------------|
| `启动` | 进程编排-开 | [启动.ps1](../../../启动.ps1) |
| `停止` | 进程编排-关 | — |
| `升级` | 数据迁移-进 | — |
| `备份` | 数据迁移-出 | — |
| `安装` | 项目安装-依赖 | — |
| `初始化` | 项目安装-首次 | — |
| `校验<名>` | 契约校验-专项 | `detect_hardcode.ps1` 等 14 个（本项目历史遗留） |
| `总入口` | 聚合所有门禁 | `detect_all.ps1` |
| `驱动-<模式>` | 进程编排-变体 | `驱动-drain.ps1` |
| `<自定义>` | 项目特化 | `生成目录树.ps1` |

**约束**：
1. 必须从上述动词集选，不得自造
2. 校验专项必须 `校验<名>.ps1`，禁用 `detect_*.ps1`（本项目历史遗留，待迁移）
3. 退出码：`0` = 通过，非零 = 拦截；CI 可直接消费
4. 幂等可重入：反复执行不破坏状态

## 五、`记忆/` 介质契约

```
记忆/
├── 棒级/
│   └── <run-id>/                              # run = 一次完整 AI 执行
│       ├── 黑板.md                            # 棒间交接上下文（永久）
│       └── 摘要.md                            # 棒结束产物
├── 任务级/
│   └── <task-id>/
│       └── 上下文.md                          # 任务内累积
├── 用户偏好/
│   └── *.json                                 # 长期偏好
└── 缓存/
    └── *.json                                 # 临时键值，可丢
```

**`.gitignore` 模板**：
```gitignore
.传承/记忆/**
!.传承/记忆/.gitkeep
```

## 六、与本项目 `传承殿/` 的映射

`.传承/` 是**规范文本**，本项目自己的 `传承殿/` 是**物理实现**——两者关系：

| `.传承/` 子目录 | 本项目对应物理位置 | 关系 |
|-----------------|---------------------|------|
| `规则/` | `rules/` | **强映射**（本项目 `rules/` 就是 `.传承/规则/` 的内容） |
| `门禁/` | `*.ps1`（散落） | **待归集**（20 个 ps1 需迁入 `.传承/门禁/`） |
| `图谱/` | `传承殿/架构全览图.html` + `传承殿/设计原则-域/完整架构蓝图.md` | **待归集** |
| `设计/` | `传承殿/落地设计-域/` + `传承殿/设计原则-域/` + `传承殿/已定契约-域/` | **待归集** |
| `治理/` | `传承殿/缺陷清单.md` + `传承殿/修订记录.md` + `传承殿/*-验收报告.md` | **待归集** |
| `格位/` | （无，未来建） | **待新建** |
| `记忆/` | （无，未来建） | **待新建** |

**两种落地模式**（**由项目自己选**）：

**模式 A：符号链接**（推荐本项目）——`传承殿/` 实际是 `.传承/` 的软链接视图
```
.传承 → 传承殿/
```

**模式 B：物理并存**——`.传承/` 是规范层，`传承殿/` 是物理层，两者一一对应

## 七、`.传承/README.md` 模板（强约束）

```markdown
# <项目名> · .传承

- 项目：<项目名>
- 类型：<类型>
- 启动：`.传承/门禁/启动.<ps1|sh>`
- 校验：`.传承/门禁/总入口.<ps1|sh>`

## 子目录
| 子目录 | 介质 | 作用 |
|--------|------|------|
| 规则/ | .md | 项目级规则 |
| 门禁/ | 脚本 | 生命周期入口 |
| 图谱/ | .md/.html | 架构/数据/调用图 |
| 设计/ | .md/.html | 落地/原则/契约/原型 |

```

## 八、`.传承/` 与其他项目元数据目录的差异

| 对比 | `.trae` | `.git` | `.vscode` | `.传承/` |
|------|---------|--------|-----------|----------|
| 工具来源 | Trae IDE | Git | VS Code | 洪荒·世界 IDE |
| 作用 | IDE 缓存+索引 | 版本控制 | 编辑器配置 | **项目级认知根** |
| 进 git | 部分 | — | 否 | **大部进 git** |
| 跨 IDE 共享 | 否 | 是 | 否 | **是**（认知可移植） |
| 内容 | 配置+缓存 | 元数据 | 配置 | **契约+设计+记忆** |

## 九、`.传承/` 与 `传承殿/` 的根本差异

| 维度 | `传承殿/` | `.传承/` |
|------|-----------|----------|
| 项目归属 | **本项目专属**（洪荒·世界） | **任一项目通用** |
| 出现位置 | 项目根下一级 | 项目根下一级 |
| 命名 | 固定"传承殿" | **固定".传承"**（带点=隐藏） |
| 承载内容 | 本项目全部认知 | 通用目录契约+本项目实现 |
| 与 IDE 关系 | 业务层（IDE 内部目录） | **接入层**（IDE 接入任意项目时建） |

## 十、`.传承/` 文件 frontmatter 契约

`.传承/` 下所有 `.md` 均走《传承文档格式规则》：

```markdown
---
层级: 大道 | 天道
文档型: 落地设计 | 验收报告 | 设计原则 | 已定契约 | 治理档案 | 规则
版本: <语义版本>
域: <域路径> | 全项目
状态: 草稿 | 讨论中 | 已定 | 已废
更新: YYYY-MM-DD
---
```

**例外**：
- `.传承/README.md`（项目身份索引）→ 视为元数据文件，frontmatter 可省
- `格位/36格位.json`（格位底层定义）→ JSON 不走 frontmatter

## 十一、迁移路径（本项目要做的事）

本项目从 `传承殿/` 散落模式 → `.传承/` 规范模式：

| 步骤 | 动作 | 风险 |
|------|------|------|
| 1 | 新建 `.传承/` 七子目录（含 README） | 低 |
| 2 | 把 `rules/` 全部移入 `.传承/规则/`（建立符号链接 `rules/ → .传承/规则/`） | 中（需验证 IDE 启动） |
| 3 | 把 20 个 `*.ps1` 归集到 `.传承/门禁/`（保留旧路径符号链接） | 中 |
| 4 | 把 `传承殿/{落地设计-域,设计原则-域,已定契约-域}` 移入 `.传承/设计/` | 中 |
| 5 | 把 `传承殿/{缺陷清单,修订记录,*-验收报告}` 移入 `.传承/治理/` | 中 |
| 6 | 把 `传承殿/架构全览图.html` + `设计原则-域/完整架构蓝图.md` 移入 `.传承/图谱/` | 低 |
| 7 | 建 `.传承/格位/36格位.json`（从角色定义导出） | 低 |
| 8 | 建 `.传承/记忆/` 配 `.gitignore` | 低 |

**注意**：本项目不做全量迁移——只建规范，未来新建文件按 `.传承/` 落，老文件逐步过渡。

## 十二、`.传承/` 跨 IDE 协议

**未来 IDE 接入任一项目时的发现流程**：

```
1. 检查 <项目根>/.传承/ 存在？
   ├─ 否 → 询问用户"是否初始化 .传承/"，建模板
   └─ 是 → 读 .传承/README.md 拿身份
2. 读 .传承/门禁/总入口.* → 注册为 IDE 启动前门禁
3. 读 .传承/规则/ → 注入 AI 上下文
4. 读 .传承/格位/36格位.json → 注入角色系统
5. 写 .传承/记忆/ → 持久化棒间状态
```

**最小契约**（IDE 必须支持的）：
- 读 `门禁/总入口.*` 退出码
- 列 `规则/` 注入上下文
- 列 `格位/36格位.json` 注入角色
- 写 `记忆/棒级/<run-id>/`
