# AI 缺陷治理规则

> 本规则针对全程 AI 开发项目的典型缺陷模式，强制 AI 在产出前自查。违反任一条均视为未完成，不得交付。

---

## 一、语义完整性（防空洞闭环）

1. 相生桥接传递的载荷必须包含完整语义，禁止仅用字符串拼接传递无意义内容。
2. 土生金生成规则时，条件不得为空 `vec![]`；必须从记忆内容中提取至少一个条件维度（如来源、标签、时间）。
3. 水生木生成任务时，描述不得为固定字符串"来自事件"；必须包含事件载荷的关键内容。
4. 木生火生成迭代时，变更说明不得仅为 `"任务完成: {title}"`；必须包含任务描述或产出摘要。
5. 每段相生桥接必须验证：上游载荷的关键字段在下游动作中被实际使用，而非仅传递标题。

## 二、测试质量（防演示型测试）

1. 每个测试必须包含至少一个**内容断言**，禁止仅用 `len() == N` 或 `is_ok()` 作为唯一断言。
2. 相生测试必须验证：载荷传递正确性（如迭代变更说明包含任务标题）、状态正确性（如版本号递增为期望值）。
3. 相克测试必须验证：被操作的对象是"最旧"的（按 id / 时间排序），而非仅验证数量变化。
4. 错误路径测试必须覆盖：非法状态流转、重复命名、空输入等边界场景，不得只测 happy path。
5. 测试命名必须反映验证的语义，如 `木生火_迭代版本递增为0.1.0`，而非仅描述操作 `木生火_任务完成开启迭代`。

## 三、错误处理（防 unwrap 滥用）

1. 生产代码中 `Mutex::lock()` 必须用 `expect("...")` 提供锁中毒上下文，禁止裸 `unwrap()`。
2. 业务逻辑中禁止用 `unwrap()` 处理可恢复错误；必须返回 `Result` 并用 `?` 传播。
3. 桥接回调中禁止静默忽略错误（如 `let _ = ...`）；至少必须 `tracing::warn!` 记录错误内容。
4. 测试中的 `unwrap()` 仅限测试数据准备阶段；断言阶段必须用 `assert!` / `assert_eq!`。

## 四、代码复用（防复制粘贴）

1. 五个引擎中重复率超过 70% 的方法（`new` / `设置信号总线` / `发布信号` / `全部` / `查询` / `Component impl`）必须用宏或泛型抽象，禁止逐引擎复制。
2. 五段相生桥接中重复率超过 70% 的模式（克隆 Arc → 订阅信号 → 取载荷 → lock → 调用）必须提取公共函数。
3. 新增引擎时禁止复制现有引擎后改名字；必须先抽象公共行为，再实现差异化部分。
4. `当前时间戳()` 等工具函数禁止在多个引擎中各自定义；必须收敛到鸿蒙层统一提供。

## 五、文档同步（防版本滞后）

1. 每次新增 / 修改功能后，必须同步更新维护文档的四项：当前状态、crate 清单、测试数、后续方向。
2. 已定契约版本号必须与维护文档版本号同步，禁止一个 v1.9 一个 v1.5。
3. 测试数必须实跑 `cargo test` 后按实际输出填写，禁止估算或沿用旧数字。
4. 后续方向中已完成的项必须立即移除，禁止保留已完成项造成虚假待办。

## 六、配置化（防魔法数字）

1. 相克阈值（容量上限）必须可配置，禁止硬编码为 2。
2. 规则优先级必须根据来源区分（记忆生成 = 低优先级，人工添加 = 可配置），禁止统一为 1。
3. 记忆标签（如"迭代产出"）、任务描述（如"来自事件"）等默认值必须定义为常量，禁止散落在桥接代码中。
4. 所有跨府共享的字符串常量必须收敛到对应契约府的常量模块，禁止魔法字符串散落。

## 七、命名一致性

1. 按 id 查询的方法统一命名为 `查询(id)`，禁止部分引擎用 `按id(id)`。
2. 列出全部的方法统一命名为 `全部()`，禁止部分引擎用 `历史()`。
3. 载荷键命名必须统一语言（全中文或全英文），禁止 `id` / `title` 与 `变更说明` / `内容` 中英混杂。
4. 新增方法命名必须与既有同类方法保持一致的语义模式，禁止同义异名。

## 八、持久化完整性

1. 相生闭环中的核心节点（任务、迭代）必须支持持久化，禁止只有记忆 / 规则 / 事件可落盘。
2. 加载持久化数据后必须自动重新注入信号总线，禁止加载后信号总线为 `None` 导致信号静默丢失。
3. 持久化必须支持自动触发（关键状态变更时），禁止仅提供手动 `保存(path)` 方法而无调用点。

## 九、实现动机（防为了实现而实现）

1. 新增功能前必须明确回答：这个功能解决什么真实问题？禁止"因为蓝图里有所以实现"。
2. 相克动作的语义必须经过工程合理性论证：为什么这个信号触发这个动作？动作是"约束增长"还是"删除数据"？后者需额外论证必要性。
3. 禁止实现"能跑通但无实际价值"的功能；如相生闭环传递空载荷，必须先补全语义再声称完成。
4. 功能完成的标准是"有真实语义 + 有强测试 + 有文档同步"，而非"代码能编译 + 测试能跑通"。

## 十、完成度验证（防完成幻觉）

1. 功能交付前必须通过三项检查：语义检查（载荷非空且有意义）、测试检查（强断言覆盖内容）、文档检查（维护文档已同步）。
2. 禁止用"测试全绿"作为完成的唯一标准；必须同时验证测试断言的有效性（断言是否验证了内容而非仅数量）。
3. 新增 crate 后必须更新维护文档的 crate 清单和测试数，禁止遗漏。
4. 重构后必须验证：既有行为未改变（测试全绿）+ 重复代码已减少（抽象生效，代码总行数下降或重复率降低）。
## 十A、生产/演示隔离（防演示代码混入生产流程）

> AI 编码的典型坏习惯：为了"验证能跑通"而写演示/自检代码，然后直接放进生产启动函数里无条件调用，导致每次启动都产生垃圾数据、占用ID序列、甚至演示代码 panic 导致生产启动失败。本节强制隔离。

1. **生产入口禁止无条件调用演示函数**。`main`、`启动`、`初始化`、`run` 等生产入口函数中，禁止直接调用名称包含"演示/示例/自检/冒烟/demo/example/test/smoke"的函数。必须有配置开关控制（如 `if config.app.run_self_test`、`if cfg!(debug_assertions)`），且默认值必须为 `false`（生产默认不运行）。
2. **演示/自检代码必须物理隔离**。演示函数、自检函数、示例代码必须放在独立文件或独立模块中（如 `演示模块.rs`、`自检模块.rs`、`examples/` 目录），不得与生产逻辑混在同一文件。生产文件中出现 `演示`/`示例`/`自检` 函数定义视为违规。
3. **演示函数禁止裸 unwrap**。演示/自检函数中处理业务逻辑（推进状态、完成迭代、创建任务等）禁止用 `.unwrap()`，必须用 `?` 传播错误或 `expect("...")` 提供上下文。演示函数的 panic 会导致生产启动失败，必须与生产代码同标准。
4. **演示数据必须可区分或可清理**。演示/自检产生的任务、迭代、记忆、规则、事件必须有明确标记（如标题前缀"[演示]"、标签`demo`）或有配套清理函数，不得静默污染真实业务数据。启动自检产生的数据不得占用真实业务的ID序列而无任何标记。
5. **新增演示代码必须在设计表中声明**。设计表的"非目标"或"架构约束"中必须明确标注："本次新增的 XXX 函数为演示/自检代码，不进入生产路径，通过 YYY 开关控制"。未声明的演示代码视为未完成。
6. **启动自检不得作为启动成功的必要条件**。自检失败时必须记录警告日志并继续启动，不得因自检失败而 `panic` 或返回错误导致程序退出。生产环境的可用性优先于自检通过。

## 十一、自动化检测门禁（提交前必须全部通过）

> 以下 14 条检测命令，AI 在每次产出代码/测试/文档后，必须逐条运行。**任何一条不通过即视为未完成，不得交付。** 检测命令可直接复制到 PowerShell 运行，工作目录为项目根目录。

### 检测 1：空条件规则（土生金不得生成空条件规则）

```powershell
$hits = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" } | Select-String "添加规则\([^)]*vec!\[\]"
if ($hits) { Write-Host "FAIL: 发现空条件规则添加"; $hits | ForEach-Object { Write-Host "  $($_.Path):$($_.LineNumber)" } } else { Write-Host "PASS: 无空条件规则" }
```

**通过标准**：输出 `PASS`。土生金桥接中规则条件必须从记忆载荷提取（如标签），不得为 `vec![]`。

---

### 检测 2：删除型 API 调用（相克已改为约束增长，不得调用删除型方法）

```powershell
$hits = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" -and $_.FullName -notmatch "契约-接口-园" } | Select-String "\.(取消最旧|淘汰最旧|回滚最旧|废止最旧)\("
if ($hits) { Write-Host "FAIL: 发现删除型API调用（相克应使用约束增长，不得删除已有数据）"; $hits | ForEach-Object { Write-Host "  $($_.Path):$($_.LineNumber): $($_.Line.Trim())" } } else { Write-Host "PASS: 无删除型API调用" }
```

**通过标准**：输出 `PASS`。相克的实现方式是容量上限约束新增（返回错误），不是取消/淘汰/回滚/废止已有数据。领域契约 trait 中的方法定义除外。

---

### 检测 3：生产代码 unwrap 数量（≤ 10 处，且必须有合理理由）

```powershell
$count = (Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" -and $_.FullName -notmatch "\\证道\\" } | Select-String "\.unwrap\(\)").Count
if ($count -gt 10) { Write-Host "FAIL: 生产代码 unwrap 数量 $count > 10，请改用 expect() 或 Result 传播" } else { Write-Host "PASS: 生产代码 unwrap 数量 $count ≤ 10" }
```

**通过标准**：数量 ≤ 10。剩余 unwrap 必须是演示代码或理论不可失败场景，禁止业务逻辑中裸 unwrap。

### 检测 4：弱断言测试（测试不得仅用 len()/is_ok() 作为唯一断言）

```powershell
$files = Get-ChildItem -Recurse -Filter "*.rs" -Path "证道"
$weak = @()
foreach ($f in $files) {
    $content = Get-Content $f.FullName
    $inTest = $false; $testName = ""; $hasContentAssert = $false; $hasOnlyLen = $false
    for ($i=0; $i -lt $content.Count; $i++) {
        if ($content[$i] -match "#\[test\]") { $inTest = $true; $hasContentAssert = $false; $next = $content[$i+1]; if ($next -match "fn (\w+)") { $testName = $matches[1] } }
        if ($inTest -and $content[$i] -match "assert_eq!\([^)]*\.(内容|标题|变更说明|名称|结论|类型|状态|版本|归档)") { $hasContentAssert = $true }
        if ($inTest -and $content[$i] -match "assert!\([^)]*is_err\(\)\)") { $hasContentAssert = $true }
        if ($content[$i] -match "^\s*\}" -and $inTest) { $inTest = $false; if (-not $hasContentAssert -and $testName) { $weak += "$($f.Name): $testName" } }
    }
}
if ($weak.Count -gt 0) { Write-Host "FAIL: 发现 $($weak.Count) 个弱断言测试（仅验证数量/成功，未验证内容）"; $weak | ForEach-Object { Write-Host "  $_" } } else { Write-Host "PASS: 所有测试均有内容断言" }
```

**通过标准**：输出 `PASS`。每个测试必须至少有一个内容断言（验证具体字段值，如 `记忆[0].内容 == "xxx"`、`is_err()`、版本号具体值），不得仅用 `len() == N` 或 `is_ok()`。

### 检测 5：文档测试数同步（维护文档中的测试数必须与 cargo test 实际输出一致）

```powershell
$actual = (cargo test 2>&1 | Select-String "test result: ok\. \d+ passed" | ForEach-Object { if ($_ -match "ok\. (\d+) passed") { [int]$matches[1] } } | Measure-Object -Sum).Sum
$docLine = Get-Content "传承殿\维护文档.md" | Select-String "测试全绿"
if ($docLine -match "\*\*(\d+) 个测试") { $docCount = [int]$matches[1] } else { $docCount = -1 }
if ($docCount -eq $actual) { Write-Host "PASS: 文档测试数 $docCount = 实际 $actual" } else { Write-Host "FAIL: 文档测试数 $docCount ≠ 实际 $actual，请实跑 cargo test 后更新维护文档" }
```

**通过标准**：文档数 = 实际数。禁止估算或沿用旧数字。

### 检测 6：硬编码字符串（桥接代码中不得出现裸字符串字面量，必须用常量）

```powershell
$hits = Get-ChildItem -Recurse -Filter "*.rs" -Path "鸿蒙\系统装配-域\联动装配-府" | Select-String '"(来自事件|迭代产出|待归档|重复事件|启动自检|启动演示)"'
if ($hits) { Write-Host "FAIL: 桥接代码中发现硬编码字符串，请定义为常量"; $hits | ForEach-Object { Write-Host "  $($_.Path):$($_.LineNumber): $($_.Line.Trim())" } } else { Write-Host "PASS: 桥接代码无硬编码字符串" }
```

**通过标准**：输出 `PASS`。桥接代码中的默认标签/描述必须定义为 `const`（如 `迭代产出标签`），不得裸写。

**门禁实现**（`.传承/门禁/校验/校验硬编码.ps1`）全仓扫 `*.rs`，命中两类：①载荷键字面量（`标签|标题|描述|版本|状态|类型|来源|时间|内容|名称`）；②文件路径后缀字面量（`[盘符]:\` 绝对路径、`.json"`、`.toml"`、`.md"`）。`const`/`static`/`include_str` 与测试上下文为天然豁免——即**明文文件名字面量收敛为常量即合规**。2026-09-12 复核：19 处候选全为数据契约文件名与 JSON 契约键名（`Cargo.toml`、`符号索引.json`、`解析定义.json`、`坐标索引.json`、`index.md`、`校验报告.md`、`{}.md`、插件临时交换产出），已逐处提为常量，未放宽判据。

### 检测 7：命名一致性（不得使用旧命名 按id/历史）

$hits = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" } | Select-String "pub fn (按id|历史)\("

**通过标准**：输出 `PASS`。按 id 查询统一为 `查询(id)`，列出全部统一为 `全部()`，禁止 `按id`/`历史`。

### 检测 8：静默吞错（生产代码中不得用 let _ = 忽略业务错误）

```powershell
$hits = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" -and $_.FullName -notmatch "\\证道\\" } | Select-String "let _ = " | Where-Object { $_.Line -notmatch "remove_file|dotenvy|recv\(\)|send\(" }
if ($hits) { Write-Host "FAIL: 发现静默忽略业务错误，请改用 tracing::warn! 或 ? 传播"; $hits | ForEach-Object { Write-Host "  $($_.Path):$($_.LineNumber): $($_.Line.Trim())" } } else { Write-Host "PASS: 无静默吞错" }
```

**通过标准**：输出 `PASS`。`let _ =` 仅允许用于 `fs::remove_file`（测试清理）、`dotenvy::dotenv()`（.env不存在时忽略）、通道 recv/send 操作。业务错误必须 `tracing::warn!` 或 `?` 传播。

**门禁实现**（`.传承/门禁/校验/校验静默错误.ps1`）在 `let _ =` / `if let Ok(_)` 之外另扫 `.unwrap_or(`；该判据**只限 Result 上下文**（同行含 `Err|error|Result|失败|错误` 标记）才列为候选。`strip_prefix/rsplit/split/rsplit_once` 之后的 Option 默认值（缺后缀回退原串、缺字段默认空、驳回层级默认「土」）属业务合理默认，不构成静默吞错。2026-09-12 复核：13 处候选全为此类，0 处需改源码。

### 检测 9：自动持久化（引擎必须支持自动保存，不得仅手动保存）

```powershell
# 硬性底线：五引擎实现文件必须含 `自动保存` 落盘调用
$engines = @{
    '任务引擎' = '任务仓库-殿'; '迭代引擎' = '迭代日志-阁'; '记忆引擎' = '记忆库-阁'
    '规则引擎' = '规则库-阁'; '事件引擎' = '事件总线-阁'
}
$missing = @()
foreach ($名 in $engines.Keys) {
    $hasAuto = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -like "*$($engines[$名])*" } | Select-String "自动保存"
    if (-not $hasAuto) { $missing += $名 }
}
if ($missing.Count -gt 0) { Write-Host "FAIL: 以下引擎缺少自动持久化: $($missing -join ', ')" } else { Write-Host "PASS: 所有引擎支持自动持久化" }
```

**通过标准**：输出 `PASS`。五个引擎（任务/迭代/记忆/规则/事件）关键状态变更后必须自动落盘（`自动保存`），加载持久化数据后必须重注信号总线，禁止仅提供手动 `保存(path)` 而无调用点。当前阶段如未实现，必须在产出说明中明确标注"自动持久化待实现"，不得声称持久化完成。

**门禁实现**（`.传承/门禁/校验/校验自动持久化.ps1`）在上述硬性底线之外另做全仓启发式扫描：函数体出现「状态变更调用」（`.动词(` 形态）却无任何持久化调用即列为候选。候选须逐条人工复核，确认为「无持久化语义」或「持久化委托下游」者登记于同目录 `自动持久化-豁免.txt`（格式 `路径片段|函数名|类别`）；不得以放宽判据代替逐条复核。

### 检测 10：组件容器注册（五引擎必须注册到容器）

```powershell
$content = Get-Content "鸿蒙\系统装配-域\联动装配-府\五行串联-殿\相生桥接-阁\桥接-模块-园\桥接模块.rs" -Raw
$registrations = ([regex]::Matches($content, "容器\.注册\(")).Count
if ($registrations -ge 6) { Write-Host "PASS: 容器注册了 $registrations 个组件（≥6 = 信号总线+五引擎）" } else { Write-Host "FAIL: 容器仅注册了 $registrations 个组件，应 ≥6（信号总线+五引擎）" }
```

**通过标准**：注册数 ≥ 6。五引擎必须注册到组件容器，容器不得仅管理信号总线。

### 检测 11：空值条件边界（取载荷 unwrap_or_default 后不得直接用于规则条件）

```powershell
$hits = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" } | Select-String "unwrap_or_default\(\)" | Where-Object { $_.Line -match "标签|内容|结论" }
if ($hits) { Write-Host "WARNING: 发现取载荷后 unwrap_or_default，需确认空值时不会生成死条件规则"; $hits | ForEach-Object { Write-Host "  $($_.Path):$($_.LineNumber): $($_.Line.Trim())" } } else { Write-Host "PASS: 无空值条件边界风险" }
```

**通过标准**：输出 `PASS` 或 `WARNING` 后有人工确认。`取载荷(...).unwrap_or_default()` 得到空字符串后，不得直接作为规则条件的值（会生成 `("标签", "")` 死条件）。空值时应拒绝生成规则或用其他维度做条件。

### 检测 12：规则库空条件 API（添加规则时条件不得为空）

```powershell
$hits = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.FullName -notmatch "\\target\\" } | Select-String "添加规则\([^,]+,\s*vec!\[\]"
if ($hits) { Write-Host "FAIL: 发现添加空条件规则的调用（规则库应校验条件非空）"; $hits | ForEach-Object { Write-Host "  $($_.Path):$($_.LineNumber): $($_.Line.Trim())" } } else { Write-Host "PASS: 无空条件规则添加" }
```

**通过标准**：输出 `PASS`。`添加规则` 的条件参数不得为 `vec![]`。规则库内部应增加校验，条件为空时返回错误。

### 检测 13：生产入口调用演示函数（启动/初始化中不得无条件调用演示/自检函数）

```powershell
$entryFiles = Get-ChildItem -Recurse -Filter "*.rs" | Where-Object { $_.Name -match "启动|main|lib|bootstrap|入口" -and $_.FullName -notmatch "\\target\\" -and $_.FullName -notmatch "\\证道\\" }
$violations = @()
foreach ($f in $entryFiles) {
    $lines = Get-Content $f.FullName
    for ($i=0; $i -lt $lines.Count; $i++) {
        if ($lines[$i] -match "(演示|示例|自检|冒烟|demo|example|smoke)" -and $lines[$i] -match "\.|\(|::") {
            $hasGuard = $false
            $start = [Math]::Max(0, $i - 3)
            for ($j=$start; $j -le $i; $j++) {
                if ($lines[$j] -match "if.*config|if.*cfg!|if.*debug|if.*self_test|if.*run_self") { $hasGuard = $true; break }
            }
            if (-not $hasGuard) { $violations += "$($f.Name):$($i+1): $($lines[$i].Trim())" }
        }
    }
}
if ($violations.Count -gt 0) { Write-Host "FAIL: 发现 $($violations.Count) 处生产入口无条件调用演示/自检函数"; $violations | ForEach-Object { Write-Host "  $_" } } else { Write-Host "PASS: 生产入口无演示函数调用（或已有配置开关控制）" }
```

**通过标准**：输出 `PASS`。生产入口函数（启动/main/初始化）中调用演示/自检/示例函数必须有配置开关控制（默认关闭），禁止无条件调用导致启动时产生垃圾数据。

### 检测 14：前端测试覆盖（呈现层 JS 模块必须有 node:test 用例且全绿）

```powershell
$乾坤 = "乾坤"
$测试文件 = Get-ChildItem -Path $乾坤 -Recurse -File -Include "*.test.mjs", "*.spec.mjs" -ErrorAction SilentlyContinue |
    Where-Object { $_.FullName -notmatch "\\target\\|\\node_modules\\" }
if ($测试文件.Count -eq 0) {
    Write-Host "FAIL: 未发现前端测试文件（乾坤/**/*.test.mjs）"
} else {
    $注册 = Join-Path $乾坤 "观星呈现-域\呈现验证-府\映射装配-殿\钩子注册-阁\映射-模块-园\映射注册.mjs"
    $注册URL = "file:///" + ((Resolve-Path $注册).Path -replace '\\','/')
    Push-Location $乾坤
    $输出 = & node --test-isolation=process --import $注册URL --test 2>&1 | Out-String
    Pop-Location
    $输出 | Select-String "tests \d+|pass \d+|fail \d+"
}
```

**通过标准**：输出 `tests N / pass N / fail 0` 且 `tests > 0`。呈现层（`乾坤/观星呈现-域`）各 JS 模块必须有 node:test 用例：纯逻辑模块（词表/语料/摘要）直接断言，DOM 依赖模块（渲染/编排/看板/对话/变更/筛选）经 happy-dom 台面桩装载后断言。**不得「文件在、跑不起来」**——呈现域源码一律以 `/xxx` 绝对路径 import（HTTP 托管根 = 域根，见 `对外契约.toml` 的 static_dir），node 下不存在这个托管根，必须经映射注册（resolve 钩子）把 `/xxx` 折回域根，否则被测模块的依赖链整链解析失败，「覆盖」只是空话。

**门禁实现**（`.传承/门禁/校验/校验前端测试覆盖.ps1`）：搜索根 `乾坤` + `artifacts/agent-workspace`；无测试文件或本机无 node 时输出 `passed:null`（人工核对项，不冒充通过）；有文件则带 `--test-isolation=process --import <映射注册>` 运行 `node --test`（cwd = 乾坤）——node 24 默认 `--test-isolation=none`，多测试文件同进程会共享模块实例与全局 document（一个文件的台面装配顶掉另一个的 DOM，happy-dom 选择器也随之串台），把真结论误报成断言失败，逐文件独立进程才可信。解析 `tests/pass/fail` 三数，仅当 `tests>0 且 fail=0` 判 `passed:true`。`乾坤/package.json`（私有、仅测试用，`node_modules` 不入静态托管）声明 happy-dom 与 `npm test`。2026-09-12 补齐：16 个用例文件、132 例全绿（29 纯逻辑 + 103 渲染/编排）——呈现域 16 个 JS 模块全数有用例。

## 十二、检测执行规范

1. **每次产出后必须运行全部 14 条检测**，不得只跑部分。
2. 检测结果为 `FAIL` 的，必须修复后重新运行，直到全部 `PASS`。
3. 检测结果为 `WARNING` 的，必须在产出说明中明确标注风险及缓解措施。
4. 检测 9（自动持久化）和检测 10（容器注册）如当前阶段未实现，必须在产出说明中明确标注"待实现"，不得声称已完成。
5. 检测命令本身也是规则的一部分，修改检测命令必须同步更新本规则文件。
6. **检测 FAIL 后必须查阅修复指南**：本项目 skill 的 eferences/修复指南.md 中，针对各条检测的每种 FAIL 结果都给出了具体修复步骤。AI 拿到 FAIL 后必须按对应条目修复，不得自行猜测修复方向。修复后必须重新运行对应检测直到 PASS。
7. **检测结果必须粘贴到核对表**：任务核对表的"自动化检测门禁结果"部分，必须粘贴 detect_all.ps1 的完整输出（含每一项的 PASS/FAIL 和证据），不得只写"全部通过"。无检测输出的核对表视为未完成。

## 十三、任务设计与验收强制流程（防语义空洞与完成幻觉）

> 本节针对自动化检测扫不到的**语义性缺陷**（如"规则条件非空但是无意义值"、"相克约束了错误的对象"、"测试断言的值本身是错的"）。核心手段：**任务前强制填写设计表，任务后强制填写核对表**，无表不得开工，无核对不得交付。

### 13.1 适用范围

以下任务必须执行设计表+核对表流程：
- 修改超过 1 个文件的任务
- 涉及架构决策的任务（如新增 crate、修改契约、改变依赖方向）
- 新增功能的任务（非纯重构/纯修复）
- 涉及五行生克语义的任务（相生桥接、相克约束、规则评估）

纯机械性任务（如重命名、格式化、单文件 bug 修复）可豁免，但必须在产出说明中注明"豁免设计表，原因：XXX"。

### 13.2 流程强制要求

1. **任务开始前**：AI 必须先输出设计表（见第十四节模板），经用户确认后才可开始写代码。设计表未经确认不得开工。
2. **任务进行中**：如果实际实现偏离设计表（如发现需要新增文件、修改契约），必须先更新设计表并说明原因，不得静默偏离。
3. **任务完成后**：AI 必须输出核对表（见第十四节模板），逐条对照设计表的验收标准提供证据。无核对表不得声称完成。
4. **用户验收时**：以核对表为依据，逐条验证证据是否真实有效。核对表中"PASS"但证据不足的，视为未完成。

### 13.3 设计表质量要求

- **任务目标**必须是用户/系统视角的结果（如"任务完成后自动开启迭代，迭代变更说明包含任务标题"），不得是"写代码实现木生火"这种手段描述。
- **非目标**必须明确列出至少 1 项不做的事（如"本次不实现持久化"、"本次不修改相克逻辑"），防止范围蔓延。
- **验收标准**必须是 Given/When/Then 格式的可测试二元条件，不得是"功能正常"、"代码质量高"这种模糊描述。每条验收标准必须能通过运行测试或检查代码来验证通过/不通过。
- **边界条件**必须列出至少 3 个：空输入、非法状态、并发/重入。每个边界条件必须说明预期行为（返回错误？静默忽略？触发约束？）。
- **测试计划**必须说明每个新增测试断言什么内容字段（如"断言迭代[0].变更说明包含任务标题"），不得只写"验证木生火正常"。

### 13.4 核对表质量要求

- 每条验收标准必须标注 **PASS / FAIL**，并提供**证据**（代码行号、测试输出、命令结果）。无证据的 PASS 视为无效。
- 12 条自动化检测门禁必须全部运行并记录结果。FAIL 的必须说明原因和修复计划。
- 改动范围必须列出所有修改的文件，并与设计表的"架构约束"对比。碰了非目标文件的必须说明原因。
- 测试有效性必须说明：新增测试的断言是否验证了内容字段（而非仅 len()/is_ok()）。如果新增测试只有数量断言，视为测试无效。
- 遗留问题必须列出未完成项和已知风险，不得隐瞒。
