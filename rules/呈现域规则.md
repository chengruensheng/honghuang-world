# 呈现域规则

## 一、呈现域的地位
1. **允许存在**：呈现层（客户端界面）以「呈现域」（`4字-域`）承载，为**纯静态资源**，不含 Rust 代码。
2. **不进 workspace**：呈现域不参与 Rust 编译，不进 `Cargo.toml` 的 workspace members；对外经 `对外契约.toml` 的 `static_dir` 挂载。
3. **唯一对外边界**：呈现域是呈现层的唯一对外边界，界面资源的增删只在该域内进行。

## 二、两条豁免（对《命名规则》的特例）
1. **府级豁免 Cargo.toml**：呈现域的「府」是**静态装配单元**（能力边界与故障隔离边界），不是编译单元，豁免《命名规则》一·「府：`4字-府`（含 Cargo.toml）」中的 Cargo.toml 要求。
2. **入口豁免中文命名**：静态托管入口文件名 `index.html` 由 HTTP 托管规范强制，属《命名规则》五·「非强制情况下严禁英文命名」之例外。**其余资源文件一律中文命名**；若因浏览器或服务端对中文路径支持失败而改用英文名，须在本文件登记该文件名与原因。

## 三、职责分层（对齐后端组织思想）
| 层 | 呈现域职责 |
|----|-----------|
| 域 | 唯一对外边界；静态骨架先行；统一装配各府并隔离故障 |
| 府 | 可插拔能力单元；**崩溃隔离边界** |
| 殿 | 能力内的职责分区 |
| 阁 | 具体功能单元 |
| 园 | 落地实现文件（代码落园） |

> 说明：对齐的是后端「单一职责 / 层层汇总上报 / 插件化 / 依赖单向 / 同级不重复」的**组织思想**，不是五层角色接力流程（呈现层没有该流程）。

## 四、韧性要求（硬约束）
1. **静态骨架**：背景、布局容器、顶栏与样式必须静态写死（HTML + `<link>` 引入），**不得经 JS 生成**——JS 失效时布局不得丢失。
2. **动态装载**：域的装配对每个府的装载（`await import()`）单独捕获失败；单个府失败不得影响骨架与其它府，失败区域显示降级提示。**降级提示一经落下即不可被后续渲染覆盖**——用「等待中 / 已连接」一类空态语盖掉「该府未就绪」，等于界面替一个坏掉的区域自述正常。
3. **单向依赖**：府与府之间不得直接互相 `import` 业务代码，只经总线通信；依赖方向唯一（域装配 → 府 → 殿 → 阁 → 园）。

## 五、内容契约（硬约束）
1. **思考与正文分道**：模型思考（reasoning）与答复（content）各走各的通道——思考进推理条（默认折叠），答复进对话气泡。思考既不混入答复正文（草稿不得冒充答复），也不丢弃（思考是过程证据）。
2. **答复以权威为准**：气泡正文以模型最终答复为准。工具调用路径的答复由工具参数合成、不在流式增量里，收尾时必须补发；不得因「流里没吐」就让气泡空着——空壳气泡是格式冒充内容。
3. **空白不算内容**：只有空白字符的答复等同于没有答复，一律以中性措辞呈现（如「道祖未返回可显示的答复」）。兜底语只陈述已确认的事实，不得替对方猜原因——「未上线」一类是界面的臆测，越权。
4. **摘要只出口人话**：模型产出的结构化自述（JSON，含被 markdown 围栏包裹的）必须先折成人话再上屏。解析失败的疑似结构化文本（以 `{` / `[` 开头）**不得原样铺出**——一屏裸符号是杂质，不是内容；给中性说明，原文一律留折叠区（摘要只管好读，证据不能因为摘要好看就丢）。
5. **同源同口径**：同一棒的动作摘要，左栏结论与右栏棒头必须同源、同截断粒度（最多 3 项 +「…+N」）。两处各截一刀，早晚互相漂移。
6. **轮次可辨**：左栏结论按 run 分组并标出轮次与角色。回退重跑时同一角色会再来一轮，不标轮次，两轮结论在界面上无法区分。
