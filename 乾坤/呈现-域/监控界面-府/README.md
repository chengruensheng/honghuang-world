## 事件结构(白箱六字段,§9.3)

每条进入直播的事件必须是以下结构:

    {
      ts: 1787038400123,
      源: '识海/格位:调用',
      动作: '铭记·写入格位 <<调用>>',
      影响: [{类型: '格位', 名: '调用', 字节: 189000}],
      token: {提示词: 0, 输出: 0, 缓存: 0, 总计: 0},
      耗时ms: 0,
      证据: ''
    }

缺一即白箱泄漏 —— 本版由 server.py 的 transform 装配器守护,原始行缺字段填 0 / '',不驱回。

## 步骤直播视图(§步骤直播 2026-08-19 拍板)

右区步骤区按本节呈现。aside 任务列表保留作索引,负责切到右区"任务树"并锚定顶卡。

### 三项铁律

1. **新内容在下,默认显示最新内容**(倒序流):事件永远贴在视图底部,视口持续对齐底沿,首屏只展现最近 N 条(N=200,溢出进回收池)。
2. **结构突出 + 图标**,不靠颜色:阶段/验收/失败/版本存档四类为"重点卡"(独立字号+前缀符),工具调用/状态推进两类为"细行"(默认折叠到所属要求下);失败前缀统一 `⚠`。
3. **SSE 推送三源 (v3.1,白箱全程)**——服务端 EventSource 订阅**三个文件**,文件大小变化即推送:
   - `.上下文/事件流.jsonl`(事实源·识海承载-府/识海-纳藏-殿/事件-流-阁/追加-落流-园/追加落流.rs §事件流)
   - `临时文件夹/模型流水-观测.log`(事实源·天庭治理-府/天层-主控-殿/鸿钧-主政-阁/主政-落笔-园/model_call.rs)— 每条模型调用原文含 messages 全量 + 回包原文
   - `.上下文/记录.jsonl`(事实源·识海承载-府/识海-纳藏-殿/变更-存档-阁/回滚-垫-园 等各处写入)— 识海格位/扫描/会话等非天庭主流程痕迹
   前端不轮询,不依赖 `interval_sec`;每条 SSE 推送携带**六字段全装配**(ts / 源 / 动作 / 影响[] / token / 耗时ms / 证据)对齐融合蓝图 §9.3 白箱契约。

### 双视图(顶 tab 默认折叠)

右区步骤面板顶头加两枚 tab:「时间线 | 任务树」,默认选「时间线」。

| 视图 | 形态 | 何时展开 |
|:--|:--|:--|
| **时间线**(默认) | 单列倒序流,所有事件按到达顺序排,阶段/验收/失败/版本存档展全字段卡,工具调用/状态推进折叠为可点开的小行 | 始终展开 |
| **任务树** | 按 `_task_id` 把事件聚成要求卡树,顶卡=要求 id + 摘要 + 当前状态;**默认折叠**只显顶卡,点开才看到步骤 | 点 tab 才显示 |

切换 tab 不重置数据,只换渲染形态;SSE 不停。

### 与 aside 的关系

aside(任务列表)仅作索引:点击某条要求 → 切到「任务树」tab,并把该要求的卡自动展开 + 滚到视口中央(锚定)。**两区不抢同一焦点**:tab 控右区视图,aside 控右区所选要求。

### 渲染契约(前端对照表)

每条事件统一 6 字段(沿用 §事件结构),前端按以下规则分类:

| 事件类型 | 渲染层级 | 前缀 | 字号 |
|:--|:--|:--|:--|
| `验收结论` | 重点卡 | `✓` 或 `✗` | 大 |
| `失败沉淀` | 重点卡 | `⚠` | 大 |
| `版本存档` | 重点卡 | `⚓` | 大 |
| `设计上呈` | 重点卡 | `◈` | 中 |
| `工具调用` | 细行(可展) | `·` | 小(折叠) |
| `要求状态推进` / `想法状态推进` / `要求入池` / `想法投递` | 细行 | `·` | 小 |

### LOD 全程白箱契约 (v3.1)

事件永远带**六字段全装配**: `ts / 源 / 动作 / 影响 / token / 耗时ms / 证据`。前端按 LOD 两级展开:

| 层级 | 字段 | 触发 |
|:--|:--|:--|
| **L0 一行重点**(始终可见) | `前缀`+`ts`+`源`+`动作`+`耗时`+`token.总计` | 默认渲染 |
| **L1 重点字段**(默认折叠,点开才看) | `证据` 前 80 字 + `影响[]` 全字段 | 点卡上 `▸ 详情` 展开 |
| **L2 全量载荷**(默认折叠,点开才看) | `_payload` 原始 JSON(单行解析为多行 pretty) | 点 L1 上的 `▾ 全文` |

**模型观测源额外**(识别 SSE payload `source: "model"`): 渲染 **本轮 LLM 全量 messages**(system/user/assistant/tool 四种角色,逐消息按角色 badge)+ **Tool 全部 调/返回**(call/return 配对,parse 内嵌 JSON pretty)+ **用量**(prompt/output/cache/total 四档)。

**性能护栏**: L2 单个全量 JSON 字符 > 2000 时,默认折叠且只露前 800 字 + 「展开全文」按钮。N=200 回收池不变。

**默认折叠**: 任务树顶卡依然默认折叠(只露 id + 摘要 + 计数);点开才下挂步骤。

### 服务端契约(步骤直播 v3.1,三源)

| 端点 | 形态 | 用途 |
|:--|:--|:--|
| `GET /api/events/recent?limit=N` | JSON | 首屏拉最近 N 条事件(三源合并,默认 N=200),按时间倒序 |
| `GET /api/events/stream` | SSE | 长连订阅,新事件以 `data: {source:"...", ts:..., ev:{六字段}}` 推送 |
| `GET /api/tasks` | JSON | 任务索引(保留) |

后台线程扫三个文件(三源),每个文件单独记录 `last_size`,SSE 循环取文件大小对比,有增量即读并推送。三源 SSE payload 字段结构:

```
data: {"source": "event|model|shihai", "ts": 1234, "ev": {六字段}}
```

- `source="event"` 来自 `.上下文/事件流.jsonl`(原文即事件,直接包 ev)
- `source="model"` 来自 `临时文件夹/模型流水-观测.log`(块字段 `========== 模型调用 @ 毫秒 ==========` 拆分,每行 prompt/回复/用量/成本 渲染为一条独立 ev)
- `source="shihai"` 来自 `.上下文/记录.jsonl`(装配成六字段)

缺字段填 0 / ""——本版由 server.py 的 transform 装配器守护,原始行缺字段填默认值,不驱回。
