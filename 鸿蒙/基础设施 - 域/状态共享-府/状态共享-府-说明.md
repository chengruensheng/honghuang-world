# 状态共享-府 说明

> 域：鸿蒙 / 基础设施 - 域
> 府：状态共享-府（lib = `zhuangtai_fu`）
> 职责：在世界运行期承载"跨殿、跨阁、跨园"需要共享的运行时状态（如当前想法 id、当前要求 id），提供 OnceLock 单例化的进程级读写。

---

## 一、府的位置与定位

状态共享-府是鸿蒙地基维度下的纯运行时共享层，**不持久化、不写日志、不产生事件**。它的存在是为了让多任务线（想法投递、要求化为、设计上呈、验收裁决、世界驱动）在同一进程内能读到同一份"现在是哪一条任务"的现场状态，避免每条任务线各自拼字符串互相耦合。

结构树：

```
鸿蒙/基础设施 - 域/状态共享-府
└── 状态-存取-殿
    └── 状态-共享-阁
        └── 状态共享-园   ← 唯一落地点（OnceLock<共享状态>）
└── 类型-定义-殿
    └── 状态-键值-阁
        └── 状态键值-园   ← 类型声明（当前想法id、当前要求id 等）
```

能力只在"园"落地，符合六层结构纪律（维度 → 域 → 府 → 殿 → 阁 → 园，不跳层）。

---

## 二、全局状态读写：OnceLock 单例

状态共享-府对外只暴露两类动作：

- **取全局状态**：进程级 `OnceLock<共享状态>` 单例的只读引用（`&'static 共享状态`）。
- **写入/更新**：通过 `共享状态::写入::<键类型>(值)` 写入键值对，写入是内部可变性（`RefCell` 或等价机制），**仍走单例同一内存**。

读写契约：

| 项 | 契约 |
| --- | --- |
| 单例来源 | `std::sync::OnceLock<共享状态>`，进程内唯一 |
| 初始化 | 首次 `取全局状态()` 时懒初始化（`get_or_init`），无需显式注册 |
| 写并发安全 | 内部使用 `RwLock` 保护（读多写少，读锁共享写锁独占）；读返回拷贝，不持有借用跨调用 |
| 持久化 | **不落盘**，重启即清空（与 `.上下文/状态/*.jsonl` 的持久状态分层） |
| 日志/事件 | **不写日志、不发事件**（保持"中立中介"特征，参见铁律） |

调用模式（与既有 `缓存读取.rs` 一致）：

```rust
let 当前想法 = zhuangtai_fu::取全局状态()
    .and_then(|共享| 共享.读取::<zhuangtai_fu::当前想法id>())
    .map(|id| id.0)
    .unwrap_or_else(|| "（无）".to_string());
let 当前要求 = zhuangtai_fu::取全局状态()
    .and_then(|共享| 共享.读取::<zhuangtai_fu::当前要求id>())
    .map(|id| id.0)
    .unwrap_or_else(|| "（无）".to_string());
```

## 三、状态类型：当前想法 id / 当前要求 id

类型-定义-殿下的 `状态-键值-阁/状态键值-园` 集中声明键值包装类型，**以 newtype 模式避免误用字符串裸传**：

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `当前想法id` | `pub 0: String` | 当前世界驱动正在推进的"想法"事项 id（如 `想-0001`） |
| `当前要求id` | `pub 0: String` | 当前世界驱动正在推进的"要求"事项 id（如 `要-0042`） |

设计要点：

1. **同型并列**：两者都是 `String` newtype，便于后续追加 `当前设计id`、`当前验收id` 等同构字段，统一键值形态。
2. **未取到显示「（无）」**：未初始化或未写入时，调用方拿不到 id 就降级到占位文本，避免 Option 蔓延到呈现层。
3. **与持久状态分层**：`.上下文/状态/世界状态.jsonl` 中的 `界主想法池` / `在途要求` 是**持久化、可回放**的历史队列；这里的"当前想法id / 当前要求id"是**运行时指针**，只活在进程内存里。二者不互相覆盖，互为补充。

## 四、主循环写入 vs 观览查询读取

状态共享-府是"中立中介"——它不替任何维度干活，只承载共享数据。写入方与读取方分属两条链路，但都通过同一份单例对齐：

### 4.1 写入方：主循环驱动

路径：**鸿蒙/基础设施 - 域/天庭治理-府/驱动-入口-殿/世界-运行-阁/循环-驱动-园**

主循环在每一轮里做两件事（按既有实现）：

1. 拉取下一条要求 → 通过 `鸿钧-主政` 化为派单 → 在落单前把 `要求id` 写入 `共享状态::写入::<当前要求id>(要求id)`。
2. 关联的 `想法id`（如有）也写入 `共享状态::写入::<当前想法id>(想法id)`。

切换任务时由天层主控链路（鸿钧-主政）负责原子写入，写完才对外宣告"开始执行"。这是单一写入点，**避免多线程同时写同一键**。

### 4.2 读取方：观览查询

路径：**乾坤/呈现-域/命令操作-府/观览-查询-殿/世界-观览-阁/缓存-读取-园**

`呈现世界状态()` 在每次被命令触发时（如 `号令 世界 状态`），按以下顺序取数：

1. 持久世界状态（`.上下文/状态/世界状态.jsonl`）→ 标题、阶段、计数。
2. 运行时共享状态（`zhuangtai_fu::取全局状态`）→ 当前想法 id / 当前要求 id，作为"指针"行追加。

读取是**只读**的，不写回、不订阅、不锁住；它每次都从同一份单例取最新值，因此呈现层看到的"当前任务"与主循环正在推进的任务始终一致。

## 五、与铁律的对齐

| 铁律 | 对齐点 |
| --- | --- |
| 跨府引用只认 lib 根符号 | 外部只引 `zhuangtai_fu::取全局状态 / 当前想法id / 当前要求id`，不深链到 `状态共享-园` |
| 跨维永不 use 对方维度的府 | 乾坤维度的 `命令操作-府` 与鸿蒙维度的 `状态共享-府` 通过 `zhuangtai_fu` crate 名引用，不在源里写深路径 |
| 鸿蒙中立、不替人干活 | 状态共享-府只承载读写，不派单、不驱动、不裁决 |
| 能力只在园 | `OnceLock` 单例的具体实现落在 `状态共享-园`；键值类型声明落在 `状态键值-园` |

---

## 六、验收方法

1. `cargo build --workspace --lib` 通过（无 Rust 代码改动，构建产物不变）。
2. 本文件存在于 `鸿蒙/基础设施 - 域/状态共享-府/状态共享-府-说明.md`。
3. 内容覆盖三项：
   - **(a)** 全局状态读写采用 `OnceLock` 单例 `get/set` 模式；
   - **(b)** 状态类型包含 `当前想法id`（String）与 `当前要求id`（String）两个 newtype 字段；
   - **(c)** 写入方为 `天庭治理-府/驱动-入口-殿/循环-驱动-园` 主循环，读取方为 `命令操作-府/观览-查询-殿/缓存-读取-园` 呈现世界状态接口，二者通过单例共享。
