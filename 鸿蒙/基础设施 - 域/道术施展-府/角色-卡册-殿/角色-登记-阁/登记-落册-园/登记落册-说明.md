## 一、子系统定位

登记-落册-园 是「角色-卡册-殿」的最底层实现单元，专责一件事：**把执行角色（Identity）落地为可检索、可增删、可持久化的活册**。一切依赖角色身份（"多宝""通天"等）的上层调度（任务派遣、模型池校验、归档检索）都从本园的 `角色册` 取得最新事实。

在六层架构中的位置：

```
道术施展-府
└── 角色-卡册-殿
    └── 角色-登记-阁
        └── 登记-落册-园  ← 本子系统
```

本园不依赖任何业务侧角色字段（不读模型池、不查任务），保持纯数据结构 + 落盘职责；与"模型连接-府"通过身份字符串解耦。

## 三、符号清单（共 10 个）

| 符号 | 类别 | 可见性 | 一句话语义 |
|------|------|--------|------------|
| `角色册` | 结构 | pub | 以身份为键的 HashMap 容器，承载全部已登记角色 |
| `新` | 函数 | pub | 构造一个空的角色册 |
| `登记` | 方法 | pub | 按身份插入 / 覆盖一条角色卡（重复身份即覆盖） |
| `卸载` | 方法 | pub | 按身份移除一条角色卡，返回被卸者 |
| `缺失模型池` | 方法 | pub | 校验某角色声明的模型池是否在可用列表内，返回缺失项 |
| `取` | 方法 | pub | 按身份取只读引用，身份不在则 `None` |
| `全部身份` | 方法 | pub | 收集当前册内所有身份键的引用向量 |
| `数量` | 方法 | pub | 返回册内角色总数 |
| `保存` | 方法 | pub | 序列化整册到 JSON 落盘 |
| `加载` | 函数 | pub | 从 JSON 文件还原角色册 |

字段依赖：内部使用 `HashMap<String, 执行角色>`；`执行角色` 类型由 `道术施展-府` 的 `类型-定义-殿` 统一声明，本园仅消费。

## 四、签名与契约

### 4.1 数据结构

```rust
pub struct 角色册 {
    角色们: HashMap<String, 执行角色>,
}
```

- 键为 `String` 形态的身份（如 `"多宝"`、`"通天"`）；
- 值为 `执行角色`（含 `身份 / 道 / 职司 / 模型池 / 契约` 五字段）。

### 4.2 方法签名

| 符号 | 签名 | 行为契约 |
|------|------|----------|
| `新` | `pub fn 新() -> 角色册` | 等价 `Default::default()`，空册起步。 |
| `登记` | `pub fn 登记(&mut self, 角色: 执行角色)` | `HashMap::insert`：身份相同则覆盖；不返回旧值；记 `debug` 日志。 |
| `卸载` | `pub fn 卸载(&mut self, 身份: &str) -> Option<执行角色>` | 命中则移除并记 `info`；未命中直接 `None`，无副作用。 |
| `缺失模型池` | `pub fn 缺失模型池(&self, 身份: &str, 可用模型池: &[&str]) -> Option<String>` | 三分支：①身份不在 → `None`；②角色未声明模型池 → `None`（视为通配）；③声明了且可用列表不含 → `Some(声明值)`。 |
| `取` | `pub fn 取(&self, 身份: &str) -> Option<&执行角色>` | 只读引用，不克隆；身份缺失返回 `None`。 |
| `全部身份` | `pub fn 全部身份(&self) -> Vec<&String>` | 返回键的引用集合，便于遍历不复制。 |
| `数量` | `pub fn 数量(&self) -> usize` | 册内条数；用于界主与巡世的对账。 |
| `保存` | `pub fn 保存(&self, 路径: &str) -> Result<(), String>` | `serde_json::to_string_pretty` 后 `std::fs::write`；错误一律转中文 `String` 描述。 |
| `加载` | `pub fn 加载(路径: &str) -> Result<角色册, String>` | `std::fs::read_to_string` + `serde_json::from_str`；记录条数后返回新册。 |

### 4.3 错误模型

- **不 panic**：所有 IO 与反序列化错误以 `Err(String)` 返回，调用方按需上抛或降级；
- **序列化失败**：返回 `"序列化角色册失败: {错误}"`；
- **写入失败**：返回 `"保存角色册失败: {错误}"`，并附 `error!` 日志；
- **读取失败**：返回 `"读取角色册失败: {错误}"`，并附 `error!` 日志；
- **解析失败**：返回 `"解析角色册失败: {错误}"`；
- **空路径 / 身份**：不在本园职责内，调用方保证。

## 五、日志约定

| 级别 | 触发点 | 关键字段 |
|------|--------|----------|
| `debug` | `登记` 成功 | `身份` |
| `info` | `卸载` 命中 / `加载` 完成 | `身份` / `路径` / `角色数` |
| `error` | `保存` 写入失败 / `加载` 读取失败 | `路径` + 错误描述 |

日志风格遵守 `日志记录-府` 的 `tracing` 宏规范，调用方无需自加日志。

## 六、使用流程

### 6.1 新建册 → 登记 → 取用

```rust
use daoshu_fu::{角色册, 执行角色};

let mut 册 = 角色册::新();
册.登记(执行角色 {
    身份: "多宝".into(),
    道: "代码".into(),
    职司: "实现".into(),
    模型池: "executor".into(),
    契约: "写代码".into(),
});

let 角色 = 册.取("多宝").expect("已登记");
assert_eq!(角色.道, "代码");
```

### 6.2 模型池校验（派遣前）

```rust
let 可用池 = ["executor", "judge"];
match 册.缺失模型池("多宝", &可用池) {
    None => println!("模型池可用，派遣"),
    Some(缺失) => println!("缺少模型池：{缺失}"),
}
```

### 6.3 落盘与还原

```rust
册.保存("./状态/角色册.json")?;
let 还原册 = 角色册::加载("./状态/角色册.json")?;
assert_eq!(还原册.数量(), 册.数量());
```

### 6.4 卸载与对账

```rust
let 被卸 = 册.卸载("多宝");
assert!(被卸.is_some());
assert_eq!(册.数量(), 0);
```

## 八、接入与依赖

### 8.1 模块树接入（现状已正确）

```text
道术施展-府/lib.rs
└── 角色-卡册-殿/模块.rs
    └── 角色-登记-阁/模块.rs
        └── 登记-落册-园/模块.rs  ← 已 #[path] + pub use
```

### 8.2 跨府引用

- 本园对外只暴露 `角色册` 与 9 个方法，全部经 `道术施展-府` 的 lib 根导出；
- 不反向依赖 `识海承载-府` / `天庭治理-府` / `模型连接-府`；后者若需角色信息，应通过身份字符串查本册（遵守跨府只走 lib 根的铁律）。

### 8.3 持久化文件格式（参考）

```json
{
  "多宝": {
    "身份": "多宝",
    "道": "代码",
    "职司": "实现",
    "模型池": "executor",
    "契约": "写代码"
  }
}
```

字段顺序与 `执行角色` 的 `serde` 派生顺序一致；增删字段需同步 `执行角色` 定义。
